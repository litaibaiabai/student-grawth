# 无卡直评：一屏设计与30人模拟班级

## 界面方案

沿用云美的墨绿与暖白，以细分隔线和编号01/02/03建立操作顺序，取消原来的多层大卡片。

| 区域 | 桌面 | 手机 |
| --- | --- | --- |
| 学生 | 左栏：班级、搜索、跨页多选、全选/清空 | 上部：相同功能，名单每页6人；低高度屏每页3人 |
| 评价 | 右栏：德美/智美/健美/艺美/劳美方向标签，项目直接选择 | 中部：方向同屏，项目两列；短屏最多4项/页 |
| 说明与提交 | 底栏并排：说明、已选人数/项目摘要、确认记分 | 底部：说明＋摘要/按钮；保持提交入口完整可见 |

按钮主体约28–40px高、圆角4–5px；名单卡片约38–45px高，取消重复的解释文字和多层“板块→一级→二级”大块选择区。桌面每页12人。多页和搜索不会清空已选学生，切班提示确认；评价权限取所选学生的共同任教范围。未选人/项目或V2未填说明时禁用提交，提交期间锁定控件，后端仍保证请求幂等。

姓名超长在名单中省略，完整姓名保留在控件可访问名称与title中；点击整行即可勾选。桌面保留左侧六菜单。手机六菜单变为3×2，低高度屏将学期选择合并到品牌行，释放纵向空间。没有隐藏页面溢出来伪造“一屏”：测试检查页面尺寸、控件边界和相邻区域，避免项目被提交区遮住。软键盘弹出、浏览器放大或更低视口时以可操作性优先，允许浏览器自然移动视口。

验证尺寸：1440×900、1280×720、1024×768、390×844、360×740、320×640。V1与V2分别使用真实MySQL模拟班级、Chromium验证；截图见本地 `output/report-core/direct-score/` 与 `direct-score-v1/`。

## 模拟数据脚本

脚本：`backend/scripts/seedClassUiFixtures.js`。默认仅check，`--apply`插入，`--cleanup`定向清理。使用事务，重复apply不重复建人；遇到现存非本脚本班级/学号会停止。仅在未发布采集期使用，建议目标为测试克隆库。

```sh
# 从仓库根运行，目标库应已具备项目六表或V2七表结构
REPORT_DB_NAME=student_growth SCHOOL_ID=1 TERM_ID=1 TEACHER_ID=2 node backend/scripts/seedClassUiFixtures.js
REPORT_DB_NAME=student_growth SCHOOL_ID=1 TERM_ID=1 TEACHER_ID=2 node backend/scripts/seedClassUiFixtures.js --apply
# 清理同一批数据；FIXTURE_GRADE/FIXTURE_CLASS_NO可覆盖默认四年级99班
REPORT_DB_NAME=student_growth SCHOOL_ID=1 TERM_ID=1 TEACHER_ID=2 node backend/scripts/seedClassUiFixtures.js --cleanup
```

插入30个学生账号、30条学期评价、30条带标记的IMPORT来源，以及指定教师的测试班任教关系。账号/学号为 `UI4C99_0001`–`UI4C99_0030`；学生密码随机生成，不设置公开共享密码。已有字段保存姓名、班级、学业等级等，来源投影生成界面值。原表没有性别和原始百分制成绩列，本脚本在 `section_meta.uiFixture` 保存 `gender`、`numericScores.math`、场景及所属教师标记，不为临时测试增加业务列。数学字母等级与模拟百分制分数保持一致，其余学科等级覆盖A/B/C/D。

覆盖：正常中文姓名、复姓、同名异学号、含间隔号、含HTML特殊字符、64字合法上限姓名；男/女/未填写；100、0、59.5、60、84.9、85、99.5及缺失成绩；跳绳真实0、部分测量边界。必填姓名/唯一学号不插NULL或重复值来破坏数据库；空值放在可选性别与成绩中。同名学生依靠不同学号区分。64字以上姓名应在导入校验中拒绝，不是可提交到VARCHAR(64)的合法数据。

V2插入/清理都会推进数据与名单版本，并使原确认失效。新增测试学生会参与该学期名单/缺项核对，故不要把测试克隆库当正式发布库。清理只操作同一批标记数据；若学生已有报告、其他学期记录、故事或证书，会停止，先核对并按业务流程处理，不强删关联材料。

### 查询实际字段（V2示例）

```sql
SELECT u.username AS 学号, e.student_name_snapshot AS 姓名,
       NULLIF(e.section_meta->>'$.uiFixture.gender','null') AS 性别,
       CAST(NULLIF(e.section_meta->>'$.uiFixture.numericScores.math','null') AS DECIMAL(5,1)) AS 模拟数学分,
       e.math_regular_grade AS 数学平时等级, e.jump_rope_1min AS 一分钟跳绳,
       e.section_meta->>'$.uiFixture.scenario' AS 测试场景
FROM student_term_evaluation e
JOIN users u ON u.school_id=e.school_id AND u.id=e.student_id
WHERE e.school_id=1 AND e.term_id=1
  AND e.section_meta->>'$.uiFixture.key'='class-ui-30-v1:1:1:4:99'
ORDER BY u.username;
```

V1没有`math_regular_grade`时，改选旧字段`math_basic_knowledge_grade`。性别与原始百分制仅是测试元数据，现有报表不会自动增加这两列；界面中的字母等级是实际已投影字段。

## 如何查看

当前直接使用本地 `student_growth`，打开 `http://127.0.0.1:5173/`，使用原来的教师账号登录，先点击页面“刷新”。不需要启动独立预览，也不需要新建数据库。

1. 进入“无卡直评”，选“四年级99班”。桌面12人/页，手机6人或3人/页，可搜索“超长姓名”，跨页多选后填说明并确认；每人本次+1。
2. 进入“六育综合情况”，选择“四年级99班”；共30人，默认25人/页，可改50人查看整班，也可按`UI4C99_0030`等学号查询。
3. 点击“查看报告”，明确切换“当前草稿/完整报告”，检查学科等级、空值、特殊字符及长姓名。测试班没有发布报告，“已发布版本不存在”是预期结果，不应把空成绩补成默认三星。
4. “学期寄语”也能选择此测试班学生。暂不需要生成寄语时直接查看/编辑；真实模型费用和调用不属于数据展示测试。

## 实测问题与建议

- 原直评页在30人时页面约2230px高；名单无限铺开、分级选择与大按钮叠加。已改为分页、方向标签和紧凑控件，六种尺寸无需滚动即可完成核心操作。
- 报表列表在1280×720下，正常学生行约205px，64字姓名学生行约384px；没有横向溢出，但长姓名把行高拉至约1.87倍，浏览效率下降。建议列表姓名最多两行，配可访问的完整姓名展开，统一行高；详情页继续完整显示姓名。
- 报表列表每行同时放六个板块进度按钮，30人信息密度偏大。建议摘要按列对齐、进度压缩成一行，详细缺项在展开区显示；保持服务端分页，不一次加载所有详情。
- 当前直评学生接口只返回内部编号，报表列表接口另含学校学号。直评当前明确标为“姓名/编号”，避免把内部ID冒称学号；后续应统一返回并显示学校学号，同名学生更易区分。
- 缺成绩显示“—”、真实0保留；性别/原始分不在现有报表契约中。建议若业务确需展示，再通过正式字段契约与迁移加入，不能只靠模拟JSON让界面出现新列。
- 长姓名详情实测无横向溢出，V2打印未报告溢出；V1旧模板的64字姓名触发了打印溢出提示，应先调整旧模板身份区的换行与高度，不能直接解除打印门禁。导入超出64字、非法学业等级或缺必填身份，应展示定位到行/字段的错误，避免直接数据库截断。
