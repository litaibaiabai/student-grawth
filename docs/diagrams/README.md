# 三个角色的操作逻辑关系图

依据 SPEC V2.1、implementation plan 和 31 个界面设计整理，日期 2026-10-23。

- `三角色操作逻辑图.png`：可直接查看或插入文档的整图。
- `三角色操作逻辑图.svg`：矢量整图，适合放大阅读。
- `三角色操作逻辑图.drawio`：可在 draw.io 中编辑节点和关系。
- `build_logic_map.py`：共用数据生成 SVG 和 draw.io，校验 31 个视图覆盖、文字边界与连线穿框。
- `logic-map-data.json`：58 个节点、50 条连线及核验结果。

## 阅读方式

颜色区分学生、教师、管理员；中性颜色表示系统自动处理或复合操作人，并非新增用户角色。每个节点右上角的 S/T/M/C 编号对应界面设计的页面编号。

主线：基础准备 → 日常评价 → 综合核算 → 教师确认与管理员发布 → 按需受控更正。第 02—06 段的日常业务并行开展，不要求先做完扫卡再申报荣誉。为避免长线交叉，用来源编号将各段结果汇入第 07、08 段。

- 第 02、03 段产生过程净积分，标准化为 P。
- 第 04 段产生独立荣誉认定分，标准化为 H，不产生过程 +1。
- 第 05、06 段提供正式六育数据来源，六维均确认后形成 B；月度故事和外部故事合成规则仍待校方确认。
- 学科考试成绩独立保存，只进入报告学科板块，不直接计入六育均分。
- 第 08 段满足六项门禁后才发布，学生只能查阅本人的已发布报告。
- 第 09 段通过冲销 / 撤销重算并保留报告版本；归档后只允许有超管能力的管理员追加冲销、生成新版。
- 第 10 段贯穿全流程，负责消息、审计、任务监控。

## 复现

```sh
python3 docs/diagrams/build_logic_map.py
rsvg-convert -w 2280 docs/diagrams/三角色操作逻辑图.svg -o docs/diagrams/三角色操作逻辑图.png
```

验证覆盖 31 个界面，且连线未穿过任何节点内部。已用本地 SVG 渲染器成功导出并目视检查整图；draw.io 文件由同一份节点/连线数据生成并通过 XML 解析校验，本机无 draw.io CLI，未使用其原生渲染器核验。

这是一张业务设计图，不代表图中功能已在现有产品中实现。
