# 来源时间契约切换操作单

本轮仅在独立测试库验证；未切换任何试点/生产数据库。本地界面验收不代表历史时钟已经核实。

1. 先备份数据库并暂停全部写入口、worker和发布准备。记录数据库、学校、负责人、停写时间以及当前应用版本。禁止两个时区版本的连接池并行写。
2. 用只读查询核实旧会话/服务器时区与至少一组可追溯原始事件。无法证明历史偏移时留空，不猜测。`previousSessionOffsetMinutes`仅是会话观测，不等于历史证据。
3. 对指定学校执行`backend/scripts/runCoreMigrations.js --record-utc-cutover --school-id=<学校ID>`。只有已核实历史偏移，才加`--verified-legacy-offset-minutes=<分钟>`。REPORT_DB_NAME必须是经过审阅的独立目标。该命令写一次SOURCE_CLOCK_BASELINE审计：旧来源最大ID、旧会话偏移、是否核实、UTC边界；不批改历史created_at。
4. 统一启动当前版本连接池。每条新连接先SET time_zone='+00:00'再交给业务。来源明确occurredAt/usedAt使用带Z的UTC，学校月/日边界固定Asia/Shanghai。
5. 停写状态只读核验边界前后记录、10月1日00:00学校时间、月末领取/跨月冲正和额度Q≥P≥G；未核实历史显示UNKNOWN，不能用生成月替代实际直评发生月。
6. 在隔离测试账号上按约定执行一次直评/领取/冲正冒烟，校验原始值、卡归属、净分和发布冻结版本；确认后恢复真实业务写入与worker。

回退必须再次冻结、备份并记录新的时间边界。不能把旧包直接连回新库继续混合写；新边界之后的明确UTC事实不可改写为旧时区。先只读核对，再由负责人决定回退应用还是恢复备份及其增量，完整保留审计。

台账覆盖索引是独立维护操作：`node backend/scripts/upgradeCoreLedgerIndex.js`默认只检查；明确`--apply`才在目标来源表添加一个派生UTC文本列和一个索引。DDL自动提交，需预留磁盘/备份及维护窗口，分步可重入。应用遇到旧库缺索引会回退精确扫描，功能可读但不承诺大数据查询预算。该操作不修改原始payload/时间，不新增业务表，也不属于UTC历史校正。
