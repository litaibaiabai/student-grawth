## MCP复演与可见性验收

演示从管理员导入开始，教师配卡、直评、上传Excel和结算，学生自评、扫码、听写故事和上传奖状，班主任人工核对奖状与寄语并确认整份报告，管理员准备并统一发布。成绩更正B→A使原确认失效，重读重审后才可发布；PREPARED阶段切换学生仍显示尚未发布。

发布后学生本人看到完整2页版本1，徐晨作为任课教师仅能看到1页冻结明细，没有寄语标题和完整确认按钮。最终浏览器停留在学生完整报告。[30步演示脚本](demo-script.md)和[本地入口](http://localhost:19981)可直接复核。

一次文件选择工具长时间等待导致原登录过期，系统实际拒绝该次预览；重新登录并重选同一文件后完成导入。原生日历需要按年/月/日分段输入，首次空日期提交被正确拒绝。专用服务重启时曾短暂产生连接提示，服务恢复后读取和完整发布均通过；没有用接口代替MCP补写结果。

## 实施边界与决策

- 在现有功能分支原地增量实现，保护已有大量未提交学生/教师端代码；未stash/reset、未把已有产品改动混入提交。使用逐任务源码快照审阅；代价是交付保留工作区改动，由用户决定后续提交方式。
- 增强学期拒绝旧学期设置中的任课关系写入口，统一走班级差异预览/提交，防绕过权威负责人及版本校验；旧版学期保持兼容。
- 新学期空数据，只接受导入班级；不自动复制班级或评价，需每学期重新导入。
- 用户追加确认后，数据统计严格沿用已经重构的四标签新逻辑，完整性和缺项放在发布中心。
