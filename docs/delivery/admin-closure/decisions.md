# 实施取舍与代价

以下记录实施时作出的判断及其代价；用户明确确认的业务规则仍以设计说明和后续要求为准。

| 顺序 | 判断 | 依据与代价 |
| --- | --- | --- |
| 1 | 在现有功能分支原地增量实现 | 当前工作区已有大量学生端、教师端未提交改动，干净工作树不能反映运行基线。保留原有修改、不stash/reset；代价是需要文件快照界定本次审阅范围。 |
| 2 | 不提交既有产品文件，使用任务前快照审阅 | 避免把其他工作混入本次提交。代价是实现保留在工作区，后续提交需由维护者划定范围；审阅快照与测试证据保留，不清理唯一记录。 |
| 3 | 增强学期只允许班级预览/提交入口变更职责 | 旧学期设置直接写任课关系会绕过权威负责人和CAS。旧版学期继续兼容；代价是增强版旧调用方需使用新班级入口，正式界面已适配。 |
| 4 | 下一学期从空班级、空评价开始 | 用户要求班级全部导入，且设计明确不复制评价。没有采用“复制上一学期班级”的建议；代价是每学期需要重新导入和配置职责。 |
| 5 | 同班同科同月共享首次生成的预算 | 更换教师不会产生第二份月额度。保留已使用卡及积分事实，剩余未用卡撤销旧凭证并交给新教师；历史超额已用卡不追溯删除，剩余为0。代价是换教师后旧打印的未用卡失效，需要重印剩余卡。 |
| 6 | 班主任停用时阻断发布；恢复同一负责人后允许沿用未变内容的确认 | 停用不等于改写报告。更换负责人仍撤销确认；激活前复查有效负责人。代价是恢复原负责人不会强制再点一次确认；若学校要求停用永久作废审核，需要另定业务规则。 |
| 7 | 审计允许非秘密发布批次标识 | releaseKey用于定位发布操作，本身不授予权限；不是密码、卡片凭证或报告内容指纹。代价是导出中可关联同批操作；管理员、学校与发布栅栏校验仍独立执行。 |
| 8 | 隔离演示使用显式固定寄语和人工奖状核验 | 避免调用付费模型，并保留真实业务写入与审核路径。代价是本次验收不证明生产ASR/OCR/LLM服务质量；未参与讲故事不伪造成绩。 |
| 9 | 收尾仍修复两个非阻断小问题 | 最终复审指出审计关键字不匹配合成类型、UI预期401日志未精确断言。用户明确要求发现问题逐一修复，因此完成三文件小修复及定向复测，覆盖技能默认“残余Minor暂存”的建议。代价是多一次受限修复与审阅，没有再跑无关全套。 |
| 10 | 保留工作区及审阅记录，不合并、推送或部署 | 本次交付范围是本地实现、迁移、测试和演示；没有授权把现有混合改动整体集成。代价是后续发布需另行选择部署环境及提交范围；不增加本次确认流程。 |

管理员数据统计严格沿用用户已经重构的四标签实现。对照基线的前后端统计模块哈希均一致，原始证据为 `output/report-core/admin-closure/statistics-preserved.json`。完整性检查只用于发布中心。
