# 学科自动月配卡交付说明

管理员依次维护“教师学科”“学科发卡策略”，系统在有效学期内每月1日生成评价卡。每位教师每月一份，兼课按主教学科策略；没有主教学科、启用策略或有效校历时会列出异常。

每个学科填写月总张数和德、智、体、美、劳、故事六个比例，合计100%。余数按最大余数法分配，同余数按德智体美劳故事顺序。比如语文100张，智育70%、德育20%、劳育10%，即70/20/10张。当前月已有分配时，策略修改下月生效；新增教师仍用当月有效版本。已有策略的学科请在策略中暂停发卡，字典状态不再提供另一条即时停发路径。

学生扫码预览后主动申领，教师选择完整两级子类再审核，固定每卡+1。实体卡只显示六育方向，不预绑细分指标。未扫码卡按当月有效期失效；已扫码待审核至次月3日23:59:59与学期审核截止中的较早者。缩短学期审核截止会永久收紧旧卡与批次上限，后续延长仅影响新批次。

“月度分配与打印”按教师显示实际卡片数量、使用进度与异常。管理员准备打印PDF后下载，未就绪教师列入首页。每位教师分组换页，A4实际大小单面打印；重复打印使用同一批卡片，不增发。PDF为含可领取凭证的私有资料。

## 启用与部署

1. 在项目根目录运行 `npm ci --prefix backend`。
2. 备份现有数据库后，在 `backend` 目录运行 `node scripts/runMigrations.js`。增量迁移保留旧测试卡，并将其隔离为不可正式申领；不清空现有记录。迁移可重复运行。本次开发只操作独立测试数据库，未修改原业务数据库。
3. 在实际后端环境中配置 `FRONTEND_PUBLIC_URL`（学生设备能访问的前端地址）、`CARD_PRINT_KEY`（固定32字节base64密钥）及 `CARD_PRINT_DIR`（私有、可持久保存的目录）。生成密钥可运行 `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`；密钥和数据库、私有目录一起备份，切勿每次启动重生成。缺少密钥时分配保留为失败快照，补齐后后台恢复。
4. 在 `frontend` 运行 `npm run build`，部署构建结果并重启后端。后台启动立即检查当月，此后每分钟补齐可恢复任务，发卡无需管理员手动触发。发卡日与期限统一按北京时间计算。
5. 核对本校专属校历与学期审核截止。只要学校维护过专属校历，未覆盖月份不会回退全局基线。配置教师主教学科及启用学科策略，首次启用将补生成当月卡片。

原 `/admin/card-quotas` 和 `/admin/cards/generate-month` 在两个API前缀均返回410；扫码预览改为POST，不将卡片凭证放进服务端查询日志。容器使用 backend 为构建上下文时，新增增量SQL随 migrations 目录打包；全新数据库初始化仍应从完整仓库执行迁移，旧库可在后端包内升级。

源工作区其他任务的改动按复制时哈希逐文件核对，不覆盖并发变更，不提交包含其他任务的整个工作树。

## 实现取舍与剩余限制

- 保留源工作区原有未提交修改，本次合回亦保持未提交；后续提交需只选择本次相关差异。
- 使用学校级锁覆盖学科、校历与预留，避免跨配置竞态；代价是同校配置与预留短暂串行。
- 学期唯一键补入school_id，允许各学校维护同学年专属校历，保留旧数据；共享全局校历仍按既有逻辑展示。
- 已维护策略的学科通过策略开关暂停发卡；为保持按月版本语义，字典的即时启停会被拒绝，需进入策略表单操作。
- 暂不迁移全项目Ant Design弃用属性，不拆分既有大包警告；功能验证和生产构建通过。
