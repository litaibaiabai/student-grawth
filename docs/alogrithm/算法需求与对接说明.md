# 六育综合成绩算法 V1（含故事）

## 1. 适用范围

六育：德育 D、智育 Z、体育 T、美育 M、劳育 L、故事 G，六项各自以0~100分记录**独立审核后的原始成绩**。A（教师直评）每次正式加1，B（学生首次成功扫描无记名一次性卡）每次正式加1，错记只以-1更正。奖状仅三种级别（省/市/区）及一二三等奖，审核通过后才统计。六育原始百分制成绩如果已经包括A/B或奖状，不能对同一事项再次加权。

## 2. 推荐计算规则（待学校确认）

- B = (德+智+体+美+劳+故事)/6，范围0~100。
- N = A有效次数+B有效扫码次数-撤销冲销次数；从V3的score_record.score_delta净求和，**不是**重新数卡或读学生总分缓存。
- P = min(100,max(0,N)*100/20)。20为试行每学期满分目标，可按年级及发分机会调整。
- 奖状内部级别分：省一9、省二8、省三7；市一6、市二5、市三4；区一3、区二2、区三1。
- R = 本学期已审核通过且不重复的奖状内部积分之和。
- H = min(100,R*100/12)。12为试行满分目标。
- **S = round_half_up(0.80*B+0.15*P+0.05*H,2)**；中间不提前四舍五入。
- 80/15/5、20、12是演示参数，不是既定校规，可通过comprehensive_score_rule配置并在学期启用时冻结。

### 演算示例

德88、智90、体86、美92、劳84、故事90，B=88.3333...
教师12条+1，扫码8条+1，无冲销，N=20，P=100。
奖状：市二等奖5，区一等奖3，R=8，H=66.6666...
S=0.80×88.3333...+0.15×100+0.05×66.6666...=**89.00**。

### 重要的公平性边界

1. **按权重折算意味着无奖状的学生荣誉部分是0，其他两项满分时其综合分最高95分。** 这是一条需校方主动接受的评分政策，不应无提示默认上线。没有奖状不等于学习表现差。
2. 如果不希望没有获奖机会的学生被拉低主成绩，可不把奖状放入总分，改为荣誉标识/独立展示；或者采用批准后的“小幅加成且100封顶”方案。不能在同一学期随意切换口径。
3. A、B每次**原始积分**永远+1；转换后对综合成绩的影响会因过程积分封顶而变化。不能把综合成绩中的0.75分误写回原始积分账。
4. 同一届次同一成果只计1张最高有效奖状；证书图片重复、学生同名不能作为合法奖状的唯一判定依据。
5. 如果六育任何一项尚未确认，综合成绩返回`INCOMPLETE`及`NULL`，不能用0代替缺失；老师填写的正式0分才属于0分。
6. 其他各类材料、考试原始成绩、讲故事作品评价是否已经参与B，必须先检查去重，不能同时在故事和奖状或日常积分中凭同一事实重复赋分。
7. 过程积分加分机会可能随教师和班级不同；试点前至少比较班级/年级发放次数分布，决定是否统一过程满分目标20。

## 3. 已有V3数据库与本方案的衔接

沿用已有`score_record`账本（包含`A_DIRECT`,`B_CARD`,`REVERSAL`）。新增三张表：

- `student_dimension_grade`：每生每学期六育原始百分制成绩，按D/Z/T/M/L/G保存。
- `honor_certificate`：奖状认定级别与奖次、审核、同一成果防重。
- `comprehensive_score_rule`：学期权重、过程满分目标、荣誉满分目标、版本。

新增表不改变已有`reward_card`扫码核销；B扫码成功时仍然**卡片永久失效＋同事务写入+1记录**。奖状内部积分不写入`score_record`，避免与A/B混在一起。所有综合成绩可以实时SQL计算，规模增长后可加结果快照表供期末发布（需另定冻结与版本设计）。

如已采用上一轮的一张`edu_evaluation_category`三级树，请新增一级“故事”（代码G）。该树中的三级加分类用于A/B扫码奖励的归类，不能直接代替独立的六育百分制正式成绩。原V3九表的`edu_dimension/edu_item`与新增三级树属于历史不同版本，正式接入前须确定一个分类主数据来源并迁移`score_record.item_id`及`reward_card.item_id`关系；本SQL不自动更改这些已有外键。

## 4. 后台业务流程

- 六育成绩：教师录入或确认 -> 检查0~100及六维归属 -> `student_dimension_grade`设为CONFIRMED。
- A教师评价：授权选择学生与加分类 -> 事务内增加1条`score_record`，防重复请求。
- B实体卡：学生登录扫码 -> 锁定实体卡行，验证UNUSED及学期 -> 事务内插入一条`score_record`和卡片置USED，重复请求不重记。
- 奖状：学生上传 -> 标记PENDING -> 教师审核层级/奖次/活动去重 -> APPROVED后参与荣誉计算；驳回不计。
- 查询综合成绩：六育完整验证 -> 取A/B+1及更正-1净值 -> 统计已审核奖状 -> 按学期规则计算并返回贡献明细。
- 纠错：教师/管理员按授权修改正式记录并记录审计 -> 重算受影响学生。学期归档后应保留旧成绩快照和规则版本，新结果作为修订版发布。

## 6. 最少验收用例

1. 6项百分制均已确认且有效记录如上，结果为89.00。
2. 故事成绩缺失时，`final_score=NULL`且状态INCOMPLETE，不是0分。
3. A有效一次和B有效扫码一次都只产生原始+1。
4. B重复扫码10次，最多一条+1；卡失效与入账同事务。
5. 冲销一条A或B后，过程积分净分减少1，但奖状和六育原始分不被改写。
6. 未审核/驳回证书均不计分；审核通过的省、市、区一二三等奖为9~1分。
7. 同一活动成果不允许多个奖状重复正式认定。
8. 达到20个过程净积分后，继续积累原始奖励也不会令过程百分制超过100。
9. 达到12个内部荣誉分后，荣誉百分制仍不超过100。
10. 归档时计算规则应与报表/导出的版本一致。

## 7. 落地建议

先让年级组在匿名样本上模拟不同的`process_full_points`（例如10、20、30）和是否对奖状单独展示，观察高频发卡及奖状获取机会差异；校方批准后将参数和适用学期冻结并公告。报告除显示综合分外，保留六育原始分、A/B有效次数、荣誉清单，让学生理解结果来源。
