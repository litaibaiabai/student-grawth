# 需求与现状依据

记录日期：2026-10-26（Asia/Shanghai）。此文件是地图的输入与调查依据，不是已经批准的完整设计。代码引用针对当前工作区，不只针对 Git 提交版本。

## 用户已经明确的要求

1. 系统按教师所教授的学科自动配发月度卡片，由管理员维护每个学科的六育发卡比例与数量。
2. 语文、数学、物理等偏智育学科的示例：每月智育 70 张、德育 20 张、劳育 10 张，共 100 张。
3. 美术学科的示例：每月美育 70 张、德育 20 张、劳育 10 张，共 100 张。
4. 实体卡印刷不标注一级子类、二级子类，仅用六个方向的颜色或图形区分。
5. 教师把卡交给学生；学生扫码提交后，教师在审核环节选择一级子类和二级子类，说明本次奖励学生的具体方面。
6. 管理员不再逐教师配置月配额，也不再操作手动批量制卡。配置好学科策略后，由系统自动生成每月卡片。

示例用于说明可配置的分配结果，不能推导出“所有老师固定 100 张”或“所有学科一律 70/20/10”。追加确认集中记录在[教师任教学科与每月领卡资格如何确定](issues/WF-CARDS-01.md#resolution-comments)的结论中；数据维护与异常资格的未决问题已转入对应开放票。

## 当前实现与新要求的差异

| 位置 | 当前事实 | 对改造的影响 |
| --- | --- | --- |
| [用户表](../../../sql/00_full_schema.sql#L38) | `users` 有教师角色、任教班级、状态；无任教学科字段，也无教师学科关系表 | 自动匹配学科策略前必须建立可靠的任教学科数据及维护方式 |
| [教师列表接口](../../../backend/routes/api.js#L128) | 查询教师姓名与任教班级，未返回学科 | 策略匹配、数据维护和分配结果展示需要统一学科标识 |
| [旧配额表](../../../sql/00_full_schema.sql#L89) | `card_quota_rule` 按教师、学期、月份存总数及三级指标分布 | 旧配置不能直接等同于按学科的长期策略；生成结果快照也不能继续成为逐教师手动配置 |
| [卡片资产表](../../../sql/00_full_schema.sql#L113) | `reward_card.category_id` 必填，绑定固定三级指标 | 新卡须在生成时独立保存六育方向；子类不能再作为生成卡片的前置条件 |
| [手动生成逻辑](../../../backend/controllers/cardController.js#L158) | 手工指定教师、指标和数量；未指定时取默认教师/三级指标；不读取学科策略 | 需要重新定义自动匹配与生成批次，不能只隐藏按钮 |
| [卡片预览与申领](../../../backend/controllers/cardController.js#L315) | 通过卡片固定指标返回类别名称与代码 | 学生扫码时应读取卡片既定方向，并允许“子类尚待老师审核” |
| [教师待审查询](../../../backend/controllers/cardController.js#L474) | 使用卡片指标内连接查询 | 新卡没有叶子指标时，现查询会漏掉待审记录 |
| [教师审核页面](../../../frontend/src/app/teacher/claims.jsx#L31) | 审核请求只有决定、驳回原因和幂等键，没有子类选择 | 必须新增具体奖励方面的选择，并与卡片方向关联 |
| [审核入账](../../../backend/controllers/cardController.js#L514) | 从卡片预绑定指标推导维度和明细；通过后固定 `+1`，同事务修改申领、卡片和积分流水 | 需要改为使用审核选定的叶子指标，并保留唯一入账约束和事务一致性 |
| [自动任务](../../../backend/services/scheduler.js#L75) | 只有过期与消息轮询，没有月度制卡任务 | 自动生成、恢复重试和首次配置后何时生效均需定义 |
| [过期任务](../../../backend/services/scheduler.js#L13) | 更新条件使用 `ACTIVE`，而正式卡片状态枚举为 `UNUSED/PENDING/USED/EXPIRED/VOID` | 跨月规则落地时需要统一状态，避免旧卡持续可用 |
| [现有制卡返回](../../../backend/controllers/cardController.js#L228) | 数据库仅存令牌哈希，原始令牌仅在生成响应中返回 | 后台自动生成后若不保留可领取的打印产物，管理员不能从哈希恢复扫码凭证 |
| [打印界面](../../../frontend/src/app/admin/cards.jsx#L598) | 依赖当前页面的 `generatedBatch`；弹窗展示卡号和原始令牌 | 目前不能作为自动生成后随时领取的持久化打印流程；不能宣称已经生成可直接印刷的二维码文件 |

## 术语对应

| 用户用语 | 现库表示 | 本地图的称呼 |
| --- | --- | --- |
| 六个方向 | 根节点 `D/Z/T/M/L/G`，`category_level=1` | 六育方向 |
| 一级子类 | 六育方向下的节点，`category_level=2` | 一级子类 |
| 二级子类 | 叶子加分项，`category_level=3` | 二级子类／叶子指标 |

当前根节点含义为德育、智育、体育、美育、劳育、故事。用户最后提到的“故”暂按现有第六方向“故事”理解，具体发卡策略与计分关联仍需在学科策略决策中确认。旧[业务决策清单](../../spec/附件D_业务决策清单.md#L15)也将故事发卡列为待校方审批事项，不能默认已经批准。

## 建图时的候选方向（历史记录）

以下是建图时提出的建议；后续是否采纳以地图关联的决策票为准，不将这份调查输入独立维护为另一套实施规则：

- 任教学科与学科策略采用稳定代码关联，不依赖教师姓名、学科显示名称或任教班级反推。
- 卡片保存方向与所属教师；具体加分叶子指标保存到审核结果及积分流水。通过审核时校验“方向 → 一级子类 → 二级子类”的完整关系。
- 月度生成保留当时学科、策略版本和分配结果快照；修改策略不默默改写已印刷卡片或历史积分。
- 自动任务重复执行不增加已完成批次的卡量；中途失败后按既定规则恢复。
- 自动生成卡片与领取打印文件是两个动作；保留查看与打印能力不意味着恢复人工选择教师、指标、数量的制卡入口。
- 审核计分的追加确认见[教师审核怎样选择子类并形成准确加分记录](issues/WF-CARDS-04.md#resolution-comments)，不再把已确认的分值作为待讨论建议。

## 后续需要覆盖的验收场景

这些是待决策完成后细化的验收方向，不表示当前业务已经具备这些能力：

- 给语文、数学、物理、美术分别配置学科策略后，生成数量与六育分布符合配置；不要求管理员逐教师逐月设置。
- 生成时无子类，卡片仍可查询、印刷、扫码并出现在待审列表；审核后才出现具体奖励分类。
- 审核选择完整有效的子类后准确入账；伪造跨方向或不匹配父子的指标请求被服务端拒绝。
- 自动任务重试、多实例并发、跨月恢复不会重复发卡；空学科、无策略、停用教师等情况有可解释结果。
- 服务重启后仍能领取该批次的打印资料；查看与重印不会生成另一批有效卡。
- 旧卡按明确的过渡规则处理；已入账积分及审计记录可追溯。
- 普通教师只能查看和审核其权限内的卡片与申领，管理员操作受学校范围约束。
