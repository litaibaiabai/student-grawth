# 三个角色的最终操作与接口边界怎样收敛

## Question

在学科、策略、自动生成、审核、打印和过渡规则明确后，管理员、教师、学生各自的操作路径与接口应怎样收敛，才能形成可以直接交给开发的改造规格？

需要形成的决定：

- 管理员如何维护教师任教学科、学科发卡策略，查看月度分配结果、异常和打印产物；明确移除教师月配额配置和手动批量制卡入口。
- 已确认由管理员给教师指定一个主教学科；仍需确定维护入口、是否按学期记录，以及学科代码、显示名称、任教班级之间的数据关系。此项承接[教师任教学科与每月领卡资格如何确定](WF-CARDS-01.md)中的维护范围，不重新讨论兼教学科是否累加卡量。
- 管理员怎样通过学期配置确定发卡适用月份，寒暑假是否纳入；跨学期月份怎样选定归属学期。此项承接[月度自动生成何时生效以及如何避免重复配卡](WF-CARDS-03.md)，不擅自把学校假期安排当成技术默认。
- 教师如何查看本人卡片、处理学生申领、选择子类并确认奖励；不增加用户未要求的逐学生发卡登记动作。
- 学生扫码预览如何显示方向与“待老师确定子类”，审核后怎样查看具体奖励方面。
- 新旧查询与写接口的边界、错误提示和字段契约；自动分配的结果可以查询，但不能悄悄变成另一种逐教师人工配额配置。
- 将前面决策固化成数据关系、状态转换、兼容边界和验收场景；需要另行确认的范围继续建票，不能自行补写为校方决定。

依据：[用户要求与候选验收方向](../context.md)。本票决定交付规格的边界，后续代码实现另行安排。

## Resolution comments

2026-10-26，参与者：用户与 Codex；由已领取本票的 Codex 记录结论。

用户明确选择：没有有效学期覆盖的月份暂停发卡，只在有效学期覆盖的月份配卡。

采用[按学科自动配卡与审核归类：开发交接规格](../../../superpowers/specs/2026-10-26-subject-card-issuance-design.md)作为本票的交接资产，确定三个角色的操作路径、教师学科维护、策略版本与校历边界、数据关系、API 契约、二维码登录恢复、自动任务、打印与测试数据过渡验收。前六张票的业务细节仍以各自结论为准，规格仅引用摘要；新增实现默认与首版范围属于 Codex 的选择，不冒充用户逐条确认。

独立 builder check 首次只发现“已有策略但尚无当月批次时，修改或重新启用的生效月份”这一缺口。由 Codex 补充为：无当月正式批次时可当月生效，有当月批次则下月生效；失败／未完成批次同样固定原版本，0 张跳过记录不占用正式份额。该补充已写入规格并向用户说明。

对修订规格再次独立审阅，结果为“nothing important left”。文档结构、链接与决策依赖另行核对。技术库、组件拆分、PDF 具体版式及性能参数明确留给实现者；未发现仍需替用户猜测的关键业务选择。

本票关闭，地图规划目的地已达到。本次不实施代码、不执行数据迁移、不生成或印刷真实卡片。
