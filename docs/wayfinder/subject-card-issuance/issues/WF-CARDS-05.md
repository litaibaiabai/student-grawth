# 自动生成后的实体卡如何领取打印与重印

## Question

卡片由后台自动生成后，谁在何处领取可印刷的六育卡资料，以及怎样确保服务重启、再次下载或重印时仍是同一批卡而不是重新制卡？

需要明确：

- 已确认管理员统一打印，再分发给教师；不是由教师自行下载打印。
- 已确认输出为按教师分组、含二维码的可直接打印 PDF；实体卡不印两层子类。
- 原始扫码凭证／打印产物如何持久保存、领取与控制访问权限；现有哈希不能恢复原始令牌，不能沿用仅在一次 HTTP 响应中返回的方案。
- 重印同一批卡不能增加有效卡数量；遗失换码、跨教师转卡和停用后自动撤卡属于未要求的额外流程，见本票的首版范围说明。
- 停用教师已有卡片保留原归属和到期规则，不在生成或打印任务中自动转移或撤销；已扫码申请的管理员接管见[教师审核怎样选择子类并形成准确加分记录](WF-CARDS-04.md)。
- 六个方向的颜色或图形如何沿用或确定；不在这张票中扩展成独立的品牌视觉项目。

依据：[当前生成返回值与打印弹窗的限制](../context.md)。保留打印领取能力不等于保留用户明确要求移除的手动批量制卡。

## Discussion comments

2026-10-26，Codex 领取本票，开始与用户交流。

- 已询问：系统自动生成卡片后，由管理员统一打印并分发给教师，还是由教师自行下载并打印本人卡片？
- 用户选择：“管理员统一打印，再分发给各位教师（推荐）”。据此确认打印资料由管理员领取并集中打印，随后分发给教师。
- 已询问：管理员需要可直接打印的 PDF，还是供印刷方排版的二维码数据清单，或两者都需要？
- 用户选择：“按教师分组、含二维码的可直接打印PDF（推荐）”。

## Resolution comments

2026-10-26，参与者：用户与 Codex；由已领取本票的 Codex 记录结论。

用户明确选择的业务规则：

1. 管理员集中领取打印资料、统一打印，再分发给各位教师。
2. 输出采用按教师分组、含二维码、可直接打印的 PDF。首版不额外要求为印刷方导出排版数据清单。
3. 实体卡只区分六育方向，不显示一级子类和二级子类。

为使自动生成与集中印刷衔接，Codex 采用以下实现默认，未声称用户逐条确认；后续说明可调整这些默认：

- 管理员按月份查看生成结果和 PDF 就绪状态，领取已生成批次的打印文件；“下载／重印”不接受教师、方向、数量参数来创建新卡，不恢复手动批量制卡入口。
- 月度 PDF 按教师分页分组，每组有教师、月份和各方向数量摘要。卡面采用方向颜色／图形、二维码及便于查找的卡号与月份，不放学生资料或两层子类；教师标识可出现在分组页或卡面以便分装。默认采用 A4 多卡排版，具体尺寸与图形属于实现时可评审的版式细节。
- 新卡除用于扫码校验的令牌哈希外，受控保存可恢复的加密凭证材料，确保数据库事务完成后即使 PDF 渲染任务中断，重试仍能使用同一张卡的凭证。不能指望从哈希恢复原始令牌，也不能在渲染重试时重新生成一批卡。
- 加密密钥由持久部署配置提供，不在每次启动时临时生成。凭证材料不出现在普通卡片查询、教师查询或日志中。
- PDF 在私有存储中按分配批次和版式版本保存，数据库记录其归属、生成状态与校验摘要。管理员通过学校范围内的鉴权接口下载，服务重启、重新登录后仍可领取；卡片生成和 PDF 就绪分别记录进度。
- PDF 渲染失败可重试同一批次；重复下载或重印使用同一批有效卡号和扫码凭证，不增加当月卡量。二维码须能引导学生读取相应卡片，领取页的登录与凭证恢复方式纳入接口整合规格。
- 六育方向沿用当前字典及其稳定编码；颜色／图形在整套印刷文件中保持一致。审批分类不进入卡面，不因审核后确定子类而要求重印实体卡。

首版范围由 Codex 作如下收敛，不冒充学校已经确认的管理制度：提供已有卡片的集中下载和同卡重印；遗失后换码补发、跨教师转卡、停用账号后自动撤销已流转卡片不在原始需求内，不作为本轮新增功能。停用教师的旧卡不自动转移，沿用原有效期与审核规则；线下卡片回收由管理员处理。用户如需要额外处置流程，再明确其规则。

集中打印的角色、输出载体和可恢复打印方式已明确，本票关闭。旧卡缺少可恢复凭证的处理仍交由[旧卡旧配额与已入账积分如何过渡](WF-CARDS-06.md)确定。
