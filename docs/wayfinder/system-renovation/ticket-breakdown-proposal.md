# 开发票拆分提案（待审阅，尚未发布）

日期：2026-10-27。来源：[系统改造规格](spec.md)。本文件是供用户审阅粒度与依赖的提案，不是可领取的开发票；不带 ready-for-agent 元数据，不修改父规格或决策票。

拟拆为 **20 个纵向任务**。每票均以可操作的用户行为为交付边界，包含必要的数据约束、服务端接口、界面与既定验收测试；不单独开“建表/写API/做UI/补测试”的横向票。

“开发阻塞”表示开发票依赖；“业务前置”指现有开放决策。即使无开发阻塞，业务前置未解决时也不能擅自决定规则。下面只列直接开发依赖，已被上游覆盖的传递依赖不重复列。

1. **任教授权与受限成绩**

   - 开发阻塞：无开发票前置。
   - 交付：管理员维护按学期的任教班级、学科和班主任职责；教师在现有成绩入口中只可读取和提交授权学科。
   - 验收重点：兼教甲班语文、乙班数学的教师不能读写甲班数学；旧入口和伪造提交执行同一授权。
   - 业务前置：[任课教师与班主任的数据权限如何区分](issues/WF-RENOVATION-04.md)。
   - 覆盖规格用户故事：35、37、38、46。

2. **预分类制卡与打印**

   - 开发阻塞：无开发票前置。
   - 交付：管理员配置D/Z及叶子份额，生成并打印带明确奖励事由、完整分类和版本的卡片；重复生成/重印不增量。
   - 验收重点：方向和叶子数量守恒；不生成T/M/L/G日常卡，不随机补分类，重印复用原凭证。
   - 业务前置：[日常卡如何预设分类并分配子类份额](issues/WF-RENOVATION-02.md)。
   - 覆盖规格用户故事：2、3、4、5、6、7、41。

3. **扫码即时入账**

   - 开发阻塞：**预分类制卡与打印**。
   - 交付：已识别身份的学生扫码即+1，页面显示真实分类和成功动画；未登录恢复意图，重复、失效、超时重试有明确反馈。
   - 验收重点：兑换、卡片已用和原始奖励同事务；同卡并发或重试只产生一次奖励，不增加教师待审；错误不播放新奖励成功反馈。
   - 业务前置：[一期扫码设备与学生身份怎样确定](issues/WF-RENOVATION-01.md)。
   - 覆盖规格用户故事：1、8、9、10、11、12、13、14。

4. **教师纠错与直评**

   - 开发阻塞：**任教授权与受限成绩**。
   - 交付：教师从授权班级账本撤销、改允许分值/分类并查看历史，也可批量无卡直评；管理员退出新流程逐笔处理。
   - 验收重点：在现有有效奖励上即可验证；冲销与替代保存更正链，串行化同笔纠错，稳定请求重试不多加/多扣，卡不恢复可用。
   - 业务前置：[教师纠错与无卡直评允许哪些变化](issues/WF-RENOVATION-03.md)。
   - 覆盖规格用户故事：15、16、17、18、19、20、21、22。

   - 验收重点：复用前票可更正的账本契约；同一认定/材料重试只记一次，认定状态与奖励一致，历史材料可核查。
   - 业务前置：[荣誉归属与正式奖励规则怎样确定](issues/WF-RENOVATION-06.md)。

## 依赖与发布范围说明

- 任教授权、预分类制卡、学籍表导入和钉钉身份预留没有彼此的开发依赖；各自仍须满足业务前置。
- 教师纠错可从现有有效奖励和直评记录开始，不人为等待新扫码；荣誉奖励复用其扩展后的更正账本契约。
- 自动六育评价依赖荣誉、故事和适用指标，后者已传递包含授权与纠错能力；不额外把尚未选定的体测导入设为所有六维的必需前置。
- 报告草稿先支持人工寄语确认，所以状态发布不被AI服务或家长输入开发票无条件阻塞。家长是否必填在报告规则中确认；若必填则发布票新增家长寄语依赖。
- AI寄语与家长寄语仍是规格要求，完整一期试点默认依赖这两票；若学校明确批准延期，调整的是发布范围，不能称功能已经完成。
- 体测、学籍、公共设备和钉钉是否进入本批次，按实际样例与试点决定后固定阻塞边。公共设备若是P0必需，不能等到P2才实现。
- 不额外安排一次横向大重构。授权与账本的必要预整理随最早使用它的完整业务票进行；新增字段/状态采用兼容扩展、业务逐步迁移，试点切换票收口新流程旧写入口。历史学期按已定迁移策略保留，不用新需求强行改写旧事实。
- 每张开发票按一个新上下文可完成的边界起草；若具体样例或平台条件暴露超出范围的工作，再明确拆分而不在执行时悄悄扩票。
