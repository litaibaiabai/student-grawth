当前源码及仓库 DDL实现事实的主要依据：frontend/src、backend、sql/00_full_schema.sql；记录源码内容摘要，便于复核。

1.2 项目目标与当前功能范围

服务谁
学生、教师、管理员三种本地账号角色。
记录什么
六育过程积分、荣誉材料、月度生活故事、学科与维度成绩。
怎样评价
实体卡审核入账与教师无卡直评；故事教师终审；评分引擎汇集 B/P/H。
怎样输出
个人账本、综合评价、管理员发布的报告快照，以及带水印的 HTML 打印视图。
当前边界
已有一组业务页面与控制器，部分链路仍存在字段、状态和安全校验差异，属于需要联调和整改的当前实现。
类别当前实现覆盖说明
评价采集配额配置、批量制卡、令牌预览、申领、审核、批量直评、积分冲销主要写操作具有部分事务及唯一约束控制，幂等与范围校验并未全面闭合。
材料与成绩荣誉路径登记/补交/审核、故事草稿/提交/终审、JSON 成绩预览与提交证书只登记文件路径；故事 AI 为本地模拟；导入不是现成的 Excel 文件上传服务。
汇总与报告规则保存、综合得分查询、报告批量生成发布、本人报告查询、HTML 打印有页面与接口，但前后端字段契约及发布前置条件仍需核对。
基础与运维登录退出、学期保存、指标树查询、审计查询、健康检查、进程内定时器没有完整账号管理、指标写管理、任务中心或真实消息投递闭环。

1.3 本版不计入当前能力的事项

  • 31 页原型里尚未落入生产路由的个人自述编辑、独立消息中心、班级成长页、期末评语确认、账号管理、故事任务配置等。
  • 独立家长账号、钉钉及外部小程序接口、外部故事加权合成、积分兑换、在线申诉、排名。
  • 真实证书文件上传与对象存储、真实大模型调用、持久化任务队列、异步 PDF 文件生成和短期签名下载。
  • 荣誉 REVOKED 撤销、报告发布后自动级联重算、归档后超管更正完整闭环、严格六项发布门禁。
  • Redis / Spring Boot / MinIO / 独立 Worker 并非当前已集成技术；实施计划中的相关选型不作为本版现状。

三、角色说明

3.1 学生（student）

通过本地账号登录，进入成长首页及六个专用业务页。个人数据接口在部分查询中以会话主体覆盖外部 studentId，前端展示不等于后端全部范围校验已完成。

操作当前入口与处理
查看成长首页、六维积分与流水、综合评价、已发布报告。
申领输入评价卡令牌后查询预览，再提交待审申请；未发现浏览器摄像头扫描接入。
申报填写荣誉名称、级别、等次、日期、证书访问路径；支持补交材料。
写作故事正文保存为草稿或正式提交，查看教师终审结果。
打印通过报告导出 URL 打开带水印的 HTML；当前无异步 PDF 任务。

3.2 教师（teacher）

操作当前入口与处理
审核专用页面：扫卡审核、荣誉审核、故事评阅。
评价无卡直评页面批量勾选学生与三级指标；控制器固定 +1。
查阅与导入教师菜单复用 /admin/cards 查看评价卡、/admin/import 进入学科成绩页面；查询与写权限由接口另行决定。
范围控制无卡直评调用 assertStudentInScope；其他读取和审核并非都做了同等强度的实时班级校验。
当前没有独立的教师“期末评语编辑并确认报告”路由；不能把故事终审操作等同于班主任报告确认。

3.3 管理员（manager）

操作当前入口与处理
基础配置创建/修改学期、切换当前/活动标记；浏览六育指标树。指标树没有对应新增/编辑/停用接口。
卡片管理配置教师配额、指定教师/月份/类目批量制卡、查看卡列表及新制卡令牌。未发现完整作废与印刷任务接口。
成绩与规则JSON 导入预览/提交、保存综合评分规则；规则保存接口默认使用 ACTIVE。
报告与纠错批量生成发布报告；查询审计记录；以原流水 ID 发起 -1 冲销。
后台辅助手动触发过期扫描；接口允许管理员执行部分教师操作，但未实现完整授权代审和专用超管能力模型。

4.6 内部调用与事务边界

处理代码中的事务 / 锁实际边界
申领 / 审核beginTransaction，SELECT … FOR UPDATE，状态变更和积分/审计在事务内尚缺全面对象范围、日期与 Outbox 写入闭环。
批量直评整个循环置于同一事务，逐生做部分班级检查不是逐生独立事务；任一 SQL 报错会整批回滚。请求键有随机尾缀。
冲销锁原流水、检查既有冲销、追加 -1 与审计后提交没有完整 school/归档/超管门禁；reason 在后端并未强制非空。
荣誉补交/审核补交与审核各有事务；初次申报主记录与材料写入没有同一显式事务初次申报存在部分成功的可能，重交不严查前序状态。
故事提交 / 评分提交版本在事务内；评分直接 UPDATE评分修改的审计、权限与归档保护没有完整实现。
导入提交使用事务循环 INSERT … ON DUPLICATE KEY UPDATE显式 invalid 行会跳过，并非“任何异常一律拒绝整批”；原版本可能被覆盖。
规则保存事务内将旧规则置 SUPERSEDED 后插入新规则未见自动全校重算任务，状态更新范围和版本策略需核对。
报告发布代码逐生查询、更新旧版和插入新版未包裹显式事务，不能宣称已具备发布原子性；快照查询字段还需与 DDL 对齐。

5.2 登录、退出与范围判断

  • 登录参数为 username/password，当前按 username 查第一条用户，没有 schoolId 登录选择；同名跨校账号的确定性需核对。
  • 验证账户状态、BCrypt 密码后签发 JWT，携带 userId、schoolId、role、grade、class_no、classes；当前 classes 是签发时快照。
  • requireAuth 校验签名与注销黑名单；黑名单查询异常时当前会降级放行，不能声称撤销会话在故障下仍严格生效。
  • 退出将 Token 的 SHA-256 与过期时间写入 token_blacklist；前端清理本地登录态。
  • 菜单按角色组织，前端路由仅要求登录；服务端 requireRole 与局部 assertStudentInScope 共同构成当前权限基础，尚未成为全入口统一范围守卫。

5.3 配额、制卡、扫码申领与审核

  1. 管理员设置 quotaN 与 allocationJson，控制器校验各分配值合计等于总额并保存。
  2. 批量制卡接口另接 count、teacherId、categoryId；查询当前最大 serial_no 后继续增加序号，生成 32 字节随机令牌，存 SHA-256，返回原始令牌用于当前页面展示。
  3. 学生输入 token 后 GET 预览；该接口只查询，并按 USED/PENDING/EXPIRED/VOID 返回不可用提示。
  4. 确认申领事务锁定卡片，要求当前状态 UNUSED，插入 PENDING 申领并将卡置 PENDING；响应明确 pointsCredited=0。
  5. 教师/管理员审批事务锁定申领关联查询；通过更新 APPROVED 和 USED，写 B_CARD +1 与审计；驳回更新 REJECTED、VOID 并写审计。
这是当前状态流转逻辑，不表示完整时效与授权保证。预览/申领未完整核对 school、valid_until 和学期时间窗；审核未完整校验原卡教师、授权代审条件，驳回理由也未强制。过期任务存在状态名不一致，见 5.10、6.1。

5.4 批量直评、账本与冲销

直评接收 studentIds 与三级类目；teacher 调用 assertStudentInScope，manager 分支直接查询学生。事务中每位学生新增一条 A_DIRECT/+1，随后写审计。当前请求键附加时间和随机值，同一请求重试不能据此保证仍命中原记录。

积分查询按学生和学校汇总 delta，并倒序返回最近200条流水；当前 SQL 未使用 termId，因此该接口展示口径是查询到的全部学期累计，不能写成严格“当前学期积分”。评分引擎另按 termId 聚合。

冲销由 manager 路由发起，锁定原记录，要求 delta 为正、尚无 original_id 关联冲销，再新增 REVERSAL/−1 与审计。原 +1 保留，唯一键防同一原记录第二次冲销。当前没有完整的强制理由、归档边界和超管能力检查。

5.5 荣誉申报、材料补交与认定

学生填报 title/awardName、级别/等次、日期、certificateUrl 与说明。控制器写 PENDING 主记录及第一版 material_revision；未提供文件二进制上传服务，缺路径时会使用模拟文件路径。event_key 由标题摘要与时间尾缀组成，不是稳定赛事届次键。

当前教师审核 decision 使用 APPROVED / REJECTED；不等同于扫卡接口的 APPROVE / REJECT。审核通过后，评分引擎汇总 honor_points；REJECTED 不参与求和。补交按原主记录追加 material_version，再回 PENDING；当前重交接口没有严格限定只可从退回态进入。

当前没有独立 RETURNED 与 REVOKED 状态、荣誉撤销接口及其自动重算/新版报告闭环。不能把 SPEC 中的完整状态机描述为当前功能。

5.6 月度故事与模拟 AI 预评

提交以学生/学期/monthKey 查找主记录；正文修改增加 current_version 并保存 material_revision。isDraft 为真写 DRAFT，否则 SUBMITTED。mockEvaluateStory 依据文字长度返回建议分和固定文案，结果存为材料建议，不调用任何外部模型。

教师终审接 teacherScore 及评语，更新为 REVIEWED。评分引擎查询当前学期按 id 倒序第一条 REVIEWED 故事的 teacher_score 作为 G；这不是“所有月份平均”，也不是已批准的校内/外部故事合成规则。

当前没有完整的 AI PROCESSING/FAILED/SKIPPED 异步状态、月度任务配置、归档只读保护与终审修改审计。教师确认月度故事与班主任确认期末报告是两件事。

5.7 JSON 成绩差异预览与提交

  1. 后端 previewImport 接 type（默认 SUBJECT）和 items 数组；预览阶段限制最多1000行。
  2. 按 username 或 studentId 匹配本校学生，校验分数0—100，并查询旧值，返回 NEW/SAME/UPDATE 与 valid/error。
  3. commitImport 再接 type、items、termId，在事务中写 subject_score 或 student_dimension_score；返回生成的 batchNo。
  4. 显式 valid=false 的行会被跳过，其余行执行 UPSERT；当前不是“存在异常则禁止整批提交”的强约束。

当前前端页面为 JSON 文本框，传 type=subject/dimension 与 records，并读取 diff_items；后端接 SUBJECT/items 并返回 diffs。数据名称和结构均需对齐；不能描述为已具备统一的模板文件导入、2MB 文件解析、服务端预览凭证或正式版本追加能力。

5.8 当前综合得分计算

B = (D + Z + T + M + L + G) / 6
P = min(100, max(0, 净过程积分 / process_target × 100))
H = min(100, max(0, 已通过荣誉分 / honor_target × 100))
S = round(six_weight × B + process_weight × P + honor_weight × H, 2)

引擎读取 ACTIVE 规则；没有规则时当前回退80%/15%/5%、20次、12分。六维存在性检查通过才计算 S，否则返回 isComplete=false、缺失维度列表和 null 综合分。当前查询未严格限定 CONFIRMED 或明确最新版本，也会用最新已评故事覆盖 G，故完整性含义仅是“当前 Map 中有六个值”。

示例仅说明现有公式：六维92、88、90、86、94、89，B≈89.8333；过程33次→P=100；荣誉8分→H≈66.6667；按回退权重得到 S=90.20。实际评分政策是否采用该口径，需要单独确认。

边界需修正：均分0在现有返回表达式中可能被转为 null；无 ACTIVE 时自动回退规则，与 SPEC 不允许无生效规则发布的目标不同。当前主要在查询/发布时计算，未发现完整的事件驱动重算任务链。

5.9 期末报告生成、发布、查阅与打印

  1. 管理员提交 studentIds、termId。publishBatch 逐个核对学生存在和账号状态，再调用评分引擎检查六维是否存在。
  2. 查询学科与已通过荣誉，组装 snapshot_json；生成固定格式的等级和模板评语，自述及家长寄语也采用代码模板。
  3. 读取 MAX(version)+1，将历史报告置 SUPERSEDED，插入新 PUBLISHED 报告与审计。当前没有先读取 CONFIRMED 草稿再发布的完整过程。
  4. 返回 published 与 blocked 列表。当前各 SQL 不在显式发布事务内，字段引用与仓库 DDL 仍有差异，需要实际库核对。
  5. 报告查询只取本人/指定学生当前学期最新 PUBLISHED；学生第一次查看会写 read_at，这只表示查阅，不是家长已阅确认。
  6. export-pdf 路由查询报告并返回带学生信息、时间水印与校验字符串的 HTML；浏览器自行打印。没有 jobId、异步轮询、二进制 PDF 或5分钟签名下载链接。
当前高优先级问题：打印路由未挂 requireAuth，按 ID 查询也未加学校/本人/发布态约束；HTML 直接插入部分业务文本。它是现有接口缺口，不是允许匿名查看学生报告的业务设计。
