# 六板块评价数据结构与来源

> 最新来源及工作流以[学校期末报告核心工作流精简方案](superpowers/specs/2026-10-28-term-report-core-workflow-design.md)为准：劳美不发卡；音美三类卡独立；故事为本系统月度文本批量评分。本文及下方前版说明保留作历史对照。

> 本文保留为前版竖表方案说明。[六板块宽表与最少数据表设计](superpowers/specs/2026-10-28-wide-table-simplification-design.md)也已被上述核心工作流方案替代。当前开发依据为[项目执行与技术实现计划书](superpowers/plans/2026-10-28-term-report-core-project-plan.md)及[六表完整DDL](database/term-report-core-v1.schema.sql)，不再按本文多表结构实施。

整理日期：2026-10-28。用途：为六板块综合测评页明确数据存储、来源和负责角色。本文件是数据方案，不是已执行的数据库迁移。

依据：用户提供的学校测评明细图片、补充需求、已核查的[实库结构清单](superpowers/specs/2026-10-28-current-database-schema.json)及[页面字段清单](ui-prototype/semester-assessment/field-map.json)。现有表以该实库清单为准；填写角色与数据来源的分工中，尚未获校方确认的部分明确标为建议。

## 1. 总体结构

六个板块共用指标定义和结果表；身体测量、小程序成绩各有来源表。积分、荣誉、月度故事是可引用的评价证据，不能未经规则映射就直接充当全部期末等级。

| 层次 | 表 | 当前状态 | 保存内容 |
| --- | --- | --- | --- |
| 评价项目 | `grade_indicator_definition` | 已有，需扩展 | 评什么、属于哪个板块/学科、星级或字母、允许哪些评价视角、谁可提供数据 |
| 正式明细 | `student_indicator_value` | 已有，需扩展 | 某学生某学期某指标的一份当前结果，包括自评/他评和来源 |
| 健康来源 | `student_health_record` | 已有，缺跳绳等字段 | 身高、体重、左右视力、1 分钟跳绳及测量来源 |
| 外部故事来源 | `external_story_result` | 建议新增 | 云美小故事提供的最终成绩、外部记录版本及学生匹配关系 |
| 修改历史 | `student_indicator_value_revision` | 建议新增 | 每次指标结果修订前后的值和来源 |
| 辅助证据 | `subject_score`、`score_record`、`honor_record`、`story_submission`、`material_revision` | 已有 | 学科原始结果、过程积分、审核荣誉和本系统月度故事 |
| 报告归档 | `student_report_draft`、`term_report` | 已有，需补完整快照 | 班主任确认的草稿及发布时冻结的完整六板块数据 |

学籍与职责复用 `users`、`academic_year`、`teacher_teaching_assignment`。板块名只是报告展示分组；例如道德与法治按图片排在“智美”，不据此擅自修改它参与六育核算的维度。

## 2. 共用表结构

### 2.1 指标定义表 grade_indicator_definition

一条记录定义一个年级、学期、版本下的评价指标。自评与他评共享同一指标定义，用结果表的评价视角区分。

| 字段 | 类型建议 | 实库状态 | 用途 |
| --- | --- | --- | --- |
| `id` | 主键 | 已有 | 指标定义 ID |
| `school_id / term_id / grade` | 与关联表类型一致 | 已有 | 学校、学期及适用年级 |
| `indicator_code / indicator_name` | VARCHAR(64) / VARCHAR(128) | 已有 | 稳定代码和显示名称 |
| `dimension` | VARCHAR(8) | 已有 | 六育核算维度，不代替报告板块 |
| `value_type` | VARCHAR(16) | 已有 | `star / grade / number / text` |
| `unit` | VARCHAR(32) | 已有 | cm、kg、次等，非测量项可空 |
| `is_required / status` | 现有字段 | 已有 | 适用指标是否必填、是否有效 |
| `definition_version` | VARCHAR(32) | 需新增 | 指标版本；已发布版本不可覆盖 |
| `report_section` | VARCHAR(32) | 需新增 | `conduct / wisdom / health / art / labor / story` |
| `subject_code` | VARCHAR(30)，可空 | 需新增 | 所属课程；作为任课权限校验依据 |
| `report_field_key` | VARCHAR(128) | 需新增 | 报告模板映射键，不要求每个展示格建一列 |
| `sort_order` | INT | 需新增 | 显示顺序 |
| `allowed_values` | JSON | 需新增 | 星级允许 1、2、3；字母集合待学校确定 |
| `perspectives` | JSON | 需新增 | `SELF / OTHER / NONE` 的允许集合 |
| `source_policy` | JSON | 需新增 | 允许的数据来源、主来源、回退条件和确认角色 |
| `aggregation_rule` | JSON，可空 | 需新增 | 经批准的积分或成绩转换规则；未配置则不自动推算 |
| `display_config` | JSON | 需新增 | 表头分组、重复项目、合并单元格等显示配置 |

唯一键建议：`(school_id, term_id, grade, definition_version, indicator_code)`。

### 2.2 学生评价结果表 student_indicator_value

**记录粒度：一个学生 × 一个学期 × 一个指标版本 × 一个指标 × 一个评价视角 × 一个项目实例。**

| 字段 | 类型建议 | 实库状态 | 用途 |
| --- | --- | --- | --- |
| `id / school_id / term_id / student_id` | 匹配现有主外键类型 | 已有 | 记录身份与学校学期范围 |
| `indicator_id / indicator_code` | 现有字段 | 已有 | 指向有效指标定义；二者必须一致 |
| `value_type` | VARCHAR(16) | 已有 | 必须匹配指标定义，不能由提交者任意改类型 |
| `raw_value` | TEXT | 已有 | 原始值或完整文字描述 |
| `typed_value` | VARCHAR(255) | 已有，可保留 | 标准化后的短值，如 `A`、`3`；长文字不放这里 |
| `numeric_value` | DECIMAL(10,2) | 已有 | 数值和星数；三星存 3，不存一串星号作计算值 |
| `status` | VARCHAR(32) | 已有，需统一语义 | 草稿、已提交、已确认、不适用、免测等；缺项不写成 0 |
| `evaluated_by / evaluated_at / revision` | 现有字段 | 已有 | 记录实际评定/录入人、时间和修订号 |
| `definition_version` | VARCHAR(32) | 需新增 | 结果采用的指标版本 |
| `perspective` | VARCHAR(16) | 需新增 | `SELF` 自评、`OTHER` 他评/教师评价、`NONE` 非评分事实或描述 |
| `evaluator_role` | VARCHAR(16) | 需新增 | 实际评定角色，与来源类型分开 |
| `instance_key` | VARCHAR(64)，默认 `DEFAULT` | 需新增 | 同一学生的多个体育/艺术特长使用不同稳定项目键 |
| `source_type` | VARCHAR(32) | 需新增 | 学生自评、教师录入、学科成绩映射、外部故事结果或规则生成等 |
| `source_ref / source_version` | VARCHAR(128) / VARCHAR(64) | 需新增 | 原始记录或批次及其版本 |
| `evidence_refs` | JSON，可空 | 建议新增 | 引用积分、荣誉、月度故事等多条证据，不在这里重复计分 |
| `confirmed_by / confirmed_at` | 用户 ID / DATETIME，可空 | 需新增 | 正式确认人及确认时间；与实际录入人区分 |

唯一键建议：`(school_id, student_id, term_id, definition_version, indicator_code, perspective, instance_key)`。现有唯一键没有评价视角，会覆盖自评/他评，必须更换。

这次明确两项存储细节：

- **评价值与实践描述分别作为指标记录保存。** 例如 `STORY_READ_ASSESSMENT` 与 `STORY_READ_EXPERIENCE` 各一条，分别记录来源和确认人。这样小程序更正成绩不会改掉本地实践描述。劳动的等级与实践文字同样分开。
- 长文字可直接使用现有 `raw_value TEXT`，不必为每段描述再增加一列，也不强制新增 `narrative_text`。若另存说明性评语，它不能替代具有独立来源的正式实践描述。

体育、艺术特长的名称、评价、成果通过相同 `instance_key` 关联。不要把“特长1/特长2”固定成数据库列；页面稿两行只是显示样例。自评/他评使用同一个评价指标代码，按 `perspective` 分开，不让编码后缀成为唯一的权限区分手段。

### 2.3 修订历史表 student_indicator_value_revision

建议新增 `id`、`indicator_value_id`、`revision_no`、`value_snapshot JSON`、`source_snapshot JSON`、`actor_id`、`change_reason`、`created_at`；唯一键为 `(indicator_value_id, revision_no)`。主键类型应与结果表一致。

历史快照包含值、视角、项目实例、来源和确认状态。只增加修订号却覆盖原值，无法回答“上次发布采用了哪次评价”。

## 3. 六板块的数据及来源

本节中的填写与确认分工为实施建议；体测来源、故事成绩接口及等级转换仍须学校明确。

### 3.1 德美少年

| 数据 | 数量及制式 | 正式存储 | 来源及负责角色 |
| --- | --- | --- | --- |
| 有礼貌、讲文明、讲信用、负责任、有爱心、守规则、善交流、会合作的自评 | 8 个星级值 | `student_indicator_value`，`SELF` | 学生在本系统自评；身份由登录会话确定 |
| 同八项的他评 | 8 个星级值 | 同表同指标，`OTHER` | 建议班主任确认；同伴评价若要纳入，应先明确采集和聚合规则 |
| 行为过程证据 | 可多条，不直接增加报告格 | `score_record`，必要时引用已审核 `honor_record` | 扫卡、无卡直评及有效冲销形成净积分；作为教师参考或经批准规则的输入 |

没有“积分达到多少自动三星”的已批准口径，不能凭总积分给八项批量填相同星级。

### 3.2 智美少年

五门课程均有学习兴趣、学习习惯、学习方法、过程表现四个星级值；下列学业分项使用字母等级。

| 课程 | 字母等级分项 | 本图展示值数量 | 来源及负责角色 |
| --- | --- | ---: | --- |
| 道德与法治 | 认知水平、实践能力 | 6 | 对应任课教师分项评定 |
| 语文 | 积累与运用、阅读与鉴赏、表达与交流、梳理与探究、书写 | 9 | 语文教师分项评定 |
| 数学 | 基础知识、数学思维、信息提取、解决问题 | 8 | 数学教师分项评定 |
| 科学 | 科学观念、科学思维、探究实践 | 7 | 科学教师分项评定 |
| 英语 | 听力素养、口语素养、书面表达、阅读能力 | 8 | 英语教师分项评定 |

38 个正式分项值统一保存到 `student_indicator_value`，关联对应课程和 `OTHER`。`subject_score` 已有 `score / raw_score / grade_label / version`，可作为原始学科结果来源，但**一门课总分不能直接填满该课所有能力分项**。若外部学科系统能提供对应分项，可按学生、学期、课程、指标代码匹配后接收。

### 3.3 健美少年

| 数据 | 类型 | 存储字段/指标 | 来源及负责角色 |
| --- | --- | --- | --- |
| 身高 | 数值，cm | `student_health_record.height / height_unit`，已有 | 建议学校健康平台、校医或指定体育/健康负责人提供真实测量数据 |
| 体重 | 数值，kg | `weight / weight_unit`，已有 | 同上 |
| 左视力、右视力 | 原始测量值 | `left_vision / right_vision`，已有 VARCHAR(16) | 同上；先确认视力记录标准，不擅自更换数值口径 |
| 1 分钟跳绳 | 非负整数，次 | **新增** `jump_rope_1min INT UNSIGNED NULL` | 体育测试记录或体育教师确认的数据 |
| 体育与健康学业水平 | 字母等级 | 指标结果 `PE_ACADEMIC`，`OTHER` | 体育教师；可引用匹配的正式学科等级 |
| 体育与健康过程表现 | 星级 | `PE_PROCESS`，`OTHER` | 体育教师过程评价 |
| 体质健康测试自我评价 | 星级 | `FITNESS_SELF`，`SELF` | 学生自评 |
| 体测水平、体测过程表现 | 各一个星级 | `FITNESS_LEVEL / FITNESS_PROCESS`，`OTHER` | 体育教师或经学校认可的体测平台结果；转换规则需批准 |
| 体育技能特长项目名称 | 文本 | `SPORTS_SKILL_NAME`，`NONE`，按项目实例保存 | 学生申报或体育教师录入，建议体育教师确认 |
| 特长自评、教师评价 | 两个独立星级 | 同一 `SPORTS_SKILL_EVALUATION` 指标，`SELF / OTHER` | 学生和体育教师分别提供 |
| 特长成果表现 | 文本 | `SPORTS_SKILL_OUTCOME`，`NONE` | 建议体育教师确认，可引用学生材料及有效荣誉 |

健康表除跳绳外，建议增加 `source_type / source_ref / source_version`；复用现有 `tested_at / imported_by / batch_id / revision`。视力标准若不能由导入批次配置明确，可增加 `vision_standard VARCHAR(32)`。保留原有肺活量等字段，未出现在当前报告上不等于应删除。

健康原始值来自测量，体育评价来自评定；两类不能互相替代，身高、体重、视力也不能直接作为奖惩积分。

### 3.6 故事美少年

| 数据 | 类型 | 正式存储 | 来源及负责角色 |
| --- | --- | --- | --- |
| 我爱读故事评价 | 独立评价值 | `STORY_READ_ASSESSMENT`，`OTHER` | 若小程序提供对应分项最终成绩则接收；否则由指定故事评价教师评定 |
| 我爱读故事实践描述 | 文本 | `STORY_READ_EXPERIENCE`，`NONE` | 本系统中学生提供事实，建议教师确认报告文字 |
| 我爱听故事评价 | 独立评价值 | `STORY_LISTEN_ASSESSMENT`，`OTHER` | 同上，但必须是“听”项目的结果 |
| 我爱听故事实践描述 | 文本 | `STORY_LISTEN_EXPERIENCE`，`NONE` | 本系统填写并确认 |
| 我爱讲故事评价 | 独立评价值 | `STORY_TELL_ASSESSMENT`，`OTHER` | 同上，但必须是“讲”项目的结果 |
| 我爱讲故事实践描述 | 文本 | `STORY_TELL_EXPERIENCE`，`NONE` | 本系统填写并确认 |

页面稿暂以星级类型预留三项评价；实际等级制式、是否能获得分项最终成绩及主来源优先级待学校确认。小程序若只有一个总分，只能保存为总结果，不能复制成读、听、讲三个分项。

本系统月度故事继续使用 `story_submission` 和 `material_revision`。它的正文、教师分和评语是另一类记录，可以被引用为证据；不直接覆盖读听讲三项结果，也不合并小程序入口。按用户要求，小程序对接范围是最终成绩，实践描述从本系统采集，默认不接收小程序原稿。

## 4. 外部故事来源表 external_story_result

建议新增，作为接收和更正的原始来源表；正式报告不绕过指标结果直接读取未匹配的外部记录。

| 字段 | 类型建议 | 作用 |
| --- | --- | --- |
| `id / school_id / term_id` | 匹配关联表主键类型 | 外部结果所属学校和学期 |
| `student_id` | 学生 ID，可空 | 待匹配时允许为空；匹配成功后才能参与评价 |
| `external_student_ref` | VARCHAR(128) | 外部稳定学生标识，不按姓名猜测 |
| `provider` | VARCHAR(32) | 云美小故事等来源标识 |
| `external_record_id / external_version` | VARCHAR(128) / VARCHAR(64) | 外部成绩记录和更正版本 |
| `result_code` | VARCHAR(32) | `READ / LISTEN / TELL / TOTAL` |
| `value_type / raw_value` | VARCHAR(16) / TEXT | 最终成绩的制式及原始值 |
| `score_value / grade_value` | DECIMAL(10,2) / VARCHAR(20)，可空 | 标准化后的数值或等级，按制式取相应字段 |
| `status` | VARCHAR(24) | 待匹配、有效、已被新版本替代、撤回等 |
| `source_ref / received_at` | VARCHAR(128) / DATETIME | 接收接口/批次及时间 |
| `confirmed_by / confirmed_at` | 用户 ID / DATETIME，可空 | 校内匹配及正式采用的确认记录 |

唯一键包含 `(school_id, provider, external_record_id, external_version, result_code)`。外部记录 ID 必须在该提供方内具有明确唯一范围；若其 ID 只在学期内唯一，应将 `term_id` 加入唯一键。

只接收最终成绩，不需要在此表增加故事原稿或实践描述字段。外部更正追加版本；对应正式指标记录保留来源引用，并触发草稿重新确认。撤回时同样使引用结果失效，不能继续拿旧结果发布。

## 5. 数据来源的记录规则

| `source_type` 建议值 | 含义 | `source_ref` 指向 |
| --- | --- | --- |
| `STUDENT_SELF` | 学生本人自评 | 本次自评提交记录/请求，评定人为本人 |
| `TEACHER_ENTRY` | 教师分项评定 | 该录入提交或批次及其版本 |
| `STUDENT_TEXT_CONFIRMED` | 学生提供事实、教师确认文字 | 提交记录及确认版本 |
| `SUBJECT_RESULT` | 采用正式学科结果 | `subject_score` 有效记录 ID 与版本 |
| `HEALTH_IMPORT` | 体测原始数据导入 | `health_import_batch` 批次及原始行引用 |
| `HEALTH_PLATFORM` | 学校健康平台同步 | 外部平台记录 ID 与版本 |
| `EXTERNAL_STORY_FINAL` | 小程序最终成绩 | `external_story_result.id` 和外部版本 |
| `RULE_COMPUTED` | 按批准规则生成评价 | 规则版本；`evidence_refs` 记录实际采用的来源 |

这些是建议新增字段的取值规范，不代表现有数据库已经具有这些枚举。入口、来源、确认分开记录：例如钉钉是登录/访问入口，不能写成体测或学科成绩的数据来源。

## 6. 报告使用数据的方式

1. 按学校、学期、年级和字典版本加载六板块指标。
2. 读取独立的自评、教师评价、文字及特长项目实例；健康原始值从健康记录读取。
3. 只采用来源有效、满足该项确认规则的结果；未提供记缺失，不当作 0 或一星。自评提交完成与教师确认是不同条件。
4. 将上述明细、来源版本、健康值、模板版本一起写入 `student_report_draft.draft_snapshot`。
5. 发布时写入 `term_report.snapshot_json`；阅读和打印消费同一冻结快照。发布后来源更正不静默修改旧报告。

逐项映射见[六板块字段与来源台账](data/six-section-field-sources.json)，含页面 102 个展示位置：图片原有 99 个，加前文要求的三个故事评价位。它包含自评、文字和可重复特长位置，不能与原 Word 的 74 个合并字段混算。

## 7. 还需要学校确定的来源

| 事项 | 待确认内容 |
| --- | --- |
| 德美他评 | 班主任直接评，还是采集同伴评价后确认；积分映射阈值是什么 |
| 健康原值 | 校医、体育教师还是学校健康平台提供；使用哪种视力标准 |
| 故事评价 | 小程序是否分别提供读/听/讲，还是只提供总结果；本地与外部谁为主来源 |
| 等级规则 | 字母等级集合、故事评价制式、积分/数值转星级或字母的规则 |
| 课程职责 | 各学科、综合实践、地方课程和特长项目的负责教师及确认权限 |

未确认前，可以建设输入、存储、来源追踪和缺项检查，但不自动编造等级或实践描述。本文件未修改数据库或正式业务代码。
