## 1. UAT 验收用例清单

| 用例编号 | 测试业务场景 | 预期必须通过的验收标准 |
| :---: | :--- | :--- |
| **T01** | 学生登录后尝试篡改请求中的 `student_id` | 服务端严格以当前会话 `users.id` 为准，拒绝访问他人数据 |
| **T02** | 教师试图查看或操作非任教班级学生 | 服务端基于 `users.classes` 强制拦截，抛出 `FORBIDDEN_SCOPE` |
| **T03** | 管理员执行操作未带学校约束 | 跨校查询严格隔离，不得越权访问其他学校数据 |
| **T04** | 学期已停用（`active = 0`）时发起写入 | 所有业务写接口立即拒绝，提示 `TERM_CLOSED` |
| **T05** | 管理员配置教师月度卡配额 $N$ 张 | 每位教师各三级指标张数总和恰好等于 $N$ |
| **T06** | 月初批量制卡任务因网络超时重复触发 3 次 | 唯一键拦截重复制卡，物理卡条目总数不增加，保持严格幂等 |
| **T07** | 上月未使用的实体卡跨入次月后由学生扫描 | 系统依据服务器时间拒绝发起新申领，提示 `CARD_EXPIRED` |
| **T08** | 教师线下将卡发给学生（系统无发放记录） | 学生正常扫码申领，系统不依赖“预先绑定学生”逻辑 |
| **T09** | 学生移动端点击“确认申领” | 单据置为 `PENDING`，卡片置为 `PENDING`，学生过程积分**尚未增加** |
| **T10** | 两个学生同时扫描同一张未用实体卡 | 悲观锁保证首个有效请求进入 `PENDING`，第二名学生提示不可用 |
| **T11** | 客户端网络抖动重复发送 5 次申领请求 | 依据 `request_key` 幂等返回同一申请单，不重复建单 |
| **T12** | 教师审核通过学生的扫码申请 | `claim` 置 `APPROVED`，卡置 `USED`，同事务原子新增 `score_record (+1)` |
| **T13** | 教师驳回学生的扫码申请 | 必填驳回理由，卡置 `VOID` 且永久作废，学生积分不增加 |
| **T14** | 教师试图审核非本人名下分配的实体卡 | 系统拒绝操作，提示无权审核非本人归属卡片 |
| **T15** | 已被使用的实体卡（`USED`）再次被他人扫描 | 接口立即拦截，提示卡片已使用，不泄露原申领学生姓名 |
| **T16** | 月末提交的待审单据在次月宽限期内审核 | 符合配置宽限期允许通过，且积分正确归入卡所属学期 |
| **T17** | 审核过程中模拟数据库宕机断网 | 事务完全回滚，严禁出现“卡变 USED 但未发分”或“发分但卡仍 PENDING” |
| **T18** | 教师执行 A 模式直评，批量勾选学生 | 每个人产生固定 +1 流水，支持不同学生逐一记录备注 |
| **T19** | 同一 A 模式批量直评批次重试提交 | 依据 `request_key` 拦截，已加分学生不会重复发分 |
| **T20** | 教师误操作发分后由管理员发起冲销 | 新增一条 `delta = -1` 流水并关联 `original_id`，总积分即刻抵消 |
| **T21** | 针对同一笔原始流水重复执行冲销 | `uk_score_reversal_original` 唯一键硬拦截，防止二次扣分 |
| **T22** | 学生申报区级二等奖荣誉证书 | 状态为 `SUBMITTED`，系统暂不折算荣誉分 |
| **T23** | 教师退回荣誉申报，学生补充清晰图片重交 | 沿用同一荣誉主记录，在 `material_revision` 生成新版本 |
| **T24** | 同一学生针对同一赛事同一届次申报两张证书 | `uk_honor_event` 拦截，系统仅认定最高等级一次奖项 |
| **T25** | 学生提交生活故事，大模型接口超时宕机 | 业务不阻断，文稿安全存盘，教师可纯人工录入终审得分 |
| **T26** | 大模型生成预评分 85 分，教师修改为 90 分 | 正式成绩仅采纳教师终审分 90 分，保留 AI 建议痕迹 |
| **T27** | 导入学科成绩或五育成绩包含同名学生 | 系统严格按照唯一身份账号匹配，不发生重名串户 |
| **T28** | 导入外部成绩生成 `batch_no` | 正式表中每行持久化该批次号，支持按批次对账审计 |
| **T29** | 六育正式分缺失任意一项（如缺少美育） | 综合评价状态显示 `INCOMPLETE`，严禁按 0 分默认算总分 |
| **T30** | 学生各项满分时验证上限封顶 | 过程分满 20 次封顶 100 分，荣誉满 12 分封顶 100 分，不溢出 |
| **T31** | 学生查阅期末综合素质报告 | 仅可查阅处于 `PUBLISHED` 状态的本人报告，其他状态不可见 |
| **T32** | 导出本人学期综合素质发展报告 | 生成带有学生姓名、学号及导出时间防伪水印的 PDF 文件 |
| **T33** | 报告发布后因事实差错由管理员受控更正 | 重新测算并生成 `version + 1` 的新版报告，原报告标记 `SUPERSEDED` |

## 2. 上线阻断性红线标准（P0 Blockers）

任何以下异常均判定为最高等级阻断性缺陷，禁止投产：
1. 越权访问（改动 URL 参数能查看他人未脱敏成绩或报告）；
2. 双重发分（重复点击造成学生同一事项获得 2 次加分）；
3. 审核前发分（学生仅扫码但教师未批准即提前入账）；
4. 超期码复活（跨月未用码次月继续被扫出加分）；
5. 作废卡复活（被驳回或作废的实体卡再次被他人扫码成功）；
6. 账本物理篡改（存在任何 `UPDATE score_record` 或 `DELETE` 操作）；
7. 报告物理覆盖（生成新版报告时将已发布的旧版物理覆盖）。
