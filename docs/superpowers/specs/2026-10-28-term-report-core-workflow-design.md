# 学校期末报告核心工作流精简方案

日期：2026-10-28。状态：设计评审稿，未实施。最新业务依据为用户确认的六种数据来源及《六育评价明细.pdf》。本方案替代此前以通用指标竖表或 11 张核心业务表为中心的设计。

## 1. 系统只围绕一件事运行

**采集六种来源的数据，自动填充一张学生学期评价宽表，由班主任确认后，全校统一发布可阅读、可打印的期末报告。**

卡、奖状、故事保留为报告数据采集入口。积分商城、成长等级、排行榜、游戏主题、独立荣誉展示系统、独立故事社区、公共设备平台、独立通知中心不在本次基线。原有账号登录和教师授权复用；不新增家长账号体系，家长协助使用学生账号提交材料。

本次不运行数据库迁移，不删除历史数据，不调用评分模型。具体评分服务和文件解析技术由实施人员选择，必须满足本方案的输入输出与评分规则；不能用字数规则冒充内容评分。

## 2. 已明确的业务决定

| 事项 | 用户已确认的要求 |
| --- | --- |
| 六种来源 | 卡生成、外部导入、奖状生成、学生自评、教师评价、故事生成 |
| 卡计分 | 一次有效无卡直评或一张有效扫码兑换卡计 1 分 |
| 卡折星 | 需要设计累计分到 1/2/3 星的算法；本稿给出建议初值 |
| 劳美 | 不发卡；学业水平由任课教师导入；成果表现由奖状生成 |
| 音乐、美术的卡 | 各有学科素养教师评价、学科素养过程表现、艺术技能教师评价三类，独立累计 |
| 故事形式 | 文本；支持粘贴和上传文本 |
| 故事频率 | 每月集中提交一次，读/听/讲每类 1–3 篇，共 3–9 篇 |
| 家长工作量 | 一个入口准备整月内容、一次提交，不逐篇办理独立提交流程 |
| 结果存储 | 所有学生各学期六板块数据存入同一张宽表，每名学生每学期一行 |
| 发布与打印 | 班主任确认、管理员全校一次性发布；HTML 查看，浏览器保存 PDF 打印 |

后文标注“建议”的算法参数、材料审核方式、页面分组及最少表结构，是本方案的设计选择，供本轮评审确认。

## 3. 从开学采集到期末发布的工作流

### 3.1 管理员配置一次学期

导入/维护学生与教师账号，设置任教班级、学科、班主任；启用学期和学校报告模板，配置适用年级、所需故事月份、评分规则、下学期开学日期。给教师下发月度卡总额度。

固定报告字段和卡分类用一份代码配置，学期差异和阈值放学期配置 JSON，不建设独立指标树管理平台。规则版本进入所有计算结果和报告快照。

### 3.2 学期中只采集报告需要的材料

| 来源 | 谁操作 | 最简操作 | 系统完成什么 |
| --- | --- | --- | --- |
| 卡生成 | 教师、学生 | 教师在总额度内按班、学科、项目生成卡；学生扫码；或教师无卡直评 | 记该学生该项目 +1 分，按规则生成星级 |
| 外部导入 | 任课教师、管理员 | 教师按任教范围导入学业水平；管理员导入五项体测原值 | 校验学生、学期和字段，预览差异后写入宽表 |
| 奖状生成 | 学生/家长协助，教师确认 | 上传证书、确认识别出的项目与归属；教师批量确认有效材料 | 匹配特长/成果指标，按配置形成等级、星级或事实描述 |
| 自我评价 | 学生/家长协助 | 期末集中填写自评和学生自述 | 写入独立自评列，不覆盖他评或系统计算列 |
| 教师评价 | 对应教师、班主任 | 填写确需人工评价的特长教师评价、学期寄语等 | 只更新负责的字段，自动来源的错误通过更正源记录处理 |
| 故事生成 | 学生/家长协助，系统评分 | 每月一次提交三类文本，各 1–3 篇 | 批量评分，分别计算读/听/讲月度成绩和期末成绩 |

扫码和无卡直评保留直接入账。新卡已经绑定分类，无须再次选分类和逐卡审核。制卡仍支持一次生成教师全部班级，并按班级输出独立卡片文件后打包；打印资料按原卡记录重建，不为打印另建业务表。

### 3.3 期末只处理缺项与异常

系统显示按班、按来源的完成情况：缺哪门学科、哪个月故事未完成、哪份奖状待确认、哪项自评未填。任课教师集中补齐自己的任务；班主任查看完整报告草稿，修改寄语，按班批量确认已齐全且无异常的报告。

班主任不重复录入卡生成、已导入、已确认奖状和已完成故事评分的数据。自动来源如需纠错，回到相应记录撤销或更正，再重新计算；不直接手改星级后被下次计算覆盖。

### 3.4 管理员全校发布一次

管理员只在发布中心看完成情况和阻断原因。全校适用项目就绪、报告来源版本与确认版本一致后，统一发布。家长和学生查看本人报告，直接通过浏览器保存 PDF 或打印。

报告发布后归档不变；后续更正进入新草稿，经重新确认后形成新的全校发布版本。

## 5. 卡分类和卡分折星算法

### 5.1 只配置实际对应报告的 37 类卡

| 一级分类 | 末级项目 | 数量 |
| --- | --- | ---: |
| 德美 | 有礼貌、讲文明、讲信用、负责任、有爱心、守规则、善交流、会合作 | 8 |
| 道德与法治、语文、数学、科学、英语 | 每科各有学习兴趣、学习习惯、学习方法、过程表现 | 20 |
| 体育与健康 | 过程表现 | 1 |
| 体质健康测试 | 体测水平、过程表现 | 2 |
| 音乐、美术 | 每科各有学科素养教师评价、学科素养过程表现、艺术技能教师评价 | 6 |
| 信息科技、劳动、综合实践活动、地方课程 | 不设卡分类 | 0 |

每张卡生成时固定末级项目、班级、学科、学期和 +1 分。无卡直评使用同一目录、每次每学生每项目 +1 分；不改变实体卡已核定张数。

本稿建议实体卡仅允许发行班级的学生兑换，班级按本学期学籍识别；这是评审时可调整的限制选择。已生成卡占用额度，重印不再占额，作废不自动放回额度；补发由管理员明确增补额度，防止反复作废超发。

### 5.2 推荐采用达标分折星

累计单位为“学生＋学期＋项目”，不把六个板块所有卡混加后填每一格。

设有效累计分为 P，项目达标分为 T，T 是不小于 2 的整数。P 等于已兑换卡、有效直评的积分，加上有效更正；未兑换卡不计分，重复提交不重复计分。

```text
1 星：0 ≤ P < ceil(T / 2)
2 星：ceil(T / 2) ≤ P < T
3 星：P ≥ T
```

**建议初值 T＝10**：0–4 分一星，5–9 分两星，10 分及以上三星。原始积分继续保留，超过达标分只封顶显示三星，不丢积分，也不增加第四颗星。

T 可按年级、项目配置。学期开始要结合班级人数、卡额度和直评安排检查目标是否可达，不能直接认定所有项目永久都用 10。规则变更用新版本并使有关草稿失效。

**未完成采集与真实零分分开**：负责教师确认该班该项目记录完成后，适用学生没有有效卡记 P＝0，按上述规则显示一星；未完成采集、规则未配置、学生不适用时分别显示待完成/未配置/不适用，不能提前批量填一星。积分出现负数应报更正异常，不静默截成 0。

## 6. 月度故事最简流程及算法

### 6.1 家长每月只提交一个批次

一个学生每月一个有效批次，内含三类，每类 1–3 篇。支持直接粘贴/编辑文字，也支持上传 TXT 后回显到编辑框。TXT 是本稿建议的首期文件范围；不引入音视频、Word 或 PDF 故事解析流程。

学生/家长可分次保存草稿，三类各至少一篇后，一次正式提交。每类最多三篇，总计 3–9 篇；系统一次处理该月全部材料，不要求逐篇点提交。提交后修订整个批次时保存新版本，不覆盖已用的旧版文本。

每篇保存类别、篇名（可选）、正文、内容摘要、评分状态、分数和反馈。服务器按“学生＋月份＋批次版本＋篇目位置”幂等处理，重复点击不会重复提交或重复计分。文本指纹可用于提示重复，但不因不同活动引用相同故事就擅自删除资料。

正式提交新版本即把该月标为待重新评分，使有关报告确认失效。评分回写必须同时匹配当前批次版本、正文指纹和评分规则版本；旧版本迟到的结果仅保留追溯，不覆盖新版本或宽表。处理锁到期可接续重试，同一篇同一版本的成功结果只计一次。

### 6.2 评分只评价所提供的文本

建议按年级配置 100 分量规，初版四维各 25 分：内容完整性、与读/听/讲类别相关性、表达条理、个人理解与感受。评分服务返回分项分、总分、依据及简短反馈；这是初版建议，评审时可调整。

不从文字推断未提供的音频表现，不按字数直接给高分。评分任务失败时保留全文并支持重试，不写默认分，不要求家长重新提交。教师仅集中处理失败、异常或有争议的结果，不把每篇人工审批设成常规必经步骤。

### 6.3 月度与期末汇总

每月每类分别对有效评分文本取算术平均：

```text
本月读故事分＝本月 1–3 篇读故事得分平均
本月听故事分＝本月 1–3 篇听故事得分平均
本月讲故事分＝本月 1–3 篇讲故事得分平均

期末某类故事分＝该类在本学期应提交月份的有效月分平均
```

月份等权：提交三篇不会天然比提交一篇多得分。每类分别汇总，不合成一个总分填满三格。缺少应提交月份时显示缺项，不按零分参加平均。所需月份按学期和实际启用时间配置，不要求补交功能启用前的月份。

**建议故事分折星初值**：0≤分数<60 为一星，60≤分数<85 为两星，85≤分数≤100 为三星。先按未提前四舍五入的均值判档，再格式化展示。量规、汇总和折星版本全部保留到来源记录与报告。

## 7. 奖状到成果的最简流程

上传 → 识别/填写奖状事实 → 匹配对应课程或读听讲项目 → 教师批量确认 → 自动写入成果字段。

保留奖项名称、颁发单位、日期、奖项级别、奖次、原文件、对应项目和认定状态。系统先给出候选归属；无法明确归属的材料进入待确认，不随机填入某学科。只匹配报告成果与特长，不另建荣誉积分商城或六育附加总分。

成果字母/星级按学校配置的“奖状事实→目标字段等级”映射表生成；同一学生同一字段有多项有效成果时，**建议取最高档**，同时保留全部获奖事实。未配置映射时只生成事实与待配置提示，不猜测 A 或三星。

**无奖状不阻断报告**：完成材料截止或确认该学期无成果材料后，该类标记“暂无成果记录”，评分保持空值，不虚构奖项、不默认三星。待审核或归属冲突与“确无材料”分开处理。体育/艺术特长没有项目时显示空项目区，不强迫学生填写不存在的特长或其自评。

## 8. 数据库目标：6 张核心业务表

| 表 | 保存什么 | 为什么保留 |
| --- | --- | --- |
| `users` | 管理员、教师、学生账号和基础身份 | 登录、学生识别及角色 |
| `academic_year` | 学期、模板/规则配置、故事月份、报到日期、全校发布状态 | 一个学期一份配置和发布控制 |
| `teacher_teaching_assignment` | 教师负责的学期、班级、学科和班主任职责 | 不依赖前端隐藏字段来限制教师 |
| `student_term_evaluation` | 一名学生一学期的完整六板块宽表、学生自述、寄语、来源及确认状态 | 当前正式值和报告草稿只存一处 |
| `evaluation_source_record` | 六种来源的材料、批次、卡额度/卡/直评、导入行、更正及处理状态 | 所有采集记录共用一张表，不再每种来源另建多张表 |
| `term_report` | 每次发布的完整冻结报告、配置版本及发布版本 | 历史报告不受后续改分影响 |

6 张指核心业务表，不包括数据库迁移工具自己的技术记录。一次性迁移到精简系统时保留原库备份；历史表不在现网直接 DROP。

### 8.1 宽表只保存结果

唯一键为 `(school_id, term_id, student_id)`。固定评价使用普通列；可有多条的体育/艺术特长用两个数组；五方面自述、学期收获与目标、教师/家长寄语直接放本行。

来源用 `field_sources JSON`，各班级学科/项目的完成与确认状态用 `section_meta JSON`；`revision / confirmed_revision / confirmed_by / confirmed_at` 管理班主任确认。来源正式提交、撤回、更正或重新评分后，受影响宽表 revision 变化，原确认失效。

相比此前 SQL，至少新增：`information_technology_outcome_grade`、`labor_outcome_grade`、`integrated_practice_outcome_grade`、`local_course_outcome_grade`，以及 `story_read_outcome_star`、`story_listen_outcome_star`、`story_tell_outcome_star`。原学业和描述列保留，来源按本稿切换。

### 8.2 统一来源表只统一存储，不混淆业务

建议公共字段：

| 字段 | 用途 |
| --- | --- |
| `id / school_id / term_id / student_id` | 来源归属；批次头、未兑换卡可无学生，明细必须能定位学生 |
| `source_type` | 六种数据来源之一；纯管理留痕可为空，不参与成绩计算 |
| `record_kind` | QUOTA、CARD、DIRECT、BATCH、ITEM、FORM、REVERSAL、AUDIT 等记录形态 |
| `parent_id / original_id` | 批次与明细、额度与卡、原记录与更正关系 |
| `owner_teacher_id / actor_id` | 卡或任务负责人、实际操作者 |
| `month_key / target_key` | 所属月份、明确的报告目标字段或故事类别 |
| `business_key` | 服务端校验的稳定业务键，学校范围内唯一，防重复提交 |
| `status / payload_json` | 明确状态；不同形态按固定合同保存正文、成绩、文件、导入值等 |
| `delta` | 卡/直评为 +1，更正为 -1；其他来源不用这个字段 |
| `token_hash / token_ciphertext / valid_from / valid_until` | 仅卡记录使用，复用现有安全凭证和重印机制 |
| `revision / attempts / locked_until / created_at / updated_at` | 修订、异步处理重试和处理锁 |

每类 payload 和状态转移由代码中的固定结构验证，不能成为随意写入任意 JSON 的接口。卡分类只允许映射文件中的 37 类；任何输入均不能把字符串当作任意 SQL 字段名使用。

| 来源形态 | 一条记录的粒度 | 关键限制 |
| --- | --- | --- |
| 卡额度 QUOTA | 教师某月一份管理员额度及教师分班计划 | 管理员改总额；教师只改额度内计划，生成时锁额度并核对各班总数 |
| 实体卡 CARD | 一张真实卡 | 固定班级/学科/末级项目和序号；一个令牌只兑换一次 |
| 无卡直评 DIRECT | 一个学生一个项目一次 +1 | 任教范围校验、稳定请求键；重试不多计 |
| 更正 REVERSAL | 原记录的一次有效冲销 | 引用原记录，禁止重复冲销；更正类别用冲销＋新记录 |
| 导入 BATCH / ITEM | 批次头＋每学生一条导入明细 | 预览和提交核对版本；只更改提供的允许字段；不将整批其他学生数据返给单个学生 |
| 奖状 ITEM | 一份证书或一项认定 | 原文件、认定版本和目标字段可追溯；撤销使有关结果重算 |
| 故事 BATCH / ITEM | 学生每月一批，批次下 3–9 篇明细 | 正文提交版本固定；评分可重试；仅当前有效版本参与汇总 |
| 自评/教师 FORM | 一次表单提交或更正 | 保存实际修改字段和来源，其他列不覆盖 |
| 管理 AUDIT | 配置、确认、发布等一次操作 | 不参与加分，私有正文受字段/角色权限限制 |

来源记录保留材料及更正历史；宽表保存当前投射结果。两者职责不同，不再保留独立积分账本、卡申领、荣誉、故事、导入批次和操作日志表来重复保存同一事件。

## 9. 最少页面与工作量

| 角色 | 页面入口 | 工作量 |
| --- | --- | --- |

| 班主任 | 班级报告确认 | 看缺项、批量确认齐全报告，异常个别处理 |
| 管理员 | 学期与基础资料 | 学籍、任教、阈值、模板、日期与卡额度配置 |

| 管理员 | 全校报告发布 | 状态总览、缺项定位、一次发布、版本记录 |

保留一个后端、一套前端和同一个 MySQL。评分、材料处理、打印在现有后端内工作，使用来源表的处理状态重试；不新增微服务、独立队列表或任务平台。

## 10. 确认、权限与全校发布

### 10.1 字段权限和完成状态

学生只能提交本人自评、自述和材料；教师只能处理任教学科/班级；班主任确认整份报告。管理员导入页可核对被授权导入的体测原值，发布中心只看完成情况，不因宽表存在就返回所有学生健康、故事和寄语正文。

宽表更新使用字段白名单、局部 UPDATE 和 revision 校验，不允许客户端提交整行覆盖。卡和故事自动生成列不作为普通手工输入列。来源与记录详情也要校验学生归属；不能把导入批次的其他学生数据混在本人响应里。

建议缺项门槛：适用学科导入齐全、卡项目已结算、应交故事月份评分完成、必需自评及学生自述提交、班主任最终确认有效。家长寄语建议非阻断。无奖状属于合法无成果状态；不适用课程/特长按模板配置跳过。

### 10.2 一次性发布，不逐人提前可见

1. 服务端确定该校该学期完整应评名单，不接受前端传任意学生子集作为发布范围。
2. 冻结名单、每份报告的 revision、确认版本、模板/规则版本到学期的发布清单；进入准备状态。
3. 准备期间所有相关来源写入、材料撤销、故事评分回写和规则变更都遵守学期发布锁。新内容保留草稿或稍后重试，不丢材料。
4. 对全部报告重新检查，写入 `term_report` 待激活归档，包含姓名班级、六板块、正文、来源和规则快照。
5. 全部准备成功后，原子切换 `academic_year.active_release_version`。学生阅读和打印必须同时检查归档版本已激活；中途失败保留原已发布批次。
6. 同一 release key 重试复用已有准备结果，不重复生成版本；更正数据后用新批次重新确认发布，旧归档保留。

管理员不在发布时自动替班主任填默认评语或自动写“已确认”。

## 12. 验收场景与设计选择

### 必须通过的业务场景

1. 同一项目 1 次直评＋4 张有效卡＝5 分；同一请求重试不多计；按 T＝10 显示两星。反向更正一分后为 4 分、一星。
2. 一张卡被并发扫码，只入账一次；卡的班级/分类不受客户端更改。未兑换卡不计入成绩，重印不占新额度。
3. 劳美目录没有任何发卡项；劳美学业来自导入，成果评分来自已确认奖状。
4. 音乐或美术三类教师卡分别更新三个目标格，不能一张卡同时累计两个教师评价格。
5. 管理员导入五项体测值，任课教师导入准确学业分项；不导入六育总分，也不把一门总成绩复制给所有分项。
6. 每类 1 篇可一次提交全月；每类 3 篇同样可提交；缺少某类或某类超过 3 篇时说明具体问题。只粘贴文本也能完成。
7. 读类当月 80、90、100 分，月分为 90；另一个月只有一篇 80 分，该类两月期末分为 85、按建议规则显示三星，不因篇数不等而变权重。
8. 某篇评分失败，已上传全文和其他篇分数保留；只重试失败项。该月未完整评分前不把失败当零分。
9. 无奖状的学生仍能完成报告，成果显示暂无记录；待审核、撤回、匹配冲突分别有状态，不伪造等级。
10. 自评与卡生成他评独立保存，多名教师修改不同字段不会覆盖对方；任何相关更正会使旧确认失效。
11. 全校有一份必需数据不齐时不激活新批次；准备中失败、重试或评分回写不产生部分新报告提前可见。
12. 手机竖屏、HTML 打印均显示完整六板块；以用户最新 PDF 为明细基准，长文本不能静默截断；发布后源数据变化不改变已打印归档。

### 本稿作出的建议，供整体评审

- 核心六表：账号、学期、任教、宽表、统一来源、报告归档。
- 卡折星使用项目达标分，示例默认 T＝10，教师先确认采集完成再评价真实零分。
- 故事每类月内取均分，学期按月份等权，建议 60/85 分为两星/三星界线。
- 文本评分量规初版四维各 25 分，TXT 为首期上传格式；具体评分服务由实施人员选择并验证。
- 奖状成果按学校配置映射取最高档，无奖状不阻断发布，不擅自补造级别映射。
- 每次发布全校统一可见，班主任可批量确认齐全报告；家长寄语建议不作阻断。
