# 按学科自动配卡与审核归类：开发交接规格

日期：2026-10-26，学校默认时区 Asia/Shanghai。

本文件是 wayfinder 最后一张决策票的交接资产，记录角色、数据、接口和验收边界；不是已经完成的代码或可打印文件。业务选择的原始回答与完整理由保存在各决策票中，本文件仅引用其摘要。完整文字尚未由用户逐条审批，技术默认与首版范围均明确标为 Codex 的选择。

入口：[改造地图](../../wayfinder/subject-card-issuance/map.md)；本文件所属决策：[三个角色的最终操作与接口边界怎样收敛](../../wayfinder/subject-card-issuance/issues/WF-CARDS-07.md)。

## 1. 意图与已确认的业务输入

让管理员维护学科策略后，系统自动给教师生成月度实体卡。教师只负责线下把卡交给学生；学生扫码申请，教师审核时才确定奖励子类，减少逐教师配额与手工制卡操作。

| 已确认的业务选择摘要 | 唯一决策来源 |
| --- | --- |
| 每位教师每月一份，管理员指定主教学科，不按兼教学科数量累加 | [教师任教学科与领卡资格](../../wayfinder/subject-card-issuance/issues/WF-CARDS-01.md) |
| 学科策略填写月总张数和六育比例，系统推算整数张数 | [学科数量与比例](../../wayfinder/subject-card-issuance/issues/WF-CARDS-02.md) |
| 每月 1 日生成当月；首次启用及月中新教师补整份；已有卡时策略修改下月生效 | [月度生成与补发](../../wayfinder/subject-card-issuance/issues/WF-CARDS-03.md) |
| 待审申请截止取次月 3 日 23:59 与学期审核截止日中较早者 | [审核期限](../../wayfinder/subject-card-issuance/issues/WF-CARDS-03.md) |
| 审核时选择两层子类，通过后每张固定加 1 分；印刷不含子类 | [审核归类与加分](../../wayfinder/subject-card-issuance/issues/WF-CARDS-04.md) |
| 管理员集中打印分发，采用按教师分组、含二维码的 PDF | [集中打印](../../wayfinder/subject-card-issuance/issues/WF-CARDS-05.md) |
| 现有卡片仅用于测试，无正式流转旧卡需要兼容 | [测试卡过渡](../../wayfinder/subject-card-issuance/issues/WF-CARDS-06.md) |
| 无有效学期覆盖的月份暂停发卡 | [月份范围与角色整合](../../wayfinder/subject-card-issuance/issues/WF-CARDS-07.md) |

下面各节是 Codex 为交接选定的实现默认，供后续实施和用户审阅。数据库字段可按现有规范调整命名，语义与约束不能遗漏。

## 2. 三个角色的操作路径

### 管理员

沿用现有 `/admin/cards` 的“评价卡管理”入口，内部调整为三个页签：

1. **教师学科**：列出现有教师、任教班级、任教学科、主教学科及数据异常。管理员选择任教学科并从中指定一个主教学科。只维护发卡需要的教师学科信息，不扩展成完整的人事或账号创建系统。
2. **学科发卡策略**：维护学科代码、名称、启用状态、月总张数和六育比例；保存前显示计算张数及生效月份。删除“配置教师月配额”和“批量制卡”，不提供逐教师修改月额度的替代入口。
3. **月度分配与打印**：按月查看教师分配快照、六育数量、使用状态、生成异常与 PDF 状态；领取集中打印文件。页面明确显示“已就绪／待处理”的教师数量，打印动作只读取既有卡片。

在现有“学期与校历”中维护日期、启用状态与新增的审核截止时间。`is_current` 继续作为默认展示选择，不单独决定发卡资格。

### 教师

- `/admin/cards` 在教师角色下继续显示“我的评价卡”，只能查本人月度分配与核销情况，无学科策略、配额设置或打印凭证下载能力。
- 线下把卡交给学生，不增加提前录入学生或登记每次发卡的步骤。
- `/teacher/claims` 按卡片方向筛选两层子类，完整选择后通过审核；可填写表现说明。驳回沿用现有作废行为。
- 当前主教学科变更后，已有当月分配仍显示其原学科快照，并提示下月采用新的主教学科。

### 学生

扫描二维码 → 登录学生账号 → 预览卡片方向、教师、月份和有效期 → 主动确认申领 → 等待审核 → 查看分类与积分。扫码或登录本身不自动发起申领，也不提前加分。

## 3. 学科与策略的数据关系

| 逻辑实体 | 必需数据与约束 |
| --- | --- |
| 学科字典 | `school_id`、稳定 `subject_code`、名称、启用状态；同校代码唯一。显示名称修改不影响策略关联 |
| 教师任教学科关系 | 同校 `teacher_id + subject_id` 唯一，支持多学科。新增学科关系不增加卡片份数 |
| 教师主教学科 | 在现有 `users` 增加可空 `primary_subject_id`，须属于本人任教学科关系。只影响未分配的当前月或未来月份，已有批次不回写 |
| 学科策略版本 | 学科、版本、`effective_month`、启用状态、月总张数、六方向比例、创建人及时间。历史版本不可就地改写 |
| 教师月分配批次 | 学校、教师、月份、归属学期、主教学科与名称快照、策略版本、总量、六育整数数量、分类版本、生成状态及异常摘要 |

策略比例以百分比输入，初版支持两位小数，内部可转换为万分比整数，六方向合计 `10000`，避免浮点误差。整数分配方法按[学科数量与比例](../../wayfinder/subject-card-issuance/issues/WF-CARDS-02.md)执行。六个字段完整显示；零比例不获分配。月总量为 0 不生成卡片，也不创建已经占用一份额度的分配批次。

初版沿用现有分类版本 `V1`，在分配批次保存 `category_version=V1`；审核时只选择该版本的有效父子链。分类版本迁移属于后续明确范围，不自动混用多个版本。

语文、数学、物理、美术的 100 张及 70/20/10 示例可作为编辑表单模板，保存前不成为已启用策略；不替其他学科推定默认分布。学科代码可与成绩导入的既有代码一致，但本轮不改写成绩表的学科数据。

**版本生效的确定规则：**只要该学科当月尚无任何正式分配批次，首次启用、已有策略修改、总量从 0 改为正数、补齐配置后修改或重新启用，都允许当前月生效并自动检查补发资格；该学科当月已有分配批次后，修改策略或启停状态形成下月生效的新版本。已经建立但生成失败／未完成的批次也固定当月版本，不能因卡片尚未全部生成而覆盖快照；总量 0 的跳过记录不算正式批次。相同生效月再次编辑形成更新的版本，不就地改写旧版本；尚未分配者采用该生效月最新有效版本，已有批次继续使用原快照。未分配的月中新教师仍使用该学科当前月有效版本。策略保存和首个分配批次的建立必须使用同一学科范围的数据库锁，避免并发把同月教师分到不同版本。这是 Codex 对边界情况的补充默认。

教师主教学科存当前维护值，历史依据由月分配快照保留；初版不建立另一套按学期手工维护的教师月配额。任教班级继续保留现有业务用途，不用于反推学科或卡量。

## 4. 校历、学期归属与截止时间

以下为实现默认，补足“有效学期覆盖月份”的可操作含义：

- 自动任务按学校时区读取当前自然月。学校只要维护过专属校历，就仅使用本校记录，不因某月未覆盖或记录停用而回退到全局基线；仅在该校完全没有专属校历记录时使用全局基线。随后选择启用、日期范围与本月相交的学期，不能混合使用两套校历。
- 没有任何匹配学期时暂停本月生成，并显示无学期覆盖原因；不回退到 `term_id=1`。本月只要有教学日期，即按一整个月的学科策略配卡，不按教学天数折算。
- 同一学校月份如果有多个本校有效学期覆盖，标记校历归属冲突，暂停尚未建立的批次，要求管理员在校历中消除歧义；不能用 `LIMIT 1` 或 `is_current` 随机决定。不新增一套自动拆分月额度的规则。
- 归属学期在首个分配批次中固化，月中改变学期配置不重新发一份。正常校历应避免一个月份分属两套发卡学期；异常配置的处置属于管理员配置修正。
- 在 `academic_year` 增加 `review_deadline_at`，现表目前缺少该字段。新建学期默认取 `end_date` 当日结束时，管理员可调整为不早于该时点的审核截止；接口和界面均展示。兼容迁移时也用原学期结束日初始化，并提示管理员核对。
- 新卡 `valid_from` 为本月开始与学期开始中较晚者，`valid_until` 为月末与学期审核截止中较早者。若当前时刻已超过该卡可申领／审核的时间窗口，则不生成已经无法使用的补发卡，记录已截止原因。
- 审核期限为 `min(次月3日23:59, 学期审核截止)`。实现时将界面分钟视为该分钟结束，统一使用学校时区并在边界测试中固定这一语义。
- 已有待审申请按其归属学期和截止时间审核，不因管理员把默认展示学期切到下一学期而失踪。学期停止新发卡不自动提前撤销尚在有效审核期的旧申请。
- 审核截止或校历修改不得静默延长已完成月份或已入账结果；已有批次保留截止快照。若管理员缩短当前学期截止，现有卡片以“原快照与新截止中较早者”限制，界面同步显示生效结果；延长只对尚未建立的批次生效。该保守规则为 Codex 的默认，不新增追溯改账功能。

## 5. 卡片、申领与打印产物

| 对象 | 改造边界 |
| --- | --- |
| `reward_card` | 新增分配批次引用、独立 `dimension_code`、批次内稳定序号和受控加密凭证材料；保留令牌哈希；旧 `category_id` 允许为空，新正式卡不靠它存审核分类 |
| `card_claim` | 通过时保存所选叶子指标、分类版本及审核说明；未通过前指标可空。通过后的数据与 `score_record`、审计信息一致 |
| `score_record` | 继续一申请一条正向卡片积分，`delta=1`；维度取卡片方向，叶子指标取本次审核选择。已有冲销机制不在此轮重做 |
| 打印产物 | 关联学校、月份、已有分配批次集合、版式版本、生成状态、私有文件位置及校验摘要。保留按教师分组的打印清单快照 |
| 生成异常 | 可查询学校、月份、教师、原因、最近尝试时间和恢复结果；可独立于有效批次存在，以记录缺少学科／策略／学期的情况 |

分配批次唯一约束为 `学校＋教师＋月份`，不把学期加入唯一键以放开第二份额度。卡片用 `批次＋序号` 唯一，令牌哈希唯一。任务重试按稳定序号恢复缺失项，不能把已使用、待审或作废卡从已生成量中扣除后重新补齐。

生成任务先固定分配快照，再为稳定卡位生成凭证。哈希与加密凭证材料在同一数据库事务内保存，随后异步渲染 PDF；文件失败不重新制卡。密钥持久配置，文件位于非公开静态目录，下载只允许本校管理员。

管理员导出月度 PDF 时，固定当时已就绪的教师批次清单，生成带清单标识的打印包。分组页列教师、月份及方向数量，卡面只列六育方向、二维码、卡号和月份等必要信息，不列两层子类。

若还有未就绪教师，下载前明确展示数量和原因，PDF 封面也保留未就绪清单；不能把部分结果伪装成全校全部完成。以后补齐新教师可形成更新的打印包，老批次卡号与凭证保持相同；重印指定的旧打印包仍得到原清单。

首版支持同卡重印，不增加遗失换码或跨教师转卡功能。停用教师的未扫码卡保留原归属及有效期，由管理员线下回收；已扫码待审申请可由本校管理员处理。故事方向沿用当前字典，卡片 `+1` 不改写月度故事正式成绩或综合评分算法。

## 6. 自动任务与状态一致性

自动任务在服务启动、每月 1 日及当前月的恢复轮询中检查未建立／未完成的分配。教师学科、策略或校历保存后触发一次当前月检查，不要求管理员手动制卡。轮询间隔及分块大小由实现者按当前部署选定，避免在一次 HTTP 保存请求中同步渲染全校 PDF。

- 正常在职且主教学科、策略、学期齐全的教师建立一份快照；缺失条件记录异常，修复后自动恢复。
- 首次启用或新教师补发只针对当前月，不补造已经结束月份的卡片。月中修改策略遵循版本生效规则，不移动已经建立的快照。
- 总张数为 0 或策略尚未生效时记录跳过原因，不创建固定卡量的正式分配。
- 分配生成状态与 PDF 状态独立：卡片已生成但 PDF 失败时，仅重试文件任务。对凭证材料或文件缺失应显示可重试的失败，不能声称打印已经就绪。
- 卡片状态保持 `UNUSED → PENDING → USED/VOID`；`UNUSED` 超时转 `EXPIRED`；待审超过最终审核期限时申领与卡片结束为 `EXPIRED`，不加分。已使用终态不被过期任务改写。
- 修正现过期任务使用 `ACTIVE` 的错误；正式枚举中没有该卡片状态。申领和审批接口自身检查时间及状态，不能依靠轮询及时运行才阻止过期使用。
- 审批在事务内锁定申领与对应卡片，校验学校、账号、卡片归属、完整分类及期限；通过时唯一写入 `+1`。并发审批、重放、过期任务竞争均不得产生第二条正向积分。

## 7. API 契约边界

沿用 `/api/v1` 前缀与 `{code,message,data}` 响应结构；下表省略前缀。这是拟实施契约，当前路由尚未具备这些新功能。

| 接口 | 角色与含义 |
| --- | --- |
| `GET/POST /admin/card-subjects`，`PUT /admin/card-subjects/:id` | 管理员维护同校学科字典，稳定代码不随改名变化 |
| `GET /admin/card-teachers` | 管理员查看教师学科、主学科和异常 |
| `PUT /admin/card-teachers/:id/subjects` | 提交 `{subjectIds, primarySubjectId}`；同校教师、主学科须在任教学科集合内；保存后自动检查补发资格 |
| `GET /admin/subject-card-policies` | 管理员查询策略、当前月及下月版本和张数预览 |
| `PUT /admin/subject-card-policies/:subjectId` | 提交 `{monthlyTotal, ratios:{D,Z,T,M,L,G}, enabled}`；返回版本、生效月份及派生张数；不接受任意教师额度 |
| `GET /card-allocations?monthKey=` | 管理员查本校，教师只查本人。管理员可加教师筛选；教师不能借参数查看他人 |
| `GET /admin/card-generation-issues?monthKey=` | 管理员查看缺失条件、失败及恢复结果 |
| `POST /admin/card-print-packs` | `{monthKey}`，只对既有就绪批次建立打印清单；不创建任何分配或卡片。返回打印包 ID、状态及未就绪摘要 |
| `GET /admin/card-print-packs/:id` | 本校管理员查询打印包状态与固定清单 |
| `GET /admin/card-print-packs/:id/download` | 本校管理员下载就绪的 PDF；未就绪返回明确状态，不能返回空 PDF 冒充完成 |
| `GET /cards` | 保留管理员／教师查询，按学校及本人范围限制；返回卡片方向，不暴露令牌、密文或哈希 |
| `POST /student/cards/preview` | 学生提交 `{token}`，返回方向、教师、月份、可申领区间、审核期限、固定 1 分及尚待确定的分类 |
| `POST /student/card-claims` | 学生提交 `{token,requestKey}`；只创建待审申领，维持一卡一次有效链路 |
| `GET /teacher/card-claims` | 所属教师或同校管理员查看；允许分类为空的待审记录，返回方向与 `categoryVersion` |
| `POST /teacher/card-claims/:id/decision` | 通过需 `{decision:'APPROVE',categoryId,requestKey,remark?}`；`categoryId` 为第二层子类叶子。驳回使用 `decision:'REJECT'` 和可选原因，不要求分类 |
| `GET /evaluation-categories?version=V1&dimensionCode=Z` | 为卡片审核获取指定版本与方向的树，不能把残缺或跨版本父子链当成有效叶子 |
| 现有学期查询／保存接口 | 增加 `reviewDeadlineAt`，保留现有角色校验；日期变更结果与批次快照规则一致 |

卡片预览改用 POST，将凭证放在请求体中；当前 GET 预览与旧配额写入、手动制卡接口在所有前端调用更新后退役，返回 `410` 和明确的迁移提示。旧配额列表接口也改由新的只读分配查询替代。现服务还将同一路由挂载在 `/api` 别名前缀，退役及权限约束必须同时覆盖，避免旧别名仍可制卡。

保留已有 `401/403/409/422` 与卡片业务错误码：校验失败清楚指出字段；越校／越权返回 `403`；重复申领、过期或已处理按卡片状态返回；PDF 未就绪返回 `409` 并可查询状态。策略保存成功但生成被配置问题阻塞时，返回已保存的配置与生成摘要，不把保存伪报为失败，也不伪报卡片已完成。

卡片审核以卡片归属教师和同校学生为范围，不从教师 `classes` 推定学科，也不新增“学生必须在该教师当前任教班级”这一用户未要求的限制；原无卡直评等功能的班级授权保持自身规则。

## 8. 二维码进入与登录恢复

当前前端使用 `HashRouter`。二维码采用部署配置的公开前端基础地址，定位到 `#/student/claim?token=<encoded-token>`，不能把普通路径路由当作现有入口。

未登录时，现有认证守卫会在领取页挂载前跳转。因此须在认证守卫／路由入口先捕获并暂存本次卡片凭证和内部目标页面，不能仅依靠领取页的挂载逻辑。登录成功后恢复到领取页；恢复目标限定为本应用内部领取路由。凭证仅作该次领取使用，捕获后可从地址栏移除；申领完成、明确失效或用户取消后清理临时状态。使用学生账号确认，不因登录恢复而自动提交。

非学生账号打开时提示使用学生账号，不创建申请。卡片凭证不写入普通请求日志；当前请求日志会记录 `originalUrl`，因此改用 POST 预览并清理旧 GET 调用，同时在两处 URL 日志输出中遮蔽卡片凭证参数，避免退役的 GET 请求仍暴露凭证。普通查询响应只返回展示信息。

## 9. 测试数据、迁移与旧功能退役

依据[测试卡过渡](../../wayfinder/subject-card-issuance/issues/WF-CARDS-06.md)，不存在必须保留原义的正式流转旧卡。实施迁移保留备份，旧测试卡及关联记录作标记或归档，与正式批次隔离；不自动转成正式卡，不重写旧积分、不复用旧令牌，也不擅自清空其他数据。

除更新全量建表 SQL，还需提供对现有数据库可重复执行的增量迁移。当前初始化器以 `CREATE TABLE IF NOT EXISTS` 为主，不能据此认为已有表会获得新增字段与约束。

更新前端卡管理、教师审核、学生申领、URL 常量、仪表盘摘要和所有旧配额查询调用；移除旧表单及写接口。现有测试中证明旧手工制卡／配额“成功”的断言，应改为证明它们退役，新流程通过；本次不保留仅为让旧测试继续成功的旧业务入口。

## 10. 验收场景与实施自由度

| 场景 | 应观察到的结果 |
| --- | --- |
| 语文、数学、物理及美术模板分别保存后启用 | 按各自主学科策略分配；示例 100 张得到对应 70/20/10，不跨学科强制套模板 |
| 同一教师兼教语文与美术 | 只获一份，采用管理员指定主学科；月中改主学科不再多发 |
| 总数 101，智 70%／德 20%／劳 10% | 张数为智 71、德 20、劳 10；零比例方向为 0 |
| 总量 0、负数、比例负数或合计不为 100% | 0 不发卡；非法数值明确拒绝保存 |
| 正常月初、首次月中启用、月中新教师／补齐主学科 | 按已确认规则自动生成整份；已生成者不重复领取 |
| 当前月策略修改后新增教师 | 已有批次不变，新教师用当月有效旧版本；下月采用新版本 |
| 无当月批次时重启策略、修改策略或将 0 张改为正数 | 新版本当月生效，按补齐后的有效条件检查补发；失败但已建立的批次不得被改写 |
| 无学期覆盖月份、缺学科、缺策略、停用教师 | 不生成错误或默认卡片，管理员能看到原因；修复可恢复的条件后自动补发 |
| 同月多个发卡学期、学校专属与全局基线并存 | 不随机分配；冲突可解释，专属与基线不混算 |
| 服务错过月初、卡片生成中断、多实例并发、PDF 失败 | 当月可恢复；不补造历史月份，不重复卡位、不重发已使用卡；PDF 可重试 |
| 生成后服务重启，再登录下载／重印 | 得到同一批卡的有效二维码；打印清单固定，不增加卡量 |
| 部分教师就绪，另有异常教师 | 界面和 PDF 清楚说明未就绪范围，不冒充全校已齐 |
| 未登录学生扫码、登录后返回 | 回到同一卡的预览；确认前不申领、不加分 |
| 新卡尚无任何叶子分类 | 可预览、申领并进入待审列表，不因内连接指标而丢失 |
| 审核缺少叶子、跨方向、父子不匹配、版本不符或指标停用 | 后端拒绝；不能靠客户端绕过，不能默认任意指标 |
| 正常审核、重放、并发与过期竞争 | 只有一次固定 `+1`，分类与卡片方向一致，卡片和申领终态一致 |
| 月末前申领、次月 3 日边界、学期更早截止 | 截止前可审，超过较早截止不得入账；未扫码卡不能借审核宽限期跨月新申领 |
| 教师伪造他人卡、跨校访问、停用账号、管理员接管 | 学校与归属校验生效；管理员仅处理本校范围 |
| 旧测试令牌、旧制卡接口及 `/api` 别名 | 不产生正式积分或新卡；旧测试记录不占正式份额 |
| 成绩、荣誉、故事与报告 | 维持原有算法与数据；只核对本次卡片链路的必要衔接，不扩大成其他模块重构 |

实现者可决定组件拆分、数据库字段的规范化命名、轮询间隔、生成分块大小、PDF 渲染库、A4 具体排版和索引的性能优化。这些选择不得改变业务规则、每月一份的唯一性、版本生效、有效期、学校权限或打印凭证的可恢复性。

后续实施应先核对当前工作区其他未提交修改，使用隔离方式安排代码工作；本规划不提交或覆盖其他任务的成果。
