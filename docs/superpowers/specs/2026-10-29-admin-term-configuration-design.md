# 管理员学期配置：版面与功能流程

日期：2026-10-29。状态：设计及可点击原型，待用户评审；不修改正式业务代码或数据库。

关联：[三角色总设计](2026-10-28-three-role-ux-and-cleanup-design.md)、[管理员三个数据菜单](2026-10-29-admin-three-menus-design.md)、[实施计划](../plans/2026-10-29-role-ux-and-report-management.md)。

## 1. 目标与范围

管理员在开学时核对学期、分配教师职责，在学期中少量调整规则和报到日期，能够预见改动对教师权限、成绩和报告确认的影响。延续现有六表和 Express/React，不建立配置中心、工作流引擎或额外配置表。

现有 Configuration 把卡阈值、逗号分隔的月份、报到日期和教师ID输入堆在一起。新设计用可理解的中文名称、月份选择、班级职责表、同页差异预览代替。已有管理员五个主菜单保持不变，此页面内设四个页签。

以下为本次设计取舍：只配置**已有学期**，学年、学期、起止日期、当前学期标记和模板版本只读；不在此新增开学建档、切换全校当前学期、复制上学期名单或修改学籍。collectionDeadline实际参与卡生成、直评与卡有效期，页面只读展示实际截止及作用范围；它不是全来源硬截止，不包装成已实现的统一收件截止。学籍、健康原值与额度分别回到三个独立菜单。

本轮建议每班最多一名有效班主任，任课学科允许多名教师协同；现有数据库未强制班主任唯一，正式实现须补服务端校验。若学校历史上配置多名，显示冲突并要求明确保留者，不自动猜选。此为设计建议，不表述成用户已确认的校规。

## 2. 页面结构与视觉

保留深绿侧栏与米白工作区，页面标题“学期配置”，副标题“先明确职责，再统一评价口径”。右上选择已有学期；显示当前配置版本和发布状态。主体先有一条简洁的配置摘要：已有班级数 / 班主任缺配班级数 / 应交故事月份；不重复发布中心的大数字看板。

页签顺序为：**学期与报到 / 任教与班主任 / 评价规则 / 变更记录**。可直接切换，无上一步下一步。编辑保存在当前学期内存草稿；切页签不丢，离开菜单、换学期或退出先提示未提交内容；刷新前提示，仍不将学生资料写入浏览器持久存储。正常只读浏览不弹确认。

桌面表单两栏：左侧主输入，右侧当前效果/影响说明；任教页为班级索引 + 职责主表。手机纵向排列，页签可换行、表格局部横滚，主按钮位于文档流末尾，不遮挡软键盘。沿用总设计字号、44px点击目标、focus、错误文字和 reduced-motion；标题用既有中文衬线字体，表单用既有中文无衬线字体，不加载在线字体。深绿主动作、浅绿已配置、琥珀待处理，禁止仅用颜色表达状态。

发布状态非 IDLE（PREPARING / READY / FAILED）时，页面顶部说明“发布批次未结束，配置暂时只读”，保留查询与变更记录，禁用所有写动作并给“前往发布中心”入口；不得在此自动取消发布或解锁。已发布快照始终冻结，新配置仅影响当前草稿和未来发布。

## 3. 学期与报到

左侧“本学期信息”只读展示学校、学年、第一/第二学期、起止日期、是否当前学期。右侧“下学期报到”提供一个有明确 label 的日期选择，旁边显示报告中的“请于 X 月 X 日报到”样式；未填则明确“尚未设置”，不默认为今天。不从日期虚构开学时间、地点等字段。

保存流程：改日期 → 点击“预览日期变更” → 同页显示旧日期/新日期、影响学生数、当前已确认报告数 → “确认保存日期”。日期为真实存在的 YYYY-MM-DD，建议晚于本学期结束日，若不晚于则以字段错误阻断；未设置可先保留空值，已设置值只有显式“清空报到日期”才清空，空输入不静默删除。清空也必须预览。零变更提示“没有待保存修改”，不推进版本、不失效确认。

沿现有 updateTerm 行为，真实日期变更推进配置版本和草稿修订、使本学期已有确认失效；不改发布快照。前端必须准确展示这个影响，不能声称“只是改文字不影响确认”。在后续可证明指纹机制支持更细失效前，不另造局部确认规则。

## 4. 任教与班主任

按当前学期学生快照生成班级列表，并合并已有任教关系中的班级，防止空班历史职责消失。班级项显示年级班级、人数、班主任姓名或“尚未设置”。可按年级/班级搜索；选班后主区显示班主任和全部任教职责。停用职责折叠在“查看已停用”中，历史不删除。

任教表列：学科、教师姓名和账号、职责（任课/兼班主任）、启用状态、操作。学科采用现有13种中文名称及稳定代码（含故事），不直接暴露英文代码。教师从本校启用教师目录搜索姓名或账号，重名同时显示账号；无结果给“前往学籍与账号”，禁止自由文本造教师。无任教教师也能被搜索到，不能只从既有任教表取人。

新增/修改在主表下方同页完成：教师姓名选择 → 学科选择 → 添加到本班待保存清单。支持为当前教师勾选多个班级，或一班多项职责，但一次确认最多100项；每项显示明确班级、学科、教师，不用后台ID。重复有效关系判“已存在”并跳过，不重复插入；同一班同学科可有多名任课教师，不擅自覆盖别人。

班主任单独选择本班已有或同批新增的有效任课教师；同一教师多个学科共用班主任职责，服务端将此班该教师有效关系的 is_head_teacher 一致设置，并清除该班其他教师的标记。没有任课关系的教师先新增至少一个学科。现任班主任最后一条职责停用前，必须同批指定继任者，或明确选择“暂不设置班主任”并在预览标出发布阻断；不留隐性孤儿班主任标记。

点击“预览职责变更”展示新增、停用、班主任旧→新、影响班级/学生、将失效的本班确认数量以及立即生效的读写权限变化；无变化不提交。有已确认报告的受影响班级须明确提醒；保存只失效实际变更班级的当前确认并推进对应学生修订，保守而可解释。历史发卡、领取、奖状认定与报告快照不转移、不改操作者。现有API每次请求重新鉴权，失去职责的教师下次读写即拒绝。

确认使用一个事务批量写入，按学期锁与稳定班级/教师顺序防竞争；批次任何教师停用、修订变化或班主任冲突全部409/422不部分成功。保存成功刷新本班表与权限摘要，保留选中班级；不自动给教师额度、代教师制卡或搬移历史凭证。

## 5. 评价规则

### 5.1 可编辑：卡积分折星

每张卡/一次无卡直评1分，37类现有卡指标、劳美/故事不发卡保持不变。全学期共用一个达标分 T，输入整数2–10000；不引入每班/每教师/每指标阈值覆盖层。

旧配置若有cardTargets年级/指标覆盖，必须先在差异预览列出并明确确认统一后移除此已知旧键；不能“保留其他配置键”导致隐藏覆盖继续高于页面T。投影只读取统一后的cardTarget，其余不相关键仍保留。

阈值下方即时解释：已结算有效分 `< ceil(T/2)` 为★；`ceil(T/2) ≤ 分数 < T` 为★★；`≥ T` 为★★★。T=10时显示0–4、5–9、10及以上。提供“试算积分”输入，仅演示算法不写入学生记录。未结算显示“待结算”，不是自动给一星；明确零卡结算后0分可为一星。改变T不会改变原始卡数、无卡事件、教师额度或每卡1分。

### 5.2 可编辑：应交故事月份

依据学期起止日期列出月份复选项，显示年份，跨年不混淆。选中月份构成 requiredMonths，至少一月、去重、按年月排序，不能选学期以外月份。已有配置存在期外月份时显示待处理错误，不静默删。月度要求固定为读/听/讲各1–3篇文本，篇数不加权。已经提交故事但拟移除月份时提示该月份不再计入期末均分，原始稿件和评分留存。

读取现有均分算法并只读展示：每类当月有效文章均分 → 应交月份等权平均；缺应交月份则待完成；0–<60★、60–<85★★、85–100★★★。不能用“保存规则”触发LLM重新打分，也不提供单篇成绩修改。

### 5.3 只读：其余口径

显示当前学业等级允许值及顺序（读取 allowedGrades，缺省沿现有 A/B/C/D），不能把星级卡指标改成学业等级。显示报告模板六板块、模板版本和现有适用项摘要；不提供拖拽重排、字段开关或直接JSON编辑。

奖状沿已生效映射及教师认定流程：显示映射条数、无映射需教师人工认定并填理由；保留既有 certificateMappings 与其他未知配置键。本轮不新增映射编辑器，不把一张奖状默认折成积分。故事模型、密钥和服务地址不在此配置。

### 5.4 保存流程

修改 T/月份 → 即时校验和试算 → “预览规则变更” → 同页差异（阈值、月份旧→新）、全学期学生数、已确认数、缺故事月份影响统计 → “确认保存并重算草稿”。正式实现沿当前服务重算CARD/STORY投影，不调用LLM、不覆盖SELF/IMPORT/TEACHER/CERTIFICATE原始输入，冻结报告不动。

重算和规则提交在同一事务；失败全部回滚、保留输入，只有真实成功才更新版本。界面显示“正在保存并重算”，不虚报百分比，不先显示成功；请求超时可按同requestKey查询/重试取原结果。独立压测当前批量重算耗时，若超预算先优化既有批量查询，不为这个页面默认另建队列表。

实现时分离config_version、汇总rule_version与固定storyScoringVersion；当前旧worker将rule_version当评分版本，改T/日期可能诱发LLM重新排队，必须一并修正。纯日期/汇总更改不得修改量规或重调LLM，真实量规不一致的迟到结果仍不得回写。具体合同与回归见实施计划R1.5。

## 6. 变更记录与反馈

按时间倒序，筛选当前学期、日期、类型（报到日期/规则/任教职责）、操作者；25/50/100分页。列为时间、操作者、类型、范围、摘要、结果；详情展开旧值→新值、配置/规则版本或职责指纹、影响人数和批次号。仅存真实操作，无更改不产伪记录；不返回学生叙述、密码、卡凭证或LLM密钥。不做一键撤销，避免把历史权限和确认盲目恢复。

所有保存复用“编辑 → 差异预览 → 一次确认 → 页内真实结果”；预览后再改内容或范围使原预览失效。409保留草稿并提供重取当前值/重新预览，不自动覆盖；422定位具体字段/关系。切换页签保留独立草稿，但一次只提交一个页签的变更，不能把旧规则草稿顺带保存。

## 7. 最小技术契约与缺口

只沿 academic_year.evaluation_config、next_term_registration_date、teacher_teaching_assignment 和既有 evaluation_source_record AUDIT；不新增业务表。当前 updateTerm 无CAS且每次都增版本，saveAssignment 无班主任唯一、无批量事务及确认失效，不能只换UI就宣称满足本设计。

- `GET /admin/report-core/term-settings?termId`：本校管理员专用；返回安全基础信息、可编辑规则、版本、releaseStatus、汇总、canEdit及lockReason。`config_version/rule_version`为比较标识，不能只信前端。
- 教师目录/班级列表复用总计划读取服务；任教关系查询增加账号、enabled和稳定 assignmentFingerprint。职责指纹来自该班完整关系集合，含停用行，避免遗漏并发启停。
- `POST /admin/report-core/term-settings/preview`：`termId,section:'registration'|'rules'|'assignments',changes,expectedConfigVersion,expectedRuleVersion,expectedAssignmentFingerprint?,requestKey`。section定义精确白名单；日期只有date/clearDate，规则只有cardTarget/requiredMonths，任教只有现有代码/人员/班级/启停/班主任选择，不接受模板/适用项/任意JSON。返回`previewId,revision,diffs,impact,versions`，存AUDIT/PREVIEW；不改业务值。服务端另存受影响学生集合的指纹（按studentId排序的revision、status、confirmed_revision），日期/规则范围为全学期，任教范围为实际变更班级。
- `POST /admin/report-core/term-settings/previews/:id/commit`：`expectedRevision,requestKey`；验证本校owner、提交内容摘要、学期发布状态、配置双版本、该班职责指纹及受影响学生集合指纹。预览后学生输入或确认变化则409，保留管理员草稿，展示新影响后重新预览；不在未告知的情况下扩大确认失效人数。这是低频配置采用的保守并发策略。在同事务重校验并执行，提交后保存幂等结果与UPDATE_CONFIG/ASSIGN审计。不盲循环调用独立提交的saveAssignment。重复key不同内容409，同内容重试返回原成功。
- `GET /admin/report-core/term-settings/history?termId&type&cursor&limit`及`:id`详情：只从本校配置/职责AUDIT读取，旧缺失信息标“历史未记录”，不猜旧影响人数。
- `updateTerm`拆出同事务可调用的保存核心，保留现有调用者；现有直接PATCH/单笔assignment也加同等版本、状态和冲突防护，不能让旧接口绕过新页面校验。学生/教师调用上述管理接口403，跨校404/403且无泄露。

## 8. 验收与原型范围

1. 点击学期配置直接进入四页签，已有学期信息清楚；不再弹“配置说明”占位框。
2. 日期合法性、明确清空、无变化不保存；预览真实影响，保存失败输入保留。
3. 教师姓名/账号搜索、中文学科、按班职责表；多学科班主任一致，无第二有效班主任，停用/交接影响透明。
4. T=2/3/10的边界正确；未结算与0分结算区分；月份选择跨年、去重且校内学期范围有效。
5. 规则只重算当前CARD/STORY草稿；不调用LLM、不覆盖其他源；已发布快照不变。
6. 发布非IDLE只读；预览过时409、整批回滚、同key幂等；旧写接口不能旁路。
7. 变更记录可追溯旧新值/人员/时间，未知历史不造数据；管理员无学生正文。
8. 手机与桌面可用，键盘label/focus/错误文本可读，页面不整体横溢。

原型演示日期预览、月份/阈值试算、任教添加/班主任交接、差异确认、发布只读与变更记录，全部虚构、本页内存；刷新重置，不接正式接口，不改变实际权限或规则。正式开发接真实服务后才能称为闭环验收。

## 9. 本轮设计核验

独立 builder check 提出的“预览后学生确认变化导致影响人数不准确”已补为第7节的影响集合指纹和409重预览；复查结论为“nothing important left”。

以上是当时局部设计可实施性检查；随后[全面闭环审查](../reviews/2026-10-29-role-ux-plan-closure-review.md)发现的时间、隐藏阈值和评分版本冲突已补入设计及实施合同，不能将局部审阅结论当作完整实现或全系统保证。

浏览器已实际核对：日期22日→23日差异及示例保存、T=3且2分为两星、T=1阻断、去选故事月份、教师账号搜索、两班添加时已有关系跳过、班主任陈→李的单班影响预览、示例历史生成、发布中全部配置写控件禁用。控制台无error；桌面实测CSS宽1800、窄屏实测469均无页面横溢。工具请求390但实际最小469，不能据此声称390已验收；正式实现仍需真实390测试。临时viewport已恢复。

本轮只更新设计、静态原型及对应计划Task12B，不执行真实接口、数据库重算或源代码删除。
