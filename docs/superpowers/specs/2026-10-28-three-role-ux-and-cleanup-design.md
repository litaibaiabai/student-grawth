## 1. 目标与已确认边界

围绕“采集六类数据 → 完成学生六育明细 → 班主任确认 → 全校统一发布”优化已有系统。学生与家长协助者少找入口、少重复填；教师按任教班级连续处理；管理员能看清学校离发布还差什么。

用户已基本认可三角色可点击方案，并明确补充：进入“给自己点星星”后，必须完整承接《六育评价明细》的自评内容，重新设计成简洁、清爽、有卡通色彩的表单。四步分组、按钮细节、色值与技术组织为本方案建议，尚非用户逐项确认。

保留现有 React 18 + Vite + Express + MySQL、六张核心业务表、六种数据来源及已有权限/修订/幂等/发布逻辑。不引入通用表单引擎、可视化低代码、微服务或新业务表。卡片每张1分，劳美不发卡，音乐美术各有三个独立教师发卡方向；本轮不调整换星算法。

报告正文以 `/Users/quanta/Downloads/六育评价明细.pdf` 及现行渲染器为基准，保留六板块、合并表头、自评他评分列、109个呈现位置、A4横向双面与手机阅读。报告封面/正文不套学生卡通主题。原需求“74项”是早期统计；当前已对照PDF细分为97个固定字段、两个重复特长集合与109个呈现位置，不能按74项删除现有字段。

本轮不新增积分商城、排名、微信小程序入口合并、Word/Excel报告导出，也不新建监护人角色。家长协助使用学生账号，家长寄语单独标注可选。钉钉扫码链接登录延续未来接入边界，本轮不将未实现的钉钉单点登录或相机扫码能力当作已有功能。

交付物包括本设计、可点击静态示意、字段映射、组件规范、接口补齐清单和清理方案。设计确认后另出开发计划，再执行产品改造与删除；当前仅制作可丢弃原型。

## 3. 角色场景、导航与页面

### 3.1 学生 / 家长协助

高频场景：扫码领卡、上传奖状；每月一次提交读/听/讲文本各1–3篇；期末填写自评与自述，学校发布后阅读报告。学生只能操作自己当学期的数据。

导航统一为“首页 / 月度故事 / 我的档案”。桌面放顶栏，手机放底部三入口；底栏避让安全区和输入法。账号退出与学期切换放头像菜单，不占主任务区。进入自评是档案下的独立页面，首页也有快捷卡。

首页由上至下：学期与姓名 → 轻量云朵插画欢迎区 → “领取积分卡 / 上传奖状”两个大按钮 → 本月故事状态和继续填写 → 学期自评进度。卡片按实际状态显示，不能用固定示例数字。没有待办时显示完成反馈，不制造待办。任务卡整块可点击，图标与文字都清楚表达用途。

**领卡**：携带凭证的链接进入后自动读取卡片；未登录先登录再回到确认页。显示班级、方向和“本次+1分”，一次确认领取。手工打开首页入口时保留粘贴链接/凭证备用。已领取、过期、班级不符分别说明原因；请求超时保留凭证并允许安全重试。不在本轮承诺调用手机相机或第三方扫码SDK。

**奖状**：选择JPEG/PNG（5MB）→ 原图预览/重选 → 提交。提交后回显“已收到，等待认定”，提交后不能宣称识别已成功。处理记录按“处理中 / 需补充 / 已认定”分组，展示人读得懂的名称、日期和原因。保留失败/拒绝历史；教师才能认定。与现有后台配置一致，不将LLM未返回结果替换成默认星级。

**月度故事**：月份选择置顶，默认学校时区当月且在学期范围内；读/听/讲三个切换页签显示有效篇数。每次只编辑当前分类的一篇，篇目最多3个；“新增一篇”与“从TXT载入”是次要操作。载入文本回显后可编辑，不上传Word/音频/视频。保留UTF-8 TXT≤64KB、每篇≤20000字的现有校验，文件失败不清空原文。读、听、讲每类至少1篇才能“提交本月故事”，不足时列出缺哪一类并定位；已填内容可先保存草稿。后端仍以整月批次提交、版本控制、每类等权计分；篇数不增加权重。

切换月份前提示保存/放弃未保存内容。每月打开时按学生+学期+月份读取最新批次原文及状态，不能靠第一页100条记录推断不存在。正式提交的批次显示只读内容与处理状态；需要重提时复用现有允许的版本路径，不直接覆盖已评分原文。评分失败给出“系统暂未评完，内容已保留”，异常由有权教师处理。

**我的档案**：学期自评、奖状记录、故事历史与期末报告分组。报告未发布展示学校统一发布说明，不暴露草稿；发布后显示当前发布版本、日期和打印入口。报告详细阅读保持学校六板块与星级/等级口径。

### 3.2 教师

高频场景：课堂批量直评、配置/生成本月卡片、整班录入学业、认定奖状、处理故事异常；班主任另有寄语、结算、报告确认。

四个主导航：“工作台 / 评价录入 / 卡片管理 / 班级报告”。最后一个只在本人拥有班主任职责的班级出现。页头固定显示当前学期、班级、学科；只列有权组合，切换班级同步更新可选学科。记住最后选择，只缓存无敏感性的学期/班级/学科偏好；失去权限时回退到当前有效组合。

工作台：本班学生、需要我处理、本人学科录入完成度三项摘要 → 快速直评/学业录入 → 个人待办。待办按阻塞程度、最早提交时间排序，可筛奖状/故事异常/缺项；点击直接进入具体材料，不再找学生。计数由服务端全量聚合，不能由当前列表长度估算。

评价录入内部使用“快速直评 / 学业水平 / 材料认定 / 采集结算”页签，保留现有结算能力，不能藏掉零卡结算、无奖状确认等业务步骤；后端决定本人可操作范围。材料认定再按奖状/故事异常筛选，禁止非故事教师手工修改故事分。

快速直评：班级与学科自动继承 → 勾选学生 → 选择方向 → 填写必要说明 → “为N名学生各记1分”。不增加任意分数输入。允许“全选当前班级/清空”，选择人数始终可见。成功后清空所选学生，保留方向；说明可显示上次内容但不自动当作本次依据提交。失败保留选择；反向撤销必须输入依据并走原冲正接口。

学业录入：默认当前班级/学科，学生为行、适用学业分项为列；支持逐格输入、粘贴、Excel导入。分项来自当前固定映射，不允许任意新增。统一“检查数据 → 差异预览 → 确认导入”；预览显示人数、覆盖格与错误格。姓名重复时按学号/标识定位，不仅按姓名覆盖；有错误禁止确认，错误格可修复，正确内容保留。继续使用既有preview/commit协议。错误提示用中文字段名，不暴露原始SQL。

奖状认定：桌面左原图右事实/归属/认定，手机先看原图后表单；图片缩放可键盘操作。LLM结果是待核对建议，不能自动覆盖教师决定。通过/退回均注明结果；保存后处理下一份本人有权材料。体育/艺术特长由奖状认定产生稳定项目ID，自评表只为既有项目填星。劳美成果同样来自奖状，无劳美发卡入口。

故事异常：保留原文、月份、分类、失败原因与量规；只对授权故事教师显示重试/人工复核。记录依据，复用现有评分接口与来源记录。不为本轮增加新的AI供应商或假成功兜底。

卡片管理：月度额度摘要（总额/已分配/已生成/可用）→ 班级分配行（班级、学科方向、张数）→ 保存并预览 → 一次生成 → 下载。多班计划不拆成反复提交；张数合计实时校验并由后端最终检查。保存后保留计划ID与最新修订，不退出页面。生成完成显示按班PDF与班级打包ZIP；若当前后端只有ZIP，优先提供“下载全部（按班分文件）”，单班下载需要补充明确接口后才呈现。卡片列表支持班级/方向/领取状态筛选，分页，凭证默认隐藏，查看和作废延续权限与审计。

班级报告：左学生名单含就绪/缺项/确认状态，右“缺项与责任人 / 教师寄语及特长教师评价 / 报告预览”。先保存评价，重新获取报告及布局结果后再确认；确认指纹对应当前修订，任何影响数据变更使旧确认失效。不能一键跳过缺项。结算明确列出影响的班级/项目，确认后才应用；缺项不可仅以前端隐藏解决。学期寄语保留现有输入方式，本轮不新增未实现的AI寄语功能。

### 3.3 管理员

高频场景：查学校完成进度、导入学籍与体测原值、下发卡总额度；低频配置学期/教师任教/规则/报到日期，最终统一发布。

三个主导航：“发布中心 / 数据与额度 / 学期配置”。发布中心为默认页。

发布中心：总学生/确认有效/待完成摘要 → “采集完成 → 班主任确认 → 报告准备 → 全校发布”阶段条 → 班级完成表。班级行展示缺项类别、人数与负责教师，不展示健康数值、故事正文、个人自述或报告全文。管理员只能看进度和职责元数据，不能借聚合接口绕过报告权限。

点击班级可按缺项类别查学生姓名/学号及责任人；这是补录定位元数据，沿用当前管理员已有名册权限，绝不返回评价值或文本。每个缺项标注对应入口与操作角色，没有自动发送消息或代教师修改的功能。

发布动作顺序完全复用原状态机：检查 → 开始准备 → 准备进度/失败后恢复 → 所有人准备齐全 → 确认全校发布。发布确认对话框列学期、人数、范围与版本，仅一次必要确认；按钮禁用时就地给出阻塞项。发布中禁止冲突编辑，刷新页面后恢复服务端进度。取消/恢复只在原状态允许时显示，全校一次性切换可见版本，不能偷换为按班发布。具体状态及分页批量处理按当前release协议映射，不能通过前端倒计时模拟进度。

数据与额度：学籍与账号、体测数据、月度卡额度三个任务面板。体测只导入身高/体重/左视力/右视力/1分钟跳绳五原值；体测水平和过程表现仍由卡生成。管理员不重新获得六育终测分导入权限。额度按教师与月份下发，教师选项展示真实姓名与负责学科，支持搜索；首版逐教师提交可沿用现有接口，不宣传不存在的原子批量下发。

学期配置：基础信息/任教职责/评分规则/报到日期分组。任教通过教师名、中文学科、班级选择，ID由程序传递；同名教师加账号末段区分。规则修改先展示影响人数及“已确认报告将失效”提示，再调用既有服务，不增加第二套规则存储。只操作本校。

## 4. “给自己点星星”完整表单

### 4.1 总体交互

独立整页，避免把长表单塞进弹窗。顶部“返回首页 / 学期 / 已完成X项”，轻量云朵陪伴区，下方四步进度条；任一步可回看。桌面内容最大860px，手机单列。返回后再次进入恢复服务端已保存值；不重置已有星级，不默认打满星。

每行包括学生能读懂的名称、一句短提示、三组星级按钮“★ 1星 / ★★ 2星 / ★★★ 3星”。选中态同时用填色、边框和aria状态表达，不靠颜色独有。按有礼貌等项目显示原始字段语义，不把提示句作为学校新评分标准，不给1星贴负面标签。每项可以修改，支持“清除本项”还原未填；清空发送null而非0。

四步主操作位置固定：“上一步 / 先保存 / 下一步”；最后一步改为“完成自我评价”。下一步只切换分组，不自动宣称服务器已保存；允许跳过稍后补填，缺项在最终检查列出并定位。先保存提交当前修改，可只保存一部分，成功后显示保存时间；断网保留输入并重试，不以toast提前宣称成功。

“完成”复用字段保存与服务端缺项校验，不新增自评审批流、提交锁或completion表。是否完成由适用字段及既有特长值推导；允许采集期修改，是否可编辑由学期状态决定。发布冻结状态显示只读及原因。自评完成不代表整份报告已具备发布条件。

七项文字保留为独立字段，不能为简洁将其合并保存。五方面自述以五个可折叠小卡展示，逐项填写并可回看；最大收获和目标放在其后。完成进度只计算非空有效值与适用固定星级，家长寄语不进入必填分母。

体育/艺术特长只显示已认定的现有项目，不让学生新建项目、改名或填写教师星级。没有项目时说明“暂无已认定特长，无需填写”，不占分母。原PDF为体育1行、艺术2行，当前数据如有更多合法项目仍逐项显示，最终报告采用现有溢出规则；本次不静默截掉数组。奖励变更导致项目消失/新增，重新拉取按ID合并并提示，不能按数组下标覆盖。

“六育全部自评”指覆盖明细中存在的自评格与正面自述。智美/劳美/故事未设独立星级自评的指标，不新增自评值；学生不填写学业等级、健康原值、教师评价或成果说明。六育是数据覆盖边界，表单不必强行拆成六个空步骤。

### 4.3 保存、冲突与接口边界

继续使用 `GET /api/v1/report-core/evaluations/:studentId?termId=...` 和 `PATCH /api/v1/report-core/forms/:studentId`。正文只提交dirty字段、当前`expectedRevision`及按项目ID的`specialtyChanges`。保留现有requestKey重试语义；新一次主动修改用新命令，超时重试用原命令。

后端在自评视图返回适用自评字段列表、是否冻结及可编辑范围，复用现有学期配置与权限计算，不把完整学校配置或他评数据返回学生。完成度计算和缺项提示使用这一份列表；配置排除项目不计入分母。13项是系统可承载的固定全集，并非忽略学期配置强制所有年级填写。

先保存串行提交，响应成功后重新读取最新revision；读取期间禁用下一次保存，仍允许编辑。编辑发生在保存过程中时，只清除已提交且本地值仍等于提交快照的dirty字段，不清空新输入。

409冲突不丢草稿：读取最新服务端值，与进入表单基线/本次dirty做三方比较。不相交变更可合并后要求再次保存；相同字段冲突显示“学校现值 / 我的输入”供选择，不自动最后写入覆盖；特长ID变化逐项处理。切换角色、学期、离开表单时提示保存或放弃，退出后清理内存；本轮不把学生文本持久化到公共设备localStorage。

无权限/发布冻结时保留当前屏幕未保存内容供复制，显示原因；不能让强制刷新直接销毁输入。整页读屏焦点定位到错误摘要，并链接到第一项错误。

## 6. 响应式与无障碍

断点建议：<700px手机；700–1099px紧凑；≥1100px桌面。学生表单一列、最大860px；成人≥1100px侧栏216px，内容最大1440px。紧凑布局缩短侧栏；手机改水平主导航/折叠菜单，核心功能不藏在只靠hover的菜单。表格容器可以局部横向滚动，页面整体不能横溢；发布进度手机2×2，汇总可换行。

触摸目标至少44×44px，学生核心按钮48px；星级组手机占整行。输入框手机16px避免自动缩放。固定底栏加安全区，内容底部预留高度；软键盘打开时表单操作条采用正常文档流，不遮挡textarea。

键盘可完成导航、星级选择、上传、导入校验和对话框；radio支持方向键，所有可见操作有焦点环。对话框捕获焦点，Escape关闭非破坏性层，关闭后返回触发按钮。路由变更焦点到主标题，错误焦点到摘要。tablist正确关联panel，当前路由标aria-current。输入有label，图片有替代文本，装饰SVG aria-hidden。状态用aria-live，长任务不反复播报。尊重reduced-motion，装饰入场≤200ms，禁止闪烁。

浏览器打印只输出报告，不输出导航、按钮、卡通欢迎区。手机报告仍按六板块顺序阅读，完整保留所有数据和自评/他评关系，不简单把宽版缩成无法阅读的图片。

## 7. 实现组织与最小接口补齐

前端沿用`app/reportCore`，按角色组合现有业务组件。建议新增`RoleShell`、`Workspace`、`SelfEvaluation`以及少量共用的`StarPicker/StatusBadge/ConfirmDialog`，已有Materials/Teacher/Administration逐步收敛；不为每种按钮建一层抽象。tokens在一份CSS定义，角色仅覆盖少量主题变量。路由使用浏览器hash/history的轻量映射即可，不为此次导航升级引入新路由框架。

已有领卡、直评、卡计划、导入、材料、表单、结算、草稿确认与发布接口继续使用。页面重组不能以修改业务接口来绕过权限。需要补齐的只读能力如下，均查询原有六张表：

| 能力 | 最小契约/约束 |
| --- | --- |
| 工作台全量汇总 | 新增`GET /api/v1/report-core/workspace?termId&grade&classNo&subjectCode`，依登录角色派生合法范围；返回counts、带中文定位信息的分页任务、班级完成聚合及对应cursor。管理员只返回缺项元数据；教师返回本人责任待办；学生仅返回本人任务状态。不创建待办表。分页与全量计数分开，响应不带原文/健康值 |
| 教师姓名选择 | 新增管理员专用`GET /api/v1/admin/report-core/teachers?q&cursor`，仅本校启用教师{id,realName,username}，分页；现任教姓名可随assignments查询返回，不用ID当显示名 |
| 指定月草稿读取 | 扩展现有sources查询支持monthKey、sourceType、recordKind和latest；按学生权限读取最新BATCH及文章原文。若现有响应已含完整payload可复用，不能靠加载所有历史代替按月读取 |
| 自评适用范围 | 扩展现有evaluation视图增加applicableSelfFields、editable、lockReason；统一完整度计算，提交权限仍由后端原校验决定 |

任务标识复用sourceId、studentId和fieldKey，不存第二套状态。缺项责任映射采用现有subjectFor及任教/班主任职责，缺负责人标注“尚未配置”并给管理员配置入口；不能随意猜一个教师。聚合读采用批量查询和索引，避免每名学生/每格发一次前端HTTP；可复用现有readiness的服务端校验定义但需避免再新增明显N+1查询。大列表分页，统计不每次按键刷新。

错误处理统一保留http status、可读message与必要定位字段，登录过期保存当前内存草稿后提示重新登录；不得跨账号恢复。所有卡量/权限/范围/修订约束仍由后端执行。
