# 教师卡片管理：月度台账、学生流向、查询与打印设计

日期：2026-10-28。状态：待确认的详细设计；未修改正式系统。

关联：[三角色前端总设计](2026-10-28-three-role-ux-and-cleanup-design.md)。用户明确要求：同时查看教师从管理员获得的月度卡额度、学生扫码领取情况，并能追溯用在哪些学生和哪些评价方向，支持查询、过滤、导出、打印。

## 1. 页面要回答的问题

1. 我这个月获配多少张、分给哪些班和指标、已经生成多少？
2. 哪些卡被哪些学生在何时领取，记在哪个指标，还剩哪些未领？
3. 哪些记录已过期、作废或冲正，实际有效积分是多少？
4. 能否从某个统计数字一键定位明细，并按相同条件导出或打印？
5. 需要下一批卡或补打时，能否原地完成，不反复找计划？

不新增卡账户、库存、分类、统计快照、导出任务等业务表；沿用六表方案。统计查询原有来源记录，新增必要只读查询与审计动作即可。

## 2. “领卡 / 发卡 / 用卡”口径

| 页面用语 | 准确含义 | 现有依据 |
| --- | --- | --- |
| 教师获配额度 | 管理员向该教师、该月份下发的总额度 | `QUOTA.payload.quotaTotal` |
| 班级计划量 | 教师分配给班级、方向的卡数 | `QUOTA.payload.plans[].classTotal/items[]` |
| 已制卡 | 已真实生成凭证的纸卡总张数 | `record_kind=CARD`的记录数 |
| 学生已领取 | 学生扫码确认成功的卡片 | 原卡`status=USED`、`student_id`、`payload.usedAt` |
| 待领取 | 已制卡但当前仍在有效期内、尚未使用且未作废 | 原卡状态及`valid_from/valid_until`派生 |
| 未到领取期 | 尚未到`valid_from`的未用卡 | 原卡有效期派生 |
| 过期未领 | 未使用且有效期已过 | `UNUSED/EXPIRED`与有效期派生 |
| 已作废 | 未使用卡经过有权操作停用 | `status=VOID`；当前服务尚无作废动作，需要补齐 |
| 已冲正 | 已领取/已直评记录另有对应REVERSAL，原记录保留 | `original_id`关联，不能用原卡USED状态判断有效积分 |
| 无卡直评 | 教师直接记1分的评价事件，不占已制卡张数 | `record_kind=DIRECT`、`actor_id`、`created_at` |

教师“获配额度”不是学生“领取”。本轮不额外要求教师逐张登记纸卡实际交付，以减少日常操作；当前没有这项事实来源，页面不能把“已生成/已打印/待领取”叫成“已交到学生手里”。学生扫码领取是目前可核实的使用闭环。若后续需要未扫码前追溯纸卡交给谁，应另确认登记方式，不能用推断补造。

**数量校验公式**：设月度额度Q、分配计划P、已制卡G、原卡已领取U、原卡已冲正R、无卡直评D及其冲正DR：

- `0 ≤ G ≤ Q`；计划生成前`0 ≤ P ≤ Q`，正常完整生成时`G=P`。
- 剩余未制卡额度=`Q-G`。作废/过期不自动退还额度，原卡已占用发行盘；变更额度仍由管理员决定。现有计划生成后锁定，剩余不代表可直接再生成。
- 已制卡G按互斥状态分解为：待领取 + 未到领取期 + 过期未领 + 已作废 + 已领取U。
- 纸卡有效积分=`U-R`；原卡被冲正后仍算历史“已领取”，但“有效积分”为0。
- 无卡直评净积分=`D-DR`；总卡源净积分=`U-R+D-DR`，不能把额度或生成张数算作学生积分。
- 领取率=`U/G`，G为0显示“—”；另显示有效积分，避免冲正后领取率被误解释为积分。

月度统计默认为**额度所属月**（`month_key`），同一月份额度、计划、原卡互相关联。明细另有“领取日期”过滤，不将额度月份当作扫码时间。无卡直评无配额月，以学校时区的**原直评发生月**归集，在“评价记录”视图将该列称为“评价归属月”；不能将其加进纸卡数量。

**跨月冲正统一回溯原评价归属月**：10月直评+1在11月冲正，截至11月查询10月净分为0；11月的原评价月净分不另扣一次。纸卡同理归回原额度月。来源明细仍保留原+1的10月发生时间与−1的11月冲正时间，不伪造事件日期。查询以asOf为截止，未来冲正不影响历史截止快照。评价记录可另按“事件发生日期”筛选；此时结果汇总标签为“筛选事件变动合计”，不能冒称整月截至当前净分。导出同时包含归属月与实际发生时间，能解释这两种口径。

## 3. 页面布局

教师主导航仍为“卡片管理”，进入后有三个页签：**月度台账 / 使用明细 / 制卡与打印**。页头统一显示学期、教师、月份；教师本人姓名固定不可切成其他教师，管理员从本校教师中选择。月份可选单月或当学期范围，默认当月；未获配显示空状态与说明。

### 3.1 月度台账（默认页）

从上到下：

1. **范围栏**：当前学期、教师、额度月份；右侧“导出月度台账 / 打印台账”。显示“统计截至时间”，加载时保留标签不闪成0。
2. **五个核心数字**：教师获配、已制卡、学生已领取、待领取、剩余未制卡额度。剩余额度若受已生成计划锁定影响，在卡下明确标注；补充“未到领取期 / 过期未领 / 已作废 / 已冲正”，点击某数字进入对应筛选明细。各数不得由当前页25条估算。
3. **班级与方向分配表**：默认班级汇总，可展开评价方向；行列为班级、计划量、已制卡、学生已领取、待领取、失效未领、有效积分、操作。未分配额度单独在表尾标注，不硬分给任意班级。
4. **月度收支与变更记录**：管理员下发/调整额度、教师保存计划、生成卡片、打印事件。显示时间、操作者、动作、变更前后量及依据。历史上未留痕的调整显示“仅有当前额度，无历史变更明细”，不能把当前quota.created_at当成每次调整时间。
5. **直接入口**：“去分配并制卡”“查看学生领取明细”。有未生成计划时提示继续编辑；已生成计划只允许查看和原码补打，不伪装成可任意增补。

桌面五卡可一排，窄屏2列换行；手机表格转换班级卡片摘要或容器内横滚，核心数量和“查看明细”始终可达。没有要求教师在月度首页看每张卡的二维码。

### 3.2 使用明细

顶部有“纸卡流向 / 评价记录”切换。纸卡流向是一张卡一行，包含未领取卡；评价记录是一笔记分/冲正一行，包含无卡直评，二者不可混作同一张卡库存。

**纸卡查询条件**：学期、额度月份、班级、六育板块、一级分类、二级指标、状态、学生姓名/学号、卡编号、领取日期起止。六育→一级→二级级联，劳美/故事不出现在卡片指标可选集。学生条件只有在有学生归属的记录上匹配；未领取卡没有学生姓名，不应显示为“数据缺失”。高级日期条件可折叠，但当前生效筛选都以可删除标签显示。

筛选区底部“查询 / 重置”，回车执行查询；姓名输入不逐键打后端。改变上级筛选清除下级；换条件将页码重置到首屏。关闭条件标签立即执行一次查询。显示“共N张，已领取U张，有效积分E”，与表格同一个过滤条件。支持每页25/50/100，默认按生成时间倒序，允许按卡编号、领取时间排序；排序始终加id作为稳定次序。

| 明细列 | 内容 / 空状态 |
| --- | --- |
| 卡编号 | 非凭证的展示编号，如`202610-0042-0008`；唯一可查，不能据此领取 |
| 额度月份 / 所属教师 | 卡所属配额月及教师；教师本人视图可收起重复教师列 |
| 班级 | 发卡时框定的年级/班级快照 |
| 六育 / 一级 / 二级 | 如“智美少年 / 语文 / 学习兴趣”，来自固定映射 |
| 状态 | 待领取、未到期、已领取、已领取·已冲正、过期未领、已作废 |
| 领取学生 | 姓名+必要学号；未领取用“尚未领取”，不得猜测姓名 |
| 领取时间 | `usedAt`按Asia/Shanghai展示，未领用“—” |
| 有效积分 | 已领取且未冲正为1，其余0；不是期末星级 |
| 生成时间 / 有效期 | 可在行详情展开，主表少列，仍可导出 |
| 操作 | 查看详情；符合条件时原码打印/作废或冲正，禁止按显示状态越权执行 |

**卡详情侧栏**：卡所属额度/计划、发行班级、完整指标路径、状态与有效期、领取学生与时间、原卡→冲正的时间线、生成/打印审计。凭证不在默认台账或导出中出现；需要打印原卡时走有权凭证下载路径。手机详情占整页，关闭回到原过滤条件和滚动位置。

**按学生/按指标汇总**：位于使用明细内的视图切换，沿用同一组过滤器。

- 学生视图：姓名、班级、扫码领取张数、其中已冲正数、纸卡有效积分；可展开六育→一级→二级分布，点击数字回到原始卡行。
- 指标视图：六育/一级/二级、所属班级、生成张数、领取张数、领取学生数、有效积分；“领取学生数”COUNT DISTINCT，不能用卡张数代替。
- 未领取卡只进入卡/指标汇总，不挂到任意学生；无卡直评仅在选择“评价记录”时单列D与DR。

**评价记录视图**：纸卡扫码+1、教师无卡直评+1、冲正−1；显示发生时间、学生、班级、教师、完整指标、来源类型、原记录编号、可选说明、净分。原卡查询领取一次只展示一条+1，不能再将同一来源在DIRECT重复计分。正常直评说明选填，冲正说明必填。

### 3.3 制卡与打印

上方获配额度/已制卡/剩余未制卡额度及计划是否锁定；中间按班设置总张数、一级与二级分配行，合计不能超过Q。下一层仍是37个现有可发卡方向，劳美不发卡。页面保留“保存计划 → 预览生成 → 生成并下载”连续原位操作，不靠退出再打开。

生成前展示各班张数及方向摘要，一次生成全部班级；生成后输出“全部班级ZIP（每班单独PDF）”。单班PDF下载可增加专用接口，不能只提供合并PDF。每张打印卡显示教师、额度月份、发行班级、指标、卡编号和二维码，二维码仍绑定原卡凭证。

**补打不等于新增**：补打使用原凭证和原卡编号，不增加额度、不新生成来源、不再次记分；提示“旧纸卡与补打卡共用同一领取资格，只能领取一次”。默认仅打印当前仍可领取卡；已领取/过期/作废卡不再输出可领取二维码。每次打印下载留审计，打印完成事实无法由浏览器确定，记录用“已生成打印文件/请求打印”，不能声称纸张一定打印成功。

现有后端只支持每教师每月一个QUOTA且生成后计划不可改。首版保留这一约束并明显显示锁定原因。管理员追加额度后虽Q-G增加，已生成计划仍不能继续生成；UI必须提示“剩余额度未使用，当前计划已生成锁定”，不能显示可点击的“继续生成”。支持生成后的增补批次需另做计划版本/批次改造，不作为本次台账隐式扩张。

额度调减规则由本方案裁定为：**不得低于已保存计划P与已生成张数G的较大者**，不自动裁剪教师计划。未生成计划需要调减时，先让教师调整计划再由管理员调减额度。当前代码只防止Q低于G，缺少P校验；实施时在saveQuota与generateCards同一QUOTA事务锁下重新计算并检查`P ≤ Q`、`G ≤ Q`，防止“先保存80张计划，再把额度降为50张，随后仍生成80张”。并发调额/保存/生成必须一方等待后按最新值校验，越额请求不部分生成。

## 4. 导出与打印规范

### 4.1 查询结果导出

首版提供UTF-8 BOM CSV，Excel可直接打开，无需新增后端Excel依赖；此导出对象是卡台账/明细，学校报告仍只HTML/PDF打印。按钮明确“导出当前筛选的全部结果”，不默默导出当前25行。当前页与勾选卡范围打印可以另外选择，但范围必须明示。

月度台账、卡明细、学生汇总、指标汇总、评价记录分别导出当前视图的对应列。明细保留教师、月份、卡号、班级、指标路径、状态、学生、生成/领取/有效期时间、原始领取事实、冲正标记、净分和可选说明，不能只导汇总数字。导出说明区/首行附查询条件、学校时区、导出截至时间；文件名如`云美_陈老师_2026-10_卡片明细.csv`。

导出由服务端执行相同过滤/权限/排序规则，全量读取，而非浏览器只导当前缓存。单次服务端一致性快照、流式输出、连接完成后释放，不新增导出任务表。建议首版最多50000行，超过时明确要求缩小月份/班级范围，禁止截断后仍提示“完整导出”。在响应开始前验证行数及参数；客户端中断及时结束查询/事务。

文本单元格正确处理引号、逗号、换行，防止以`= + - @`开头的用户输入在表格软件中被当作公式；规则作用于文本，不改真实数值−1。卡号/学号按文本输出，避免前导零丢失。导出绝不包含明文扫码凭证、token_hash、token_ciphertext、后台SQL或其他教师私有材料。

### 4.2 台账打印

“打印台账/打印查询结果”打开HTML打印预览，A4横向、重复表头、页码、教师/学期/月份、筛选条件及汇总，行尽量不跨页；打印前可检查，浏览器保存为PDF。隐藏应用导航与操作列，不压缩成看不清的长截图。

默认当前筛选全部结果，预览列明实际行数；建议首版上限1000行，超过时提示收窄条件或导出CSV，不静默打印第一页。手机同样可保存PDF，打印布局独立于手机卡片列表。打印台账仅有元数据，不含可扫码二维码。

“打印积分卡”与“打印台账”两个按钮分开，前者是可使用的原卡凭证PDF，后者是查询记录。不能让教师误把流水纸当作积分卡。

## 5. 状态与操作

| 状态 | 可用动作 | 对数量的影响 |
| --- | --- | --- |
| 计划草稿/待生成 | 编辑、保存、预览生成 | 仅P变化，不产生学生分 |
| 可领取未用卡 | 查询、下载原码打印、带原因作废 | 生成已占额度；作废后不可领，不自动返额度 |
| 尚未到领取期 | 查询；允许生成未来月份打印文件时明确提示生效日 | 不能提前领取 |
| 过期未领 | 查询、导出、打印台账 | 0分，不提供可领取二维码 |
| 已领取 | 查询学生流向、查看详情；有当前记分权限可冲正 | 原始+1，冲正产生−1 |
| 已领取且冲正 | 查询原始记录及冲正依据 | 领取事实保留，净分0，不可重复冲正 |
| 已作废 | 查询/台账导出 | 不可恢复凭证或当成新卡再次生成 |

作废仅适用尚未领取卡，不删除来源记录。补齐`POST /api/v1/report-core/cards/:id/void`，传expectedRevision、原因、requestKey，事务锁卡，若学生已先领取返回409并刷新状态；作废先赢则领取失败。**首版仅原卡所属教师可作废，管理员没有作废/冲正权限**；管理员只调额度和查询卡元数据，不能代教师改学生积分。服务端检查角色和owner，不能靠前端显示。批量作废不是首版必需功能，避免未经定义的部分成功。

已领取卡的撤销继续用现有reverse接口与唯一original约束；权限按当前任教范围，不因拥有旧卡就获得越权给学生改分的能力。对作废/冲正进行一次有具体对象的确认，导出/打印不叠加多轮确认。

## 6. 数据结构与接口最小改动

### 6.1 存储映射（无新增业务表）

| 对象 | 已有存储 | 缺口 / 最小补齐 |
| --- | --- | --- |
| 月度获配 | QUOTA：school/term/owner/month，payload总额与计划 | 保存/调整时追加AUDIT，记录oldTotal/newTotal/change/操作者/时间，历史缺口标未知 |
| 原卡 | CARD：parent_id=quota，owner、month、target、ordinal、有效期；payload班级/方向；USED后关联学生与usedAt | 查询补生成时间、名称及派生状态；不复制二维码到新表 |
| 无卡直评 | DIRECT：actor_id、student_id、target_key、delta=1、created_at | 说明改选填；不消耗QUOTA |
| 冲正 | REVERSAL：original_id、delta=−1及依据 | 查询join，分别归属原卡/直评，不改写原事实 |
| 学生名称与班级 | 原卡payload发行班级、当学期student_term_evaluation姓名/学号相关快照；必要时users补当前名称 | 主查历史快照，查不到用“归属学生#标识”，不丢弃历史记录、不臆造转班前名称 |
| 打印/生成动作留痕 | AUDIT，source_type=NULL；payload action/cardIds或quotaId、范围、操作者 | 按现有CHECK允许类型写入，不引入未知ISSUE/PRINT record_kind |

AUDIT不参与积分投影或卡张数；QUOTA是当前额度真值，AUDIT只用于变更追溯，不再建一套余额账。现有唯一教师/月额度、幂等与加锁约束保持。

### 6.2 查询接口

新增在现有reportCoreFeatures路由和服务中按职责组织的只读能力，不搭建独立报表服务：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/report-core/card-ledger/summary` | 全量统计数字、班级/指标分配和当前额度信息 |
| `GET /api/v1/report-core/card-ledger/cards` | 纸卡分页详情与同过滤总数/聚合 |
| `GET /api/v1/report-core/card-ledger/usage?groupBy=event/student/indicator` | 评价事件或学生/指标流向，明确sourceMode=paper/direct/all |
| `GET /api/v1/report-core/card-ledger/cards/:id` | 允许范围内的原卡详情及冲正/打印轨迹，默认无凭证 |
| `GET /api/v1/report-core/card-ledger/audits` | 月度额度/计划/生成/打印变更记录，分页 |
| `GET /api/v1/report-core/card-ledger/export?view=...` | 同一过滤规范的全量CSV，一致性快照 |
| `GET /api/v1/report-core/card-ledger/print?view=...` | 权限内HTML台账预览，受行数限制 |

公共参数：termId、monthFrom/monthTo、grade/classNo、section、primary、categoryCode、status、studentId或keyword、cardId、usedFrom/usedTo、eventFrom/eventTo、sort/order、cursor/limit（分页接口）。教师ID由登录者派生；管理员可传本校teacherId；所有参数服务端验证，不能直接拼接ORDER BY。纸卡主筛选按额度月，直评及关联冲正按原评价月；领取日期与事件日期是附加条件，事件列表显式返回attributionMonth、occurredAt及汇总口径；多月范围只在当前学期内。

时间一律用Asia/Shanghai学校日界线，范围开始含、结束不含，转换为数据库约定时间再比较；usedAt虽存ISO文本，应解析/索引化处理，不能用浏览器本地时区substring决定月度归属。过期状态使用响应`asOf`时刻计算，各状态数量与列表共用同一时刻。现有cards列表只返回前100条且无筛选/总数，不能拿它在前端假装全量台账。

列表返回`rows,total,summary,asOf,nextCursor`，卡编号不等于凭证。总数和分页结果同一请求快照；跨页浏览后发生领取时允许刷新更新，页面显示截至时间。CSV一次读快照，全量结果不以跨多请求抓列表代替。

打印积分卡沿用ZIP接口并补齐按班/选中可用卡范围的PDF接口；读取原凭证必须教师本人所有权校验，管理员看全校台账不自动获得所有老师可扫码凭证。打印审计应作为独立有权幂等POST动作登记，GET查询不增加来源积分或篡改状态。文件请求失败和生成成功分开记录，不能声称浏览器已完成纸张打印。

### 6.3 查询性能与权限

教师只读本人QUOTA/CARD及本人DIRECT和相关REVERSAL。卡所属教师与当前任课教师不一定相同，历史台账读取按记录所有权，学生详情只暴露该原卡关联的姓名/标识/指标元数据，不借此开放整份评价或故事材料；新记分/冲正仍校验当前任教范围。管理员可查看本校额度和卡使用元数据，不返回学生健康数值、自述或故事正文。学生不能调用教师台账接口。

先复用`idx_source_owner_month`、`idx_source_student_target`及冲正唯一索引。全量聚合用分组/关联批量查询，禁止一张卡一次HTTP或每行再次取学生。需要稳定过滤大量生成/领取日期时，在同一来源表上按执行计划添加最少的复合索引或生成列（例如usedAt的可索引映射）；不得为了统计再增多张维度/统计表。索引与schema契约同步更新，先用典型月度与全年数据EXPLAIN验证。

## 7. 验收清单

1. 教师同时看见本人获配额度与学生扫码领取；新教师/新月份无数据时不展示虚构数字。
2. 每张已领卡能定位到学生、发行班级、额度月、完整指标、生成/领取时间；未领卡不虚构学生。
3. 换月/班级/指标/学生/状态后，统计、明细、CSV、台账打印使用同一过滤规则；第101条仍可查且计数正确。
4. 37指标映射无新增劳美/故事卡；同名指标在不同学科不会混淆。
5. 跨月查看区分额度月与领取日期；0卡领取率显示“—”；冲正前后原始领取数量不变、净分减1，幂等重试不重复。
6. 作废/扫码竞争只允许一方成功；作废/过期不恢复额度；无卡直评不占纸卡总量。
7. 查询、CSV和打印禁止跨教师/跨校读取，导出无明文token/密文token；CSV安全处理特殊文本与前导零。
8. 补打使用原码不产生新卡或新积分，已领/失效码不作为可领卡打印；ZIP按班分PDF，中文字体有效。
9. 手机可以筛选、看学生流向、打开详情并导出/预览；表格内部可滚动，页面不横向溢出。
10. 教师直评仍为单页，说明空值可通过真实后端；本文件不把原型内存操作当作已实现功能。

原型中台账数据为虚构，导出和台账打印可演示本地结果但必须标明“示例数据”；真实统计/权限/审计与文件服务需在设计确认后的实施计划中落地。
