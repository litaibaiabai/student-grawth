# 六育系统改造方案（评审草案）

日期：2026-10-27。状态：**已核对仓库的方案建议，尚未批准实施**。

## 1. 改造目标与材料边界

用户本轮确认的目标是：**减少老师操作、简化积分流程、重新设计学生端、自动生成学期报告。**

- [userReq.md](../../../userReq.md)：本轮需求清单，编号 1—36 用于下文追踪；其“开发前还需要确认的事项”仍是未决问题。
- [userAdvice.md](../../../userAdvice.md)：报告与教师寄语建议稿，包含字段索引、结构与 SQL 示例。它明确声明权重、映射、权限细节等尚待确认，不能把建议当成已批准校规。
- 当前实现以控制器、服务、路由和实际表结构为依据；历史演示、README 和旧设计仅辅助理解。
- 本次没有找到材料所述的原始 Word/XLS 报告附件。82 个表头及 74 项评价字段的描述来自 userAdvice.md，尚未独立核验原附件。
- 本文的“建议”“拟新增”“默认建议”均为 Codex 提案；用户确认四个目标及同意查看草图，不等于确认全部规则。

本轮终点是可评审的改造设计和决策地图。后续经确认才能编制实施计划；本轮不改业务代码、不执行数据库迁移、不部署。

## 2. 总体判断与路径选择

建议沿用现有 **React/Vite/Ant Design + Express + MySQL**，重构业务流程与权限，在学生端采用独立布局。保留已有身份认证、学期、学科自动配卡、二维码打印、材料版本和报告快照能力。

| 路径 | 优点 | 主要问题 | 判断 |
| --- | --- | --- | --- |
| 仅修改页面、把审核按钮自动点击 | 表面改动少 | 分类尚未预设、权限未收敛、评分仍依赖终测导入 | 无法满足本轮需求 |
| 在现有模块上改造积分、评价与报告链路 | 可复用已有能力，便于逐段验证 | 需要同步修改状态机、约束、授权和评分 | **推荐** |
| 全面重写并拆分多个服务 | 可重新组织所有模块 | 迁移、运维和回归成本明显增加，目前没有必要性证据 | 不采用 |

推荐形成三个工作面：学生看成长；教师完成评价并处理异常；管理员配置规则并检查发布准备状态。

## 4. 积分卡：制卡定类，扫码入账

### 4.1 分类与自动配卡

**卡型只有德育 D 和智育 Z；评价体系仍保留六个维度。** T/M/L 由学科、活动、审核荣誉等经批准的证据形成评价；G 来自成长故事及相关指标，不能因为不再发对应卡就删除这些维度。

建议保留“每位教师每月一份、采用主教学科策略、管理员集中打印”的已有能力，但本轮只把它视为复用建议。学科发卡策略调整为月总量、D/Z 数量及各叶子子类数量；最终确认见决策地图。

每张卡生成时冻结：学校、学期、责任教师、方向、叶子指标、完整分类路径及指标版本、固定 +1 分、有效期、批次。卡面清楚显示奖励事由，便于老师发对卡。当前层级仍为方向第 1 层、一级子类第 2 层、二级子类第 3 层。

不能只配置 D/Z 比例而让程序任意挑子类。建议由管理员一次配置子类数量/比例，系统计算整数张数，所有叶子合计必须等于该方向份额；具体比例由学校确认。已有非 D/Z 配额不能静默转成 D/Z。

指标后续改名或停用不覆盖已生成卡片的分类快照。是否允许未使用旧版卡继续兑换，需要在切换方案中明确；不得临时跳到其他子类。

### 4.2 扫码与防重复

个人设备建议在已登录学生身份下扫码即兑换；不再要求教师确认或学生逐次选择分类。未登录时先登录并恢复兑换意图。若学校希望保留一次学生确认，可作为待确认交互选择，不能重新引入教师审核。

同一事务内完成：验证身份和卡片 → 锁定卡片 → 校验学校、学期、时效与可用状态 → 写兑换记录 → 写 +1 流水 → 标记卡已使用 → 写审计 → 提交。只有提交成功才播放加分成功动画。

- 新卡正常状态为 UNUSED、USED、EXPIRED、VOID；新兑换记录使用独立的“已兑换”语义。
- 同一请求重试返回同一次兑换结果；不再次累计积分。同一学生换请求重复扫显示“已经领取”；其他学生扫已用卡只显示“已使用”，不泄露领取人。
- 以卡片唯一兑换约束和行锁防并发，以稳定请求键应对超时重试；前端禁用按钮只能改善体验。
- 保留现有高熵凭证、哈希校验和受控二维码打印。不记录明文兑换令牌到普通日志。
- 纠错后卡片仍是已使用；不退回 UNUSED，防止撤销后再次领取。

**公共设备的身份是单独的前置条件。** 奖励卡只能说明“发了什么奖励”，不能证明“是哪名学生”。若一期需要公共设备，必须先选定学生身份凭证与短会话机制，再进入兑换；不得沿用上一位学生账号。设备绑定学校，限制为兑换能力，结果短时显示后清屏，不开放个人报告、健康或成绩查询。

### 4.3 教师纠错与无卡直评

推荐保留追加账本：教师界面表现为“取消/改分/改分类”，后端记录“冲销原有效项 + 必要时写替代项”，并保存原因、教师、时间和更正关联。例：原 +1 改为 +2，新增 -1 和 +2，净值为 2；改分类时旧分类 -1、新分类 +1。

现有 ±1 约束和来源枚举不足以承接改分及荣誉分，需显式迁移；不能绕开约束直接 UPDATE 原记录。替代项不复用原始 card_claim_id 的唯一入账槽位，使用更正链关联原奖励。更正锁定奖励根记录及当前有效版本，避免两位老师同时纠错；每条有效项最多冲销一次，整个更正事务可幂等重试。

建议教师可处理其获授权班级的记录，所有更正都留痕；是否限本人发卡、能否改学生归属、能否跨 D/Z、允许的分值区间和学期关闭后的处理，均由校方决定。本轮不默认为教师开放任意负分或跨班改分。

无卡直评保留批量选人、选分类、写理由及即时入账。**首版建议只开放 D/Z、每次 +1**，这是待确认建议；不能把需求中的开放问题误当成已决定。请求键应稳定绑定批次和学生，不能每次重试拼接时间/随机数造成重复加分。

## 5. 荣誉、故事、学科与六育计算

### 5.1 荣誉

学生填写赛事、届次、比赛级别、获奖等级、日期并上传证书。教师通过时选择 T/M/L；驳回必须有原因。审核通过、确认规则版本和写正式奖励在同一事务内完成。

建议复用 score_record 承接荣誉奖励，并扩展来源与分值范围；honor_record 保存认证事实、归属、规则版本和认定分，**汇总时只计账本一次**，不再另加一遍 honor_points。故事终审百分分仍留在故事来源记录，不直接当作奖励积分入账。

现有固定 1—9 分可用于核对旧数据，不能直接认定为新校规。奖项表改为管理员可维护的版本化规则，覆盖哪些级别、重复奖项如何认定、是否封顶由学校决定。去重依据应稳定包含学生、赛事届次、奖项；当前含时间尾缀的 event_key 不能可靠表达重复认定。同一审核请求、材料版本只能入账一次。已通过荣誉的撤销/归类更正也须冲销关联奖励，不能只改状态。

### 5.2 故事

保留直接输入/粘贴、草稿、提交、建议分、教师终审。首版建议使用公开可解释的规则建议分，标明规则版本、采用哪些指标及局限；篇幅不能自动证明“内容真实、成长明显”。正式成绩只取教师确认值。

需确认每月要求、可否退回重写、哪些月份纳入学期及聚合方式。**不沿用“最后一篇覆盖整学期 G”作为默认**；建议按本学期应交月份的有效终审版本聚合，权重与缺交处理待定。读/听/讲故事指标与原创月度成长故事并存，不能互相冒充。

### 5.3 成绩与评价指标导入

建立“学校 + 学期 + 教师 + 班级 + 学科”的精确任教关系。现有 users.classes 与 teacher_subject 两份独立列表不能相乘推断授权：老师教甲班语文、乙班数学，不代表也能导入甲班数学。

导入顺序为选授权班级/学科 → 上传 → 字段映射与校验 → 查看差异/错误 → 确认入库。服务器在预览和提交时均校验当前授权、学期、学科、学生、数据类型及分值范围，不信任客户端传回的 validStudents。旧单行导入与批量导入均需覆盖，防止绕过新入口。

优先按稳定学号匹配；仅姓名不能自动确认同一人。保留原始值，支持数值、等级、星级、文本，以及缺失、缺考、免测、不适用等明确状态。A/三星与百分分之间的换算必须来自学校规则，不做隐式转换。

取消管理员新增六育终测的预览和提交能力；任课教师管理自己的学科；管理员保留学籍基础资料导入和规则配置。成绩更正创建可追溯有效版本，计算和报告只选对应期间的有效版本。

### 5.4 自动六育评价

推荐把核算分为三个层次：**来源事实 → 按规则生成的六维结果 → 报告展示等级**。报告只读取核算结果与源证据，自己不记分。

| 维度 | 建议候选来源 | 必须解决的口径 |
| --- | --- | --- |
| D 德 | 德育净积分、行为习惯、道法相关评价 | 日常奖励与学期评价怎样归一、是否设目标线 |
| Z 智 | 智育净积分、授权学科评价 | 哪些学科参与，等级怎样映射，避免同项重复 |
| T 体 | 体育/体测评价、体育实践及已认定体育荣誉 | 无竞赛学生仍有可完成的常规来源，免测如何处理 |
| M 美 | 音乐/美术评价、艺术实践及已认定美育荣誉 | 非获奖学生的常规评价，科目适用年级 |
| L 劳 | 劳动/实践评价、实践证据及已认定劳育荣誉 | 实践由谁确认，哪些记录参与计算 |
| G 故事 | 本学期终审故事、读听讲指标 | 月份范围、聚合方式与缺交处理 |

这里只规定引擎能力，不规定校规数值。每维支持：来源过滤、有效版本、归一化、来源权重、目标线/封顶、状态、等级阈值及证据引用。记作 `维度结果 = F(有效来源, 该学期已批准规则)`，具体 F 和阈值必须由学校确认后才能启用。

**避免重复计分：**既然日常积分与荣誉已用于形成维度，就不能再无条件沿用“六维 80% + 同一过程 15% + 同一荣誉 5%”。新学期建议以六维等级与证据为主；是否保留综合总分、六维间怎样合成另行确认。历史 80/15/5 结果按原版本保留。

缺失规则：空值不等于 0；确认完成采集后“没有奖励/没有荣誉”可以是有效零次，不能要求每名学生都获奖才能发布。未配置规则、常规必评未完成、已确认零值、免测与本年级不适用分别处理。缺项不偷偷补零，免测也不偷偷重分配权重，具体策略由规则定义。

## 6. 权限收敛

建议把班主任视为教师的班级职责，保留 teacher 主角色，并增加按学期的班主任任命。班主任需要哪些汇总证据权限必须显式授予，不能让任课教师默认读取全部个人报告。

| 能力 | 学生 | 任课教师 | 班主任职责 | 管理员 |
| --- | --- | --- | --- | --- |
| 兑换卡 | 本人 | 无 | 无 | 无 |
| 日常直评/纠错 | 无 | 授权班级和规则范围 | 授权班级和规则范围 | 无 |
| 荣誉审核/故事终审 | 提交本人 | 被分配的审核范围 | 被分配的审核范围 | 无逐笔业务审批 |
| 学科评价与成绩 | 本人已授权展示内容 | 对应任教班级、学科 | 是否查看跨学科原成绩须另授予 | 不改个人成绩 |
| 报告与寄语 | 本人已发布版本 | 无默认完整报告权限 | 所负责班级草稿、确认及打印 | 只看准备状态 |
| 发布 | 无 | 无 | 确认完成 | 对符合门槛的版本批量发布 |
| 配置/组织 | 无 | 查询履职必需信息 | 同教师 | 学期、指标、学科、发卡、规则、模板、职责 |

管理员接口采用字段白名单，仅返回数量、缺项代码、负责班级/完成状态和发布结果；不返回分数、寄语、故事正文、健康值或 snapshot。是否展示状态清单中的学生姓名由学校确认，默认建议班级汇总优先。

同时收紧旧报告详情/HTML、综合评价、积分列表、材料及附件查询、发布响应、审计 old/new summary 和导出接口。管理员审计默认显示动作与状态，不以审计查询绕回学生详情。前端移除菜单不足以实现权限要求。

## 7. 学期报告与教师寄语

### 7.1 数据与状态

复用 term_report；新增指标字典、指标有效结果、教师寄语修订、发布准备状态等能力。不另建一套平行 student_term_report。

建议状态为 DRAFT（材料收集中）、REVIEW（待教师确认）、READY（可发布）、PUBLISHED（已发布）、SUPERSEDED（已替代）。READY 必须绑定本次数据版本、规则版本与寄语确认版本。

拟定发布检查：适用学期与学生身份有效；必需来源/指标满足年级规则；六维已按有效规则生成；班主任确认最终寄语；模板及版本齐备。家长寄语建议非阻断项，最终由学校确认。免测/不适用按配置视为完成，不能要求所有人拥有全部 74 项字段。

管理员点击发布时只引用 READY 报告及预期版本，服务器在每份报告的事务内重新检查数据版本。若教师确认后源数据变化，该草稿重新进入待确认；不能把旧确认套在新数据上。

发布事务冻结身份与班级、学期、来源有效版本、六维分解/等级、指标值、教师寄语、家长寄语及来源、模板/评分规则版本。新版本成功写入后再替代旧版；并发发布使用唯一约束与幂等任务标识。一批可部分成功，但每份失败必须保持原已发布版本可用。

发布后源数据修改只影响后续草稿；经重新确认生成新发布版本。旧版本仍可按授权查询及打印。报告正文不能在打印时混入实时学生姓名/班级或实时评语；“本次打印时间”可独立标识。

### 7.2 内容与双版式

建议电子版分区呈现：学生与学期、六育成长总览、学期成长足迹、行为习惯、学科表现、身体健康、故事精选、教师寄语、家长寄语及署名。雷达图保留，但不是报告全部内容。

A4 版与电子版读取同一个发布快照；打印模板去掉互动动画，保证中文、星级、长评语、跨页表格与签名区域可读。A4 是需求；两页/双面、盖章位置、全部 74 项是否纳入是待确认版式。本轮草图仅演示信息层次，不代替原校表。

指标使用字典与类型化值承接原有字段，字典还需包含适用年级、学期/版本、显示与必填策略、单位和允许值。学校与版本进入唯一范围；旧建议 SQL 中缺少的学校边界、实际主键/外键类型、来源有效版本等必须补齐。原始值保存用于核验，不让“141cm”作为字符串直接参与运算。

### 7.3 寄语生成

“教师寄语”与“学期总述”建议合并为同一内容。输入只选本学期已经确认的评价事实、典型记录、审核荣誉、故事和可比的历史证据；输出初稿、引用证据及证据不足提示，班主任修改并确认最终版本。100—180 字是建议长度，仍需版式试排。

需求 14 明确要求 AI 寄语。建议预留生成适配层：经学校授权的模型起草；失败时教师手写或明确标注的规则模板兜底。**仅完成规则模板不能宣称已交付 AI 寄语。** 若一期不接模型，需要校方明确接受分期，AI 验收项仍标记延期。本轮不调用模型、不配置密钥。

生成任务失败不影响已保存草稿；允许重试但不能覆盖教师最终确认文本。保存生成方式、模型/模板版本、证据及人工修订历史。不默认传输姓名、学号、健康、家庭等数据；不编造奖项、性格、名次或进步趋势。健康字段仅在有业务权限的报告区域展示。

### 7.4 家长寄语

当前无完整家长身份链。推荐由班主任向已核验监护人提供受限填写入口，凭证仅绑定该学生/学期、可过期及撤销，提交时记录来源；是否采用该入口需学校确认。学生代录可作备选，但必须显示“学生代录”，不能冒充家长实名提交。

建议将家长寄语作为非必填反馈。若希望进入首次发布的纸质版，需在发布前征集；发布后提交保存在独立反馈版本，可另附打印，或经确认后重新发布报告，不能静默修改已冻结正文。家长查看整份报告的权限与填写权限分别确认。

## 8. 学生端体验草案

推荐“成长森林”作为首套讨论主题：暖米白底、森林绿主色、德育橙/智育蓝等方向色，小动物作为成长向导。学生独立布局以成长首页、扫码、成长足迹、荣誉、故事和学期报告为主；教师与管理员保持现有简洁操作风格。

首页突出一个主要动作“扫卡收获成长”，展示自己的六维成长与最近记录。成功页清楚显示加到哪个分类、+1、当前个人成长变化；重复扫码/失败状态不能播放新的加分成功反馈。动画短且可跳过，尊重减少动态偏好。

游戏化等级是个人激励展示，不能直接当作学校评价等级；计算口径与名称需确认。不增加同学排行、商城、抽奖等未提出的业务。主题由颜色、背景、角色、图标等配置切换，不改分数、不拆分数据库；首版做好一套并保留扩展结构。

配套可点击草图只使用虚构学生和演示数据，包含首页、兑换成功、成长记录及电子报告/A4方向。图中示例等级和积分不代表本校已批准阈值。

草图资产：[独立 HTML](../../wayfinder/system-renovation/prototype.html)、[学生首页预览](../../wayfinder/system-renovation/student-preview.jpg)、[报告预览](../../wayfinder/system-renovation/report-preview.jpg)。[独立审阅与校验记录](../../wayfinder/system-renovation/review.md)说明了已经检查和仍待验证的范围。

接口建议保留现有兑换 URL 并升级响应，避免印刷二维码失效；使用版本/开关区分新旧学期。新增教师纠错、任教学科导入、报告准备状态、班主任确认、本人报告和受限家长反馈接口。具体命名留实施计划确定。

旧教师扫卡审核与管理员积分冲销/六育终测导入在新流程停用，不能只隐藏菜单。旧入口收到新学期操作应明确拒绝，并记录调用；历史待审卡是否继续处理由迁移决策确定。manager 不因使用 teacher 路径而获得教师业务能力。

### 9.1 学籍与体测样例导入

学籍导入作为独立的基础资料能力，不复用管理员成绩导入权限。建议先识别学校样例表头，让管理员确认“原列→标准字段”的映射并保存映射版本；按学校和稳定学号匹配，区分新增、更新、同名不同号、重复行与冲突。预览列出将变更的姓名/班级等基础字段，确认后事务写入并留批次审计；不覆盖密码、角色、教师成绩或已经发布的报告。学生转班只影响后续业务授权，历史事件按发生时班级保留。具体档案字段和试点适用格式由样例确认。

健康/体测导入走单独受权的数据范围，建议由体育或学校指定人员操作，管理员仍只看报告完成状态。字段匹配需确认单位、视力记法、测量日期、缺测/免测与允许值；原值保留，异常进入待核实，不自动推断健康状况，也不把身高体重直接折成奖励分。尚无样例时只设计接口与字段边界，不承诺兼容任意表格。

### 9.2 统一登录预留

钉钉预留“外部身份→校内用户→学校/角色/任教或班级职责”的映射边界；外部平台返回的信息不能由客户端自行选择为管理员角色。现有 external_id 字段可作迁移基础，实际关联唯一范围与账号绑定/解绑方式在确认接入条件后设计。当前不假设学校已提供平台权限、测试账号或可用接口；未纳入一期时沿用现有登录。

## 10. 分期与上线依赖

| 阶段 | 目标 | 交付边界与进入条件 |
| --- | --- | --- |
| 方案确认 | 明确本轮未决业务选择 | 先定扫码身份、卡片分类与纠错；评分/报告决策可独立继续 |
| P0 积分闭环 | 制卡定类、扫码即 +1、教师纠错、无卡直评、防重复 | 同步调整授权及数据库约束；完成旧卡处理方案 |
| P1 评价与数据 | 荣誉归类入账、故事建议分、精确任教导入、自动六维 | 依赖学校确认来源/权重/等级与适用指标 |
| P1 报告闭环 | 草稿、AI/人工寄语确认、真实家长输入、状态发布、A4 | 依赖评价有效结果及报告内容/权限确认 |
| P1 学生体验 | 独立学生布局、成长反馈、成长记录和一套主题 | 可用虚构数据并行做设计；真实等级显示依赖规则 |
| P2 身份与设备扩展 | 钉钉、校内设备、手机专项及学籍格式优化 | 依赖实际硬件、平台条件和样例；若公共设备是一期开卡必需则提前到 P0 |

不凭空承诺人日或发布日期；试点班级、开发人员、学期截止和硬件确定后再估算。建议先试 1—2 班验证后扩展，试点范围仍需校方确定。

切换前盘点 UNUSED/PENDING/USED/历史测试卡、现行策略与已发布报告。已使用卡与原积分不重记，已发布报告保持原内容/算法版本。待审卡有“限期走完旧流程、停止并受控换卡、确认后批量转换”三种候选，未确认前不得自动入账或销毁。未用旧卡缺少子类也不能随意补类。

建议按学校/学期开关启用，并先只读对账。回退关闭新入口、保留已记账事实和快照，以受控更正修复；不能靠恢复旧数据库覆盖上线后的有效积分。现有自动演示、测试夹具和操作手册也需要在实施阶段更新，防止仍教老师走旧审核流程。

## 11. 验收场景

以下为后续实施需要通过的验收，不是本轮已执行测试：

1. 生成一批 D/Z 卡，每卡有明确叶子分类，子类总量守恒；T/M/L/G 与无分类策略不能误生成日常卡。
2. 正常学生扫有效卡，单次事务入账 +1，成功反馈展示正确分类；教师待审数量不增加。
3. 同卡并发、断网重试、换请求重复扫、不同学生抢扫，合计始终只有一次原始奖励。
4. 过期、作废、跨校、未生效、旧测试卡均不加分；失败与重复不伪装成新的加分成功。
5. 教师按授权撤销、改分类、改允许的分值；原记录可追溯，重复/并发纠错不重复扣分；卡仍已使用。
6. 无卡直评同一批次重试不会重复发分；越权学生或分类被拒绝。
7. 荣誉审核选择 T/M/L 后只入账一次；驳回有原因，重提留版本，撤销与账本同步。
8. 故事输入/粘贴、建议分与教师正式分区分，学期 G 按已批准月份规则生成。
9. 教师教甲班语文与乙班数学时，不能读取/导入甲班数学；改造请求体或调用旧入口同样被拒绝。
10. 空白、有效 0、A、三星、缺考、免测、不适用正确区分，未经规则不互相换算。
11. 取消终测导入后，系统仍能从有效来源生成六维；积分与荣誉不在综合评价重复加权。
12. 学生无获奖但常规评价齐备可达到发布条件；未完成必评不能伪装为 0 发布。
13. AI 寄语只引用确认证据，失败有明确状态，教师可编辑确认；模板兜底不会被标成模型生成。
14. 任课教师、班主任、管理员、学生、受限家长分别通过授权；管理员通过详情/HTML/审计/发布响应也看不到个人内容。
15. 确认后改成绩导致 READY 失效；并发重发不产生两个同版报告；单份发布失败不损坏旧版。
16. 发布后改姓名、班级、源成绩或反馈，旧报告正文保持一致；新版本经确认后才替代。
17. A4 实测中文/星级、最长字段、长寄语、跨页与签名；电子和打印内容来自同一发布版本。
18. 学生端独立布局、主题切换不改积分或评价；公共设备若纳入一期，必须验证学生切换、超时和清屏。

## 12. 待确认决策与审阅边界

完整问题、建议和依赖以[系统改造决策地图](../../wayfinder/system-renovation/map.md)的子票为准；本文不把建议记为学校已经批准。

最先需要确认的是：一期扫码身份与设备、制卡子类分配、教师纠错与直评范围。评分来源/权重/等级、班主任权限、原报告样例、家长渠道、AI 是否一期实接、旧卡切换及试点范围会决定后续实现范围。

设计草图采用“成长森林”、复用现有技术栈、报告主表沿用 term_report、状态/内容分离和追加纠错，均为本轮推荐。实施者可选择模块文件组织、查询/索引细节、状态投影实现、内部接口命名与动画技术；不得擅自决定学校评分口径、身份渠道或访问范围。
