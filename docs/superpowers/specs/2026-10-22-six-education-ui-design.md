# 六育学生评价系统 · 全模块界面设计

日期：2026-10-22｜状态：设计评审稿｜交付：可点击设计原型 + 本说明

## 1. 设计依据与目标

依据 `docs/plans/2026-10-22-student-evaluation-system.md`、`docs/spec/学生学期综合素质评价系统_SPEC_V1.0.md`（正文 V2.1）和附件 B、D。需求冲突时以 SPEC V2.1 的业务不变量为准，附件 D 未确认参数始终标注“试行/待校方配置”。

用户明确的视觉要求：**非常清爽、干净、简洁，容易使用，一眼看清楚自己需要做什么。** 用户同意以浏览器可点击原型查看三端各模块。

本次是界面设计，不改后端，不接真实数据库，不把演示操作当成真实业务。原型里的角色切换仅用于设计浏览，生产系统的角色由服务端会话决定。原型不生成可用实体卡令牌或真正的 PDF，只演示这些任务的状态与反馈。生产接入仍需执行原 implementation plan。

## 2. 设计方向与自主决定

设计方向：“清晰的成长工作台”。所有页面先回答“我现在要做什么”，再提供查阅与追溯。禁止把后台业务对象直接堆到首页。

以下是设计者根据现有项目作出的选择，尚非用户逐项确认：

- 使用白色侧栏、浅灰绿背景、墨绿主要按钮，六育颜色仅用于小面积图标、标签和图表。
- 原型使用无外部依赖的 HTML/CSS/JavaScript，直接浏览和保存；未来正式前端沿用现有 React 18 + Vite + Ant Design，不迁移到 Vue，也不据计划中的 Java 示例改写现有 Express 后端。
- 三端共享视觉系统；原型默认教师工作台，突出最高优先级 Task 14-A。生产保持独立角色路由和权限边界，组件与设计令牌可以共享。
- 桌面侧栏 224px、顶部栏 72px、页面边距 32px；内容最大宽 1440px；主要表格行高至少 56px。
- 正文 14px，辅助说明 12px，页面标题 26px；中文字体现有设备可用的苹方/思源黑体，数字使用清晰的等宽数字特性。无需下载字体即可阅读。
- 页面原则上只有一个实心主操作。危险操作用文字/描边入口，进入说明后再以红色确认。
- 不新增家长账号、排行榜、积分兑换、申诉工单或实体卡学生预绑定。

## 3. 全局布局与通用交互

桌面：左侧分组导航 → 顶栏当前模块/学期/消息/身份 → 页面标题与一行说明 → 待办或操作区 → 列表与详情。侧栏只展示当前角色可见内容。学生只能看本人，教师仅任教班级，管理员仅本校。教师班级下拉只出现授权班级。

移动端：小于 760px，侧栏变为抽屉导航，顶部保留模块和身份；双栏变单栏，表格保留容器内横向滚动，操作区换行，审核详情与底部操作保持易触达。学生扫码、教师扫码审核和故事终审为重点场景，触控目标至少 44px。320px 宽度下页面本体不横向溢出。

通用规则：

- 搜索/筛选仅影响当前授权范围；日期和自然月按学校配置时区展示。
- 已归档学期置顶展示“已归档，只读”，保留查询，停用常规写入口；归档后受控更正只对具备超管能力的管理员呈现，不增加第四个登录角色。
- 提交显示 loading；服务端结果到达前保持原状态。请求失败保留表单，重试沿用同一幂等键。成功后更新待办数量。
- 空状态包含原因与适合当前角色的下一步；无结果提供清空筛选；异常用页内提示和“重试”；无权限不显示他人数据；会话失效回登录。
- 仅提交、不可逆操作、放弃未保存编辑使用确认；常规导航不额外询问。
- 颜色配合状态文字/图标；可键盘访问，显示焦点环，弹层支持 Esc、关闭后返回触发按钮；减少动态效果设置生效。
- 原型演示操作只更新当前浏览器内存，刷新恢复种子数据；故事草稿可在本地保存并明确提示。生产接入使用真实接口而非演示状态。

## 5. 学生端逐模块设计

### S01 成长首页

顶区“每一步成长，都值得被看见”，显示姓名、班级、学期。首屏左侧为“本月待完成”，仅列实际需要行动的事项；右侧为最近一次教师反馈。中部六维过程积分条形概览，明确标题“过程积分”，不与百分制正式分混用。下部最近流水/荣誉，提供查看全部。扫码领取在页面主操作。

### S02 扫卡领取

输入区接受二维码链接或令牌，真实扫码从 `/scan?t=<rawToken>` 进入同一预览；正式版相机需 HTTPS 和相机权限，拒绝后保留输入入口，原型以演示卡预览表现流程。卡面展示三级指标路径、脱敏教师名、固定 +1、截止时间和状态。不显示令牌哈希或数据库 ID。

“确认申领”之后显示“已提交，等待教师审核”“通过后 +1”，过程积分保持不变。已使用、已作废、已过期、他人申领中均展示不可操作提示，不泄露领取人。教师审核通过后才在账本出现 +1；驳回卡永久作废。设计原型以状态选项演示完整状态。

### S03 积分账本

顶部六维净积分；筛选为时间、维度、来源。流水列为时间、指标、维度、来源、变动、操作教师、凭证。正向和冲销各保留一行，冲销详情能跳回原记录。无编辑、删除入口。

### S04 荣誉申报

列表有活动、级别/奖项、认定分、当前状态、更新时间、操作。“申报荣誉”弹层包括赛事名称、届次/赛事标识、获奖日期、省市区级别、一二三等奖、证书原图。认定分只读预估，审核前不计入。退回项第一行显示原因，“补充材料”沿同一记录产生新材料版本。证书详情展示版本时间线与审核记录。赛事去重由服务端判断，原型仅展示冲突文案。

### S05 月度故事

顶部月份时间线区分草稿、已提交、已评分和未开始。主体为安静的写作区域，显示任务说明、截止日、字数、草稿状态；主要操作“提交本月故事”，次操作“保存草稿”。评分后显示教师终审分和反馈，AI 建议不作为学生正式成绩。重新提交保留版本。缺月显示未完成，不显示 0 分。

### S06 综合评价

分开呈现六育正式分（0—100）、过程净积分、荣誉认定分，再显示 B/P/H 标准化结果、权重、综合结果和规则版本。缺任意 CONFIRMED 维度，综合结果位置显示“待完善”，列出缺项，不显示貌似正常的 0 或部分总分。学科考分单独成表，不参与六育均分。

### S07 学期报告

已发布版本用纸张式内容区：身份/学期/版本 → 六育雷达和成绩表 → 过程积分摘要 → 学科成绩 → 故事与荣誉 → 评语/自述/家长寄语。原型雷达为直接可读的 SVG，并附文字数值。未发布只显示“报告尚未发布”，不向学生暴露草稿。

PDF 按钮显示准备中、可下载、生成失败重试三态；正式版轮询任务，下载 URL 5 分钟有效，超过 60 秒标记失败。原型不伪造成功文件。报告版本历史只展示本人曾发布版本，旧版标注已被新版替代。

### S08 个人信息与自述

基础身份只读；自述和家长寄语可编辑。家长寄语明确显示“由学生代录”，非必填；不出现家长账号入口。提交/报告冻结后根据学期写权限变只读。生产自述持久化接口需要补契约，原型仅演示编辑。

## 6. 教师端逐模块设计

### T01 工作台

首屏标题“把目光，放在每一次成长上”，下方三项待办：扫卡、荣誉、故事，数量和操作直接对应。中部“待处理事项”列表，可逐项进入审核；右侧为本月班级任务清单。下部班级六育概览及最近记录，避免重复堆叠统计卡。

### T02 扫卡审核

默认待审，只显示当前教师名下卡申领；班级/月份/状态筛选。选择记录打开右侧详情：学生、班级、申领时间、三级指标、卡归属、宽限截止。“通过并记 +1”与“驳回”并列；驳回必须填写理由，并解释卡永久作废。失去班级权限的历史待审按 SPEC 由原卡教师负责，服务端最终鉴权；不提供查看其他教师卡的入口。

### T03 无卡直评

左侧班级学生列表，支持搜索/多选/全选；右侧三级指标、固定 +1 提示、共同备注及逐生备注（可折叠）。底部显示“已选 N 人，每人 +1”，提交前摘要确认，结果逐生显示成功/失败并保留批次号。不得出现自由分值输入框。失败重试复用每生幂等键，不再次给成功学生记分。

### T04 荣誉审核

列表筛选班级/状态，详情左证书右申报信息与版本链；通过显示系统计算分，退回补充材料与终态拒绝分开。退回/拒绝必须理由。已通过只读，普通教师不提供撤销；管理员撤销在 M06。

### T05 故事评阅

三段式：待评列表 → 文稿（主要阅读宽度）→ 评分面板。AI 建议区标签“仅供参考”，显示建议分与评语、模型状态；人工终审分输入 0—100，评语必填，明确点击“确认终审”才成为教师评分。AI PROCESSING/FAILED/SKIPPED 时仍能人工评分；无建议文本不显示空建议卡。已归档终审分只读。

### T06 班级成长

授权班级选择；表格显示学生、六育正式分齐备度、过程净分、荣誉认定、故事提交、综合状态。学生详情将过程积分与正式分分区。缺项用“缺美育”而非 0。无全校检索和班级排名。

### T07 学科成绩导入

三步向导：选班级/类型并下载模板 → 上传与差异预览 → 确认及批次结果。仅学科类型可写，五育为查阅入口。模板身份键用学号，不按姓名匹配。限制 2MB/1000 行，异常定位到行和字段；有异常不可确认。确认后展示批次号、成功条数和明细。

### T08 期末评语

学生列表 + 当前报告草稿：六育齐备度、学科表、荣誉与故事摘要、评语编辑。“AI 生成草稿”不自动保存正式评语；教师可修改。保存与“确认报告草稿”分开，缺项时阻止确认并提供缺项清单。教师无发布按钮。

### T09 我的评价卡

显示本月总配额、未申领/待审/已入账/作废/过期统计；按指标分布及每张卡状态只读列表。说明“线下发卡后由学生扫码，不需预先绑定学生”。教师无制卡/印刷导出入口。

## 7. 管理员端逐模块设计

### M01 管理概览

主区按学期阶段组织：进行中（缺项/审核）→ 结算（导入/核算）→ 发布（门禁/报告）。突出待解决问题和下一步；数字可点击到筛选后列表。学校范围始终明确。

### M02 学期与校历

学期表 + 编辑面板。字段含学年、上下学期、起止日期、时区、当前展示学期、可操作状态、故事提交截止、发卡截止、审核截止、发布日、次月宽限期。校历周次基于起始日展示教学周，允许标记假期（原型示意，持久化结构待补）。启用/当前展示是两个不同控件。结束日期不得早于开始日期，宽限截止不得超过学期审核截止。归档需摘要确认并说明后续正常业务只读。

### M03 账号与班级

三类账号分段筛选，搜索学号/账号/姓名；新建与编辑教师班级授权、学生归属班级；停用显示影响说明，已有待审卡进入可代审条件。角色码严格使用 student/teacher/manager。密码不在详情回显，重置使用单独动作。最终授权依据服务端能力字段。

### M04 六育指标

左六育一级树 → 中二级/三级指标 → 右当前节点详情。显示代码、路径、启用状态、版本和固定 +1。已被使用的指标保留历史版本，启停只影响新业务；本次不提供任意分值编辑。

### M05 评价卡管理

页签“月度配额/卡片批次”。配额按教师编辑，列三级指标张数，总和实时反馈；不等于 N 禁止保存。月度制卡展示月份、教师数、预计卡数、有效截止；重复制卡展示已有批次。印刷导出为一次性敏感资产处理，原型不生成真实码。作废只作用于 UNUSED；不得作废恢复/复用终态卡。管理员代审入口仅对教师停用或已有授权转办的记录可操作，展示触发依据、理由、代审身份和审计记录。

### M06 荣誉材料

全校筛选、证书/版本预览、认定记录。对 APPROVED 显示“撤销认定”，必填原因，确认前说明将触发综合分重算和报告新版本；REVOKED 不可恢复到已通过。原记录保留，不直接删除证书。

### M07 故事任务

月份任务表显示标题、起止、完成率、待终审、AI 开关。任务详情按班级查看缺交/待评，监控 AI 失败。校方未确认量规/外部成绩合成前只提供待配置提示，不自动混合外部故事成绩与月度终审分。

### M08 成绩导入

类型选学科、五育、外部故事；模板导入为当前支持方式，不出现已连通钉钉 API 的假状态。遵守 T07 的上传/预览/确认流程；预览对新增/变更/异常分别计数，按学号定位、版本与旧新值对比。确认成功才出现 batchNo；外部故事独立来源标记，不静默合成。批次历史有提交人、时间、类型、影响范围、错误报告下载。

### M09 综合核算

上半当前规则与版本：B/P/H 权重、过程阈值、荣誉阈值、DRAFT/ACTIVE/DEPRECATED 历史；推荐 80/15/5、20/12 标注“试行待校方确认”。新建版本才可编辑；权重和必须为 100%，阈值大于 0。激活确认会展示“替代当前规则并触发全校重算”。下半核算结果，缺项列学生/班级/缺失维度，未完成不按 0 计算。重算任务展示进度/失败重试。

### M10 报告发布

页签“待确认/可发布/受阻/已发布”。列表逐生展示六项条件：六育齐全、规则生效、班主任确认、综合分完成、快照有效、学期可操作。受阻显示具体原因与定位入口，禁止勾选发布；可批量选择全部满足条件的报告。发布确认显示人数、学期、版本和发布结果通知。原型同时展示“全部通过”和“缺项受阻”样例。历史报告和更正版本均可追溯。

### M11 积分与更正

全校流水查询；只有未冲销的 +1 显示“受控冲销”，弹层包含原记录、-1 影响、必填理由。确认追加负向流水，不修改原行。已发布后的更正依 SPEC 检查超管能力，归档后仅超管可追加冲销/新版报告；普通管理员只看到说明。更正预览列原综合分、预计新分和新版报告路径；无法在前端替代后端校验。

### M12 审计与通知

页签“操作日志/消息投递/任务监控”。日志显示时间、操作人/身份、动作、对象、前后摘要与请求追踪；代审标记专用身份。通知显示待发/已发/失败、重试次数、下次时间；内部重算消息不作为学生通知。任务显示卡过期、申领过期、重算、PDF 导出；只在有授权时提供失败重试。原型任务为示例，不声称后台任务已部署。

## 8. 数据与原型状态约定

演示学校“青禾实验学校”，学期“2026—2027 学年 · 第一学期”，演示时点 2026-10-22，时区 Asia/Shanghai。所有姓名、班级、数量为虚构样例，不来自真实学生。

原型页面顶部持续显示“界面设计原型 · 演示数据”；提供学生/教师/管理员切换、全部模块目录和桌面/手机预览。可演示：导航、筛选搜索、审核详情、驳回必填、固定 +1 直评、故事终审、材料补交、导入差异、规则权重校验、发布门禁、冲销理由等。真实扫码、上传解析、导出印刷码、PDF 文件、AI 调用、真实登录、账号管理均明确为接入点，不能显示伪造的线上成功反馈。

## 10. 验收与下一步

本次设计验收：31 个视图均可访问；三端导航和主操作清楚；关键异常状态可见；桌面和手机布局无主体横向溢出；交互反馈如实标注演示；原型不影响现有产品源代码。由独立审阅者检查设计是否遗漏业务限制，并以浏览器实测导航和主要交互。

用户对本说明与原型确认后，再依据批准的设计编写正式前端实施计划，并逐模块接入现有 React 工程；原型不能直接视为已交付生产功能。
