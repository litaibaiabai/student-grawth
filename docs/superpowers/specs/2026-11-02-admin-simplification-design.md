# 管理员三模块重构设计

状态：2026-11-02用户指定进入writing-plans阶段，尚未修改产品代码或正式数据。已确认：额度按班科计算、班主任确认即发布；每学期卡片只能初始化一次，去掉重置功能；同步修改教师卡片管理与学生报告读取模块。

## 目标及保留边界

管理员只保留：学籍账号管理、卡额度管理、数据统计。删除发布中心、学期配置、操作记录的页面、导航、导出入口及专用接口。合并学籍与班级入口，去掉独立班级编辑、任教关系编辑、调班、启停和密码重置面板；关系只通过统一Excel导入，之后查询。

继续使用现有React/Vite、Express/MySQL和绿色米白视觉体系，不添加UI框架。运行数据只使用student_growth原有正式表，不创建临时库、临时表或第二套学校数据。改动数据前备份。已有师生日常操作、教师体测Excel、班主任寄语和既有四类统计保留。

删除操作记录模块不等于删除来源事实或幂等命令记录：它们仍服务于积分计算、事务重试及历史报告，不再提供管理员操作记录浏览/导出。历史冻结报告也不删除。

## 一、学籍账号管理

### 用户流程

一个Excel工作簿完成学期、教师、班级、学生和学科教师映射初始化。页面上部为下载模板、选择文件、检查结果和确认导入；下部以学生、教师、班级三个只读视角查询同一关系。

文件选择后先完成跨工作表校验和差异预览，显示新增/更新/跳过人数、班级和课程数，错误定位到工作表/行号/字段。预览不写账号、班级、评价或课程关系。确认后一次事务提交，任何一行失败均不部分导入。

查询支持姓名/账号、年级、班级、学科和分页。展示学生→班级→班主任及任课教师，或教师→学科→对应班级。没有手工分配教师、编辑班级或单独新建账号按钮。

### 默认重导入规则（设计判断）

相同文件重复提交幂等跳过，不重置现有密码、不重复建立评价或课程。遗漏的现有记录不删除。姓名等允许在预览后更正；同学期关系变更仅在卡片正式初始化前通过重新导入完成，初始化后拒绝修改并说明原因，防止已发卡权限失配。无重置或删除入口。

### 一个工作簿的字段格式

只接收.xlsx，一个文件包含以下五张固定名称工作表。账号、班主任账号和教师账号使用文本单元格，保留前导零；不把姓名作为关联键。首行为表头，空白行忽略。

| 工作表 | 必填列 | 可选列/默认 |
| --- | --- | --- |
| 学期 | 学年、学期序号、学期名称、开始日期、结束日期 | 采集截止日期默认结束日期；下学期报到日期可空；设为当前学期默认“是” |
| 教师 | 教师账号、姓名、初始密码（新账号） | 既有账号初始密码留空或忽略，不通过导入重置 |
| 班级 | 年级、班级、班主任账号 | 班级名称默认“X年级Y班” |
| 学生 | 学号/账号、姓名、年级、班级、初始密码（新账号） | 既有账号初始密码留空或忽略 |
| 任教关系 | 年级、班级、学科、教师账号 | 每个班级每个学科仅一位教师；一个教师可多班多科 |

学期表仅一行：学年如2026-2027，序号1或2；日期为YYYY-MM-DD或Excel日期单元格。年级和班级为正整数。教师与学生账号在学校内唯一，角色冲突拒绝。新密码沿用现有长度限制。

学科沿用现有12项：道德与法治、语文、数学、科学、英语、体育与健康、音乐、美术、信息科技、劳动、综合实践活动、地方课程。学科显示名与固定代码一一对应，未知值拒绝。

引用关系必须能在本文件或学校已存在记录中明确解析：学生班级必须存在；班主任和任课教师必须是启用教师；重复班科教师冲突必须报错，不能以最后一行覆盖。班主任不因身份自动获得所有学科卡。

示例：教师T001林知行在四年级1、2、3班任教语文，三个班的关系表分别填写一行；学生20260401林小禾在四年级1班，班级表填写该班班主任账号。

## 二、卡额度管理

### 已确认计算口径

从“张/班/月”改为“张/班/学期”，不按月份再乘。语文60、数学70、英语75分别为每班整个学期的数量；林知行教三个班语文，生成60×3=180。每位教师持有本人实际课程对应的卡，每张只能领取一次，仍限制本班学生领取。

页面只配置学科额度并显示初始化结果；默认100、学科空白继承默认、0不生成，沿用此前已确认的偏好。唯一主操作为“初始化”，不提供重置或删除功能。教师端停止自动按月增发，改为读取、筛选和打印管理员已初始化的学期卡。有效期为学期开始至采集截止，不再有月度选择器。

### 初始化

管理员配置后点击初始化，系统读取Excel导入的班科教师关系，一次生成全学期全部卡片。生成前给出教师数、课程数、各科数量及总量；确认后使用学期排他锁和配置版本校验，重复点击不重复发卡，失败事务不留下半套卡。

初始化后学科配置只读，页面显示生成总数、已领取和未领取；不能通过修改额度隐式增发卡。未初始化不能领取或打印。旧教师自动同步接口和初始化入口都要清理，不能保留绕过管理员初始化的替代写入口。

### 一次性初始化与锁定（用户最终确认）

每学期只能成功初始化一次卡片。初始化即该学期卡配置生效，之后无论是否已经领取，都不允许重置、删除、再次初始化或修改额度。管理员端不展示重置按钮，后台也不提供重置/删除接口。

初始化前展示确认对话框，列明学期、教师、课程和总卡数，明确说明“本学期只能初始化一次，确认后不能重置或修改额度”，取消为安全默认。事务失败不算初始化成功，可在修正问题后重试；已成功请求的网络重试返回同一结果，不增发卡。

在学期排他锁内核对初始化状态和配置版本，初始化状态与所有卡片在同一事务提交。初始化后前端只展示结果和只读额度，服务端拒绝任何替代写入口。对已领取卡片及积分不做删除或回撤。

## 三、数据统计

现有卡片与奖励、自我评价、荣誉上传、故事参与四标签及年级/班级/学科筛选、学生明细和统计口径保持一致。改为学期卡后，统计仍只统计实际成功领取和有效无卡奖励，不把生成数量混入获奖数。

## 班主任确认即发布

班主任仍在教师端查看完整报告，校验必需数据、寄语和打印溢出后确认。确认与该学生报告快照发布在同一事务内完成；成功后学生即可看到本人报告，不等待管理员，不检查其他学生是否完成，也不冻结整个学校学期。

按学生维护发布版本。后续数据更正使当前审核失效，但学生保留可读的上一已发布快照；班主任再次确认后产生新版本，旧快照不原地改写。班主任替换等身份校验沿用现有范围约束。

学生报告读取和任课教师冻结明细读取统一选择该学生最新PUBLISHED版本，排除PREPARED或未确认草稿；任课教师仍不读班主任私有寄语。学生空态改为“等待班主任确认”，删除“等待学校统一发布”文案。

旧的全校准备、恢复、取消、激活、完整性导出和管理员阶段变更接口不再被保留为替代入口。已有已发布快照兼容可读，历史记录中的发布元数据可保留。采集起止日期来自Excel；新流程不再以管理员阶段切换作为师生操作前置条件。

## 界面方向

延续现有米白底、深绿文字、宋体标题与轻边框，采用更精简的表格工作台。左侧只三个菜单；顶部保留学期选择。学籍页以一个文件入口贯穿，结果与只读关系紧邻；卡额度页直接展示学科数量和初始化状态，初始化前弹出一次性操作确认框；统计页复用原组件。

设计预览使用虚构静态数据，不访问数据库，不冒充正式功能。桌面与窄屏都不出现整页横向溢出，表格在容器内滚动。

## 迁移、清理与验收

1. 备份正式库和相关配置，记录原卡、领卡、报告数量；不自动重置当前已经领用的演示卡。
2. 旧已发卡作为历史批次兼容读取，不能因新初始化再次增发；已有批次的旧学期直接认定为已初始化、额度锁定。新学期使用学期卡模式；不删除已用卡事实或既有报告。
3. 删除三个被撤模块的组件和专用样式、路由、导出及旧导航引用；共享工具按调用关系保留，不靠隐藏菜单假装删除。移走仍被保留功能依赖的月份/日期等通用函数，避免保留整块旧学期配置服务。
4. 统一导入从五张表产生一个原子业务结果；下载的模板与服务器解析共用字段契约。提供填写示例、字段说明、错误示例和重传规则。
5. 在正式表内使用可回滚验证数据，不建立临时库表；涉及真实还原或破坏数据前执行备份并遵循本次授权范围。
6. 验证单文件初始化、重复导入、跨表引用错误、角色/跨校拒绝、教师多班额度180、不重复初始化、初始化二次确认/取消/并发只成功一次、已初始化拒绝修改与删除、班主任确认立即可读、更正后旧版保留及重审新版本、四类统计不变。
7. 运行前端测试、lint/build和相关后端验证；MCP实际走通三个管理员模块及教师确认→学生阅读，交付完整源代码、迁移说明、Excel字段要求和实际截图。代码继续提交到feature-six-education-v4。

## 设计判断清单

- 一个Excel含五个工作表，避免把学生和教师笛卡尔展开成重复行。
- 文件导入是唯一关系写入口，新增后不提供手工编辑；后续更正通过同一文件预览提交，已发卡时阻止关系静默变化。
- 保留默认100与0不生成的既有偏好，额度单位改为班/学期。
- 班主任确认生成单生冻结快照，历史发布版本继续可读。
- 移除操作记录界面，仍保留必要的来源事实和幂等记录。
- 按用户最终要求去掉重置：学期卡配置仅一次初始化，成功后不可重置/删除/改额。
