# 三角色全系统闭环演示与本机 MCP 验收设计

状态：2026-10-26用户确认“继续”，批准按完整方案执行。执行及测试结果另记交付报告。

## 1. 目的与已确认范围

用户确认：面向学校领导与管理员；覆盖整个系统，从学期配置、自动发卡、成绩、荣誉、故事到综合评价与期末报告；完整走通，不以时长删减。先生成所有演示资料与演示方案，再使用 MCP 在本机完成一次全面测试。

领导需要看到评价证据如何成为学生成长记录，管理员需要看到配置、师生协作、异常修复、核算、发布与追溯。围绕同一批虚构学生串联全部环节，避免只有孤立菜单巡览。

## 2. 实施者默认选择（非用户已确认事项）

- 使用本机独立 MySQL 演示库和独立端口，不覆盖原业务库、原 `.env`、现有服务及旧材料。
- 采用8名虚构学生、四年级两个班、2名演示教师、1名管理员；另设最小量的边界测试账号。教师甲主教语文并兼教数学，教师乙主教美术；教师甲任教两个班，教师乙任教二班，用于观察权限边界。另有异校账号用于越权验证，不参与领导演示主线。
- 演示学校的数据使用 school_id=1，但位于完全独立的演示数据库内，以匹配当前部分默认查询仍以学校1为默认值的现状；不得借此省略异校负向测试。
- 学期按实际运行日动态选择覆盖当日的校历，默认使用北京时间及当前学年；生成日期、月份、学号、教师与卡片均来自同一个清单，不硬编码旧的2026-10示例卡号。
- 正式交付以可打印 PDF 演示手册、Markdown可编辑原稿、HTML/SVG流程图、Excel/CSV导入材料、PNG模拟证书、故事文本和本地启动/初始化脚本为主，不额外制作PPT。
- 演示手册分“领导讲解主线”和“管理员逐步操作”两层，每步都包含角色、入口、操作、对应材料、预期页面、关键数字、切换时机、失败时排查方法。
- 现有77项后端与14项前端测试作为已有回归基线；验收时以重新执行结果为准，不能把旧测试结果当成本轮已通过。

## 3. 当前功能事实与旧资料处置

当前代码与旧手册存在明显差异，旧手册保留归档，新包标明为当前版本：

- 发卡已改为主教学科策略自动月配卡，不再讲解教师手工额度或批量制卡入口。两位教师分别示范100张中“智70/德20/劳10”和“美70/德20/劳10”；兼课教师每月仍一份。
- 打印使用系统真实生成的V2教师分组PDF。卡面只有方向，扫码预览与教师两级子类审核使用真实可领取凭证；不制作声称可用的伪卡号或预绑叶子卡面。
- Excel批量导入已存在，应以实际上传、预览、错误隔离、确认入库为主；JSON作为排障备用，不能替代正常界面演示。
- `subject_score`的学科成绩与`student_dimension_score`的六育终测分是两套来源，当前没有从语数英自动推导智育终测分的链路，演示手册不得宣称已有此功能。
- 故事辅助评分为`mockEvaluateStory`规则模拟，教师终审分才是正式依据。须展示此限制，不宣称接入真实大模型。
- 当前综合评价引擎按默认80%六育均分、15%过程标准分、5%荣誉标准分计算；过程目标20、荣誉目标12，最终以当前激活规则为准。G优先采用当前实现选择的已终审故事分，需用预期计算表验证。
- 当前报告导出接口返回受控HTML打印视图，演示“打开打印视图→浏览器打印/另存PDF”；不宣称后端直接返回PDF二进制。
- “六项门禁”按实际可证明的条件讲解，至少验证六育维度完整性。若界面声称的其他门禁、评分来源或权限与实际不符，计入缺陷，不能写进演示稿充当已实现能力。

## 4. 演示数据与可重复性

主角学生完成全部正向闭环；其他学生承担缺项、补齐、对照和班级隔离场景。所有姓名、学号、奖项、学校均为虚构，证书明显标注“演示样本·非真实荣誉”，不使用真实学校印章或真实获奖背书。

基础初始化仅准备账号、班级、指标字典及明确标记的历史演示数据；不得预写将作为现场操作结果的申领、审核通过、正式荣誉认定或已发布报告，随后冒充MCP实测产生。

可准备主角学生18条各+1的历史过程演示积分（每条明确标为历史演示样本），再现场演示直评+1、卡片审核+1达到20分目标；历史记录与本次现场产生的记录在清单中分开列出。若初始化使用历史数据，讲稿明确说明，不把其当成本次操作的结果。以规则和精确原始值独立计算总分、标准分、等级和报告预期，预期计算不调用被验证的评分函数。

每轮初始化新建有唯一运行编号的数据库，不删除或重置未知数据库。保留：

1. 可重复演示的起点配置与生成器；
2. 本轮完整测试后的状态与证据；
3. 如需再次演示，另建新的起点实例，而非在已终审/已核销数据上硬重放。

原业务库不执行迁移；迁移在独立演示库及独立回归测试库执行。现有自动测试会写数据，因此不能直接运行在保留给正式演示的库上。

## 5. 演示闭环顺序

| 阶段 | 主角色与操作 | 可验证产物 |
| --- | --- | --- |
| 0 启动与说明 | 管理员登录，说明虚构数据、当前学期、三个角色 | 环境健康、演示账号与身份一致 |
| 1 学校配置 | 管理员创建/核对校历、审核截止、指标树与评分规则 | 有效学期、完整指标、明确权重与版本 |
| 2 学科自动发卡 | 管理员维护学科、教师兼课及主学科，保存比例策略；教师看本人分配 | 每教师一份，数量/方向正确，无缺配置误发 |
| 3 实体卡交付 | 管理员下载教师分组PDF；教师线下发卡；学生打开真实二维码链接 | 卡面不预绑子类，预览方向/教师/期限正确 |
| 4 卡片申领审核 | 学生确认申领；教师选择两级子类并审核；学生查看账本 | 申领时0入账，通过后一次+1；卡片USED；分类可追溯 |
| 5 无卡直评与纠错 | 教师给主角直评+1；管理员对额外的演示误评做受控冲销 | 原记录保留、冲销另记、净分可复算，不产生额外正式加分 |
| 6 荣誉闭环 | 学生上传模拟证书申报；教师先退回一项，学生补材料重提，再认定通过 | 材料版本、退回原因、图片受控预览、荣誉标准分变化 |
| 7 故事闭环 | 学生保存草稿、修改并提交本月故事；查看模拟辅助建议；教师终审与评语 | 草稿不等同终审，正式G分来自可追溯教师终审 |
| 8 学科成绩 | 教师上传Excel，查看新增/变更/错误行，确认导入有效行 | 真实批次、学号匹配、错误报告、不合规数据不入库 |
| 9 六育终测 | 管理员先导入故意缺体育维度的数据，观察缺项；再补齐终测 | 不把缺项当0，核算完整性从不完整转完整 |
| 10 综合核算 | 学生查看六维数据、过程/荣誉标准分、封顶情况与总分；管理员核对规则 | UI、API/只读数据库与独立预期计算一致 |
| 11 发布与回看 | 管理员先演示缺项学生被阻断，再补齐、发布；学生查看报告与打印视图 | 通过/阻断对象正确，报告成绩、版本、学科与荣誉一致 |
| 12 审计与归档 | 管理员查看配置、导入、冲销、发布记录；核对已发布快照 | 行为有据可查，后续数据变化不静默改写旧快照 |

不要求为避免角色切换而把闭环拆成各角色互不关联的三个展示。每次切换均说明“谁提交、谁核验、何时生效、学生在哪里看到”。

## 6. 正式资料清单

使用新的独立目录`demo_materials/full-system-demo/`与`docs/delivery/full-system-demo/`，保留旧资料原样：

- 资料索引/README：一键启动入口、当前版本、生成时间、运行编号、目录链接、恢复方法。
- 演示手册PDF与Markdown：完整讲稿、角色操作脚本、逐步预期、领导关注点、异常处理与诚实功能边界。
- 三角色流程图HTML/SVG及可编辑源，区分主线与异常回路。
- 虚构师生与账号表XLSX/CSV、教师任教学科/主学科与策略准备表；密码仅为本机独立演示账号，不混入原账号或数据库秘密。
- 学科成绩正确版XLSX/CSV、带常见错误版XLSX、成绩更正版XLSX；列结构与当前模板兼容，不以无效长表冒充批量宽表。
- 六育终测缺项版、完整/补齐版XLSX/CSV；保留G输入与教师故事终审覆盖的验证案例。
- 荣誉申报字段表、两版有明显演示水印的证书PNG、退回/补交说明文本。
- 主角故事草稿、修订稿、提交稿、其他学生样本与教师评语TXT/Markdown。
- 系统真实生成的可打印卡片PDF、对应本机领取链接/二维码使用说明；卡片数量、教师和凭证从生成批次提取，不手工拼假数据。
- 预期结果核对表XLSX/CSV：学号、六维分、过程净分、荣誉原分、折算分、总分、等级、报告条件与逐步增量。
- 初始化/启动/预检脚本与运行清单JSON（数据库名、端口、ID映射、素材哈希、明确无外部秘密），保护本机密钥和运行环境文件不进入普通交付包。
- MCP测试清单、逐步实测报告、截图、下载文件、问题与复测记录；测试前模板先生成，测试后填真实结果。
- 测试产生的真实期末报告打印视图及能通过本机浏览器合法保存时的PDF，不用手工伪造“发布成功”报告替代。

生成资料后先校验文件可读、Excel结构、模拟图片、文稿与账号映射，再进行全流程MCP测试。

## 7. 本机全面测试方式

MCP浏览器/本机工具实际操作页面，包含登录、角色切换、文件上传、二维码链接进入、审核、导入、受控下载与打印视图。API/数据库用于准备基础条件、独立核对与自动化边界回归，不能代替所有UI操作后宣称已MCP全面测试。

主线每个阶段至少一项真实页面证据；重要数值在状态前后核对。建立可勾选矩阵，覆盖三个角色的全部现有菜单、所有上述主线及关键异常：

- 身份与范围：未登录、过期登录、学生读他人资料、教师跨班/跨校、非管理员发布、错误角色扫码。
- 自动发卡：缺主学科、缺策略、兼课一份、同月重复、策略下月生效、私有校历无覆盖、缺打印配置的恢复。
- 扫码审核：取消、重复申领、乱序预览、不完整/跨方向分类、到期、驳回、同校管理员接管、幂等一次+1。
- 荣誉与故事：非法图片/材料缺失、退回补交、版本、草稿与正式分、重复操作、跨班/跨校、教师正式分与辅助建议的边界。
- 导入：空表/非法分数/未知学号/重复行/零分/更新、有效行与无效行隔离、错误报告、确认前不入库、权限。
- 核算：六维缺项、G正式分来源、过程冲销后净分、过程/荣誉封顶、权重版本及四舍五入。
- 发布：缺项阻断、部分成功、重复发布版本、发布后数据改变与快照、本人/跨班/跨校权限、打印与下载。
- 安全与运行：退出会话、刷新恢复、敏感凭证不出现在普通日志、私有文件不可匿名读取、后台任务与前台状态一致。

不更改操作系统时钟。跨月和截止使用隔离测试库中的时间夹具及自动化回归验证，并在报告区分“页面实测”和“自动化边界验证”。3000名不同学生的压力测试不属于本次默认目标；不得把重复同一学生的循环入库宣称成真实全校规模验收。

每项结论标为PASS、FAIL、BLOCKED或明确不适用，附操作/预期/实际/证据。发现与界面或当前规格不符的行为，先记录，修复影响闭环的普通缺陷后复测；涉及评价规则或权限业务决策变化时另行说明，不靠直接改分、关闭权限或预写结果绕过。若确有无法修复的外部依赖，交付明确阻断，不能报“全面通过”。

## 8. 完成标准与交付

1. 材料全部生成并能按索引打开，当前账号/学号/月份/URL/PDF对应同一运行实例。
2. MCP实际走通管理员→教师→学生→管理员发布→学生报告的闭环，覆盖全部现有菜单，关键异常有证据。
3. 预期核对表、页面、账本、荣誉、故事、综合分及报告快照一致，发现的问题有修复复测或明确阻断。
4. 新增或必要修改的代码通过适当回归及前端构建，保留其他任务的修改，不把测试库操作误施于业务库。
5. 交付清晰的启动入口、演示起点重建方式、测试后结果、PDF手册与报告、真实测试总结与限制；不只交一个“方案已写好”。

## 9. 留给实施者的事项
