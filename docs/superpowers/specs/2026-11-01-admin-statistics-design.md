# 管理员学生数据统计设计

## 已确认方向

用户要求四个标签页，分别展示卡片与奖励、自我评价、荣誉上传、故事参与；用户已查看浏览器草图并回复“可以”。沿用当前 React 18 / Vite / Express / MySQL 架构和浅底墨绿界面。草图为 `.superpowers/brainstorm/94955-1793540217/content/admin-statistics-four-tabs.html`，其中数字仅为示例。

## 目标与范围

管理员通过独立“数据统计”菜单了解全校学生的参与、完成情况，并逐级筛选到年级、班级和学生。不改变发布中心和学生采集流程；不引入图表依赖，不新增数据库表，不修改真实学校数据。采用概览数字、可读的条形/环形图和分页学生明细，数字始终同时提供文字。响应式适配桌面和手机，四个标签页支持键盘切换。

## 共同规则

- 只允许管理员查询本人学校的数据；学期必须属于本人学校，只支持当前六育 V2 学期，旧版学期给出明确提示。
- 学籍以学期快照为准，排除转出、不适用和 `roster.included=false` 的学生；零记录学生仍出现在明细中。
- 使用全局学期选择器；页面提供年级、班级筛选，跨标签页保留。改变年级清空班级，改变统计范围清空详情分页。
- 学科筛选作用于卡片页的概览、图表和明细；姓名/学号搜索、完成状态筛选仅作用于学生明细，并明确标注。
- 分页默认 20 人，可选 20/50 人；没有数据时显示 0 和空态，百分比无分母时显示“—”。加载/失败期间不展示上一范围数据，支持重试及取消过期请求。
- 管理员只接收统计与奖励记录元数据，不返回自述、故事正文、音频路径、证书文件路径或卡片凭证。查询使用同一个数据库快照，避免总量和明细不一致。

## 四个标签页与统计口径

### 卡片与奖励

概览显示获得奖励人数、成功领取二维码卡数量、有效无卡奖励次数、总奖励次数。学科条形图显示两种方式的数量，环形图显示方式占比。学科列表保留所有课程和零数据项。

只统计 `CARD/USED` 和 `DIRECT/CONFIRMED`；通过有效 `REVERSAL` 排除已撤销原记录，不用净分数替代人数。二维码卡使用原始学科代码或课程元数据；无卡直评在缺少学科代码时按评价目标映射，日常行为等非学科目标单列“日常行为”，无法确定的单列“未归属学科”，不得猜测教师任教科目。学生明细显示两种次数、合计，展开后显示学科、方式、评价项目、教师、时间，分页读取完整奖励记录。

### 自我评价

概览显示完成人数、完成率、尚未完成人数、已评价项目数。按年级对比完成率，选年级后按班级对比；星级图显示一/二/三星数量和占比。

使用当前 V2 学生自评页面可填写的固定 `SELF` 星级字段，且只包含学期配置的适用项；完成指这些项目全部有 1–3 星，部分有值为进行中，均无值为未开始，无适用项单独标记并排除完成率分母。V2 不计入当前页面无法填写的旧版特长数组或教师评分。星级分母为所有已经填写的适用自评项目数，未填写不折算为一星。

### 荣誉上传

概览显示上传人数、累计上传份数、已认定、待处理数量。按已认定荣誉级别对比，状态图和文字同时展示已认定、待处理、不予认定、已撤回和识别失败。每条证书申报计一份，重试/版本记录不重复计算；累计上传含撤回，状态单列，使总数可以核对。级别只来自已认定结果，缺失级别单列“未标级别”。

### 故事参与

概览显示任一方向参与去重人数，以及讲、听、写各自参与人数和作品/完成数量。条形图比较三种参与率，旁列显示各方向累计量和参与者人均量，明细显示每个学生三种计数。

讲故事统计 `TELL_RECORDING/CONFIRMED`；历史存在 `TELL_WORK` 时只数有当前有效提交版本的根作品一次。听故事统计 `LISTEN_COMPLETE/CONFIRMED`，不统计启动/心跳。写故事统计 `WRITE_WORK/SUBMITTED` 且有当前有效 `WRITE_SUBMISSION` 版本的根作品，一次作品多版本不重复；讲故事不以完成评分为前提。三类参与人数不能直接相加。

## 实现者决定

采用独立管理员只读统计服务和路由；汇总与分页在服务端完成，不依赖前端全量学生列表或第一页来源记录。复用既有目录分层，新增 `manager/statistics/`。图表使用 CSS，保留可读图例与原始数量；长列表滚动、学生表内部水平滚动。原有工作区有大量未提交改动，本轮在现有功能分支增量编辑，只记录本轮文件，不提交已有改动。

## 验收

使用独立测试库验证四类指标、撤销、零记录、学科推导、转出排除、学校/学期权限、故事当前版本、自评适用项和分页。浏览器验证四个标签页、范围联动、搜索/状态/学科过滤、奖励记录展开、错误重试、桌面与窄屏无整页溢出。执行前后端测试、构建和针对新增文件的 lint，保留截图证据。
