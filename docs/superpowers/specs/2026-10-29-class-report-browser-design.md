# 班级报告：全部负责班级、学生摘要与PDF式详情

日期：2026-10-29。用户确认列表与详情无需进一步调整，进入[实施计划评审](../plans/2026-10-29-role-ux-and-report-management.md)；正式系统尚未修改。

关联：[三角色总设计](2026-10-28-three-role-ux-and-cleanup-design.md)。用户确认“所有班级”指当前教师负责的全部班级；点击学生进入报告详情，格式参考学校《六育评价明细.pdf》，支持导出与打印。

## 1. 页面结构

“班级报告”成为所有拥有有效任教职责的教师可见入口。覆盖当前学期本人任教及班主任职责关联的班级，以学期+年级+班号去重，不仅显示当前页头选中的一个班；不展示无关班级或全校名册。

首屏为**班级列表 + 学生报告摘要**，点击学生后打开独立**报告详情页**，不将整份报告塞进窄弹窗。返回时恢复学期、选中班级、搜索、状态过滤、列表页码和滚动位置；浏览器前进/后退有效，刷新详情按授权重新加载该学生。

### 1.1 班级与学生列表

桌面：顶部学期与总览；左侧约240px显示所有负责班级，右侧显示所选范围学生摘要。手机：上方班级列表可折叠，下方学生卡片/可滚动表格；“全部负责班级”始终可一键恢复。班级数多时可按年级与名称搜索，不能只展示列表第一页而声称全部。

左侧包含“全部负责班级”及每个班级的名称、学生数、报告就绪数、缺项人数、已确认人数、已发布人数；本人是否为班主任以文字徽标区分。点击班级更新右侧；默认选中“全部负责班级”，不是任意第一个班。每位学生在当前学期只显示一条学籍记录，任教多个科目不重复计人。

右侧工具栏：搜索学生姓名/学号，按“全部 / 待补齐 / 待确认 / 已确认 / 已发布”过滤；显示当前范围、总人数和更新时间。默认每页25条，可25/50/100；统计与分页分开，不能只计本页。

| 学生摘要字段 | 说明 |
| --- | --- |
| 姓名、必要学号、班级 | 姓名与“查看报告”都可打开详情；重名以学号区分 |
| 六板块简要信息 | 六个小标签分别显示有效已填/适用项数，如“德美16/16”；点击后在报告中定位相应板块 |
| 学业/星级摘要 | 如“A等级N项”“三星N项”，仅统计已存在的原值；不计算新的六育总分或平均星级，不把缺失当0 |
| 缺项与待办 | 缺失数据数量、待评分/待认定数量、寄语是否齐全，避免看见数值就误认为已就绪 |
| 报告状态 | 待补齐、待班主任确认、已确认待学校发布、已发布；已发布且当前草稿有变化需另标“有新草稿” |
| 版本 / 更新 | 当前草稿revision与已发布版本分开，更新时间注明含义 |
| 操作 | 查看报告；报告详情内导出PDF/打印；只有班主任可编辑寄语/确认 |

六板块摘要从当前适用字段和既有特长项目计算；七项自述、学期寄语、材料待处理、零卡结算/无奖状确认等独立检查仍可使报告未就绪。109个是既有模板呈现位置数，不强制每个学生必填109项，不能用一个常量减去非空值充当缺项数。

无需在列表加载所有报告HTML和全文。摘要用批量结构化数据返回，点击学生才取详情；保持跨学科原值不变。

## 2. 报告详情页

顶部面包屑：“班级报告 / 四年级（2）班 / 林小满”，返回列表按钮；学生姓名、班级、学期、报告状态及版本固定可辨认。正文前显示缺项/待办摘要及“当前草稿 / 已发布版本”选择；有已发布版本时默认打开当前有效发布快照，无已发布时打开当前草稿。

内容分两种浏览范围：

1. **六育评价明细**：默认打开，对照学校PDF保留德美、智美、健美、艺美、劳美、故事美六表、表头合并、自评/他评、星级/字母等级/原始值、体测与特长。桌面采用PDF左右列布局，手机六板块纵向阅读，保留全部字段。
2. **自述与寄语 / 完整正反面报告**：班主任可切换，保留五方面自述、最大收获、目标、学期寄语、家长寄语、报到日期及完整报告正面。无需从零重画报告正文，复用现行renderer。

教师只读报告不能直接改学业等级、卡分、学生自评或材料结果。缺项提供正确来源与责任人提示；有本学科输入权限时可跳转相应录入入口，返回恢复所查学生；班主任可以就地编辑学期寄语、特长教师评价，调用原表单保存后重新加载草稿与布局检查。

确认区保留完整性、布局与指纹检查。只有班主任可“确认本报告”；确认使用最新revision/fingerprint/templateVersion，源数据变化使旧确认失效。已发布快照不可修改；修改的是当前草稿，不覆盖已发布记录。

## 3. 权限边界与现有代码改动

本次为满足“所有负责班级学生的PDF式明细查看”而作如下明确方案裁定：

| 能力 | 普通任课教师 | 本班班主任 | 管理员 |
| --- | --- | --- | --- |
| 本人负责班级、学生摘要 | 可 | 可 | 原发布统计范围，不进入教师正文入口 |
| 负责班级学生六育明细完整只读与导出/打印 | 可 | 可 | 不可 |
| 学生自述/家长寄语等报告正面 | 不可 | 可 | 不可 |
| 编辑学期寄语、报告确认 | 不可 | 可 | 不可 |
| 修改学科录入、认定、冲正 | 沿用原学科/动作权限 | 沿用原权限 | 沿用原权限，不因报告入口扩张 |

用户确认的是负责班级范围；以上“普通教师看明细、班主任看完整正面”的细分为方案建议，兼顾本次PDF式查看与既有正文限制，未扩大至全校。

当前`authorizationService.assertScope`将`report/confirm`一并限制为班主任，`buildReportDraft`也仅供班主任；实施时需区分**明细只读**与**完整报告/确认**。新增明确`report-detail-read`动作校验任教班级，仍将`report-front-read/confirm/form.teacher_comment`限制班主任。避免直接删除现有head判断导致普通教师取得所有编辑权限。

普通教师响应只包含获准六育明细值与摘要，服务端不返回学生五自述、家长寄语、学期寄语正文或故事上传原文；不能把完整模型发到前端后用CSS隐藏正面。明细中的已评价实践描述属于报告明细，按本次负责班级明细查看范围返回。报告渲染器支持`DETAIL_ONLY`输出，仅生成获准明细页；普通教师的下载、打印、按版本查看同样使用此裁剪结果。

已发布快照也需先验证当前有效任教，再按允许范围生成只读内容；历史转班/任教撤销后不沿用浏览器旧范围获取新数据。管理员仍仅能看原有完成统计，不借新接口取得正文。

## 4. 导出与打印

详情工具栏提供“导出PDF / 打印”。复用HTML打印：点击导出时提示在浏览器打印面板选择“另存为PDF”，两按钮均打开同一份已选版本的可打印内容，不假称存在服务器PDF文件下载，也不新增Word/Excel报告导出。

- “六育评价明细”默认输出A4横向1页，与前述PDF明细相对应。
- 班主任选择“完整报告”时输出A4横向正反两页，保留现有正面内容；工具栏明确当前导出范围和页数。
- 未完成/未确认/未发布版本在打印内容内显示“草稿/未发布”及缺项提示，不能只在浏览器外壳上标注而打印后消失。允许教师打印核对稿，但不视为学校已发布。
- 已发布版本显示发布版本/时间，使用冻结快照；打印期间不混入实时新分数。页面姓名、预览iframe、导出版本必须一致。
- 打印隐藏导航、列表、按钮和页面控件，保留报告学生身份、学期、六表数据；手机与桌面使用同一打印模板，正文不裁切。
- 普通浏览器不能保证打印机实际出纸，界面只确认“已打开打印面板”，不能冒称已打印成功。

教师可以在学生详情导出/打印；本次不以引入服务端PDF引擎或批量生成所有学生PDF为前置条件。报告页面加载失败、版本改变、布局溢出时显示明确状态，打印按钮不操作另一个学生的残留iframe。

版面溢出时首版沿用现有布局确认规则：**禁用导出、打印及确认，列出溢出板块并保留屏幕全文阅读**，不得截断内容或缩到无法阅读，也不能偷偷增加页数而仍标注1页/2页。有权人员完成内容核对或由开发者修复模板版式后重新检查；不得要求教师编造/删除真实记录以绕过检查。特别是合法长文本与多特长项目，实施计划需纳入边界样本并修复版式；如学校未来允许续页，再另确认附页规则。

## 5. 数据与接口

仍使用users、academic_year、teacher_teaching_assignment、student_term_evaluation、evaluation_source_record、term_report六张表，无新增报告摘要表或班级表。

| 能力 | 建议接口 / 数据 |
| --- | --- |
| 所有负责班级 | `GET /api/v1/report-core/report-classes?termId`：有效任教按年级班号去重，返回isHeadTeacher和全量班级摘要；列表不受页头学科单选限制 |
| 学生报告摘要 | `GET /api/v1/report-core/report-students?termId&grade&classNo&keyword&status&cursor&limit`：范围未指定班级即本人全部负责班级；返回rows、total、counts、nextCursor |
| 学生详情 | `GET /api/v1/report-core/reports/detail/:studentId?termId&version=current-or-published&scope=detail-or-full`：服务端派生真实权限，返回受限model、html、revision、发布版本、可用动作与缺项摘要；参数不能放宽访问 |
| 保存与确认 | 继续使用原forms PATCH、draft及confirm协议，班主任限定不变；只读查询不顺带产生确认 |

摘要六板块可返回`sectionProgress:{conduct:{filled,applicable,missing},...}`及现有原值的gradeCounts/starCounts；确认状态与发布状态分开返回。每个summary项带canReadDetail/canReadFront/canEditComment/canConfirm，不由前端根据名字猜权限；后端每次调用再校验。

教师已确认状态使用当前revision和确认指纹，已发布状态使用term_report对应当前有效releaseVersion；不得把`status=CONFIRMED`当成已发布。所有负责班级无学籍时显示0人空状态，非班主任不能被统计成“有权确认”。

当前`missingItems`有逐学生查询，实施摘要接口需批量读取待评分/待认定计数、来源结算标志与特长完整性，复用相同校验规则，避免一班40人发40次报告HTML请求。列表分页不影响班级和全范围汇总，索引优先复用现有学籍/任教键，按查询计划必要时补索引，不建统计中间表。

详情路由包含学生ID与学期，服务端校验无关学生返回403/404；前端取消过时请求或比对请求ID后再更新，快速点A再点B时不能显示A的报告配B的页头。返回列表不丢筛选。改学期、权限撤销、登录过期均清理旧报告DOM，避免原文残留给新账号。

## 6. 验收

1. 一位教师任教多个班，列表展示全部相关班级；多学科同班不重复，非负责班级不可查询或猜ID打开。
2. 默认“全部负责班级”显示各班学生摘要，按班、姓名、状态筛选和分页均准确，统计不是当前页长度。
3. 学生六板块摘要可追溯至原值/完整度，不生成未经学校确认的六育总分；无奖状、不适用指标不假报缺项。
4. 点击任一学生打开独立详情、身份正确、PDF式六板块完整；返回恢复原列表位置，快速切人无串人。
5. 普通教师能看负责学生六育明细，但响应/HTML无家长寄语或学生自述原文；不能伪造scope=full、确认或编辑寄语。
6. 班主任仍可补寄语、布局检查、确认，数据变更使确认失效；全校统一发布仍由管理员执行。
7. 明细PDF为A4横向1页、完整报告为两页；原有109个呈现位置、合并表头、自评他评与原始健康值保留，导出无后台按钮或名单。
8. 草稿标识进入打印内容，已发布内容来自冻结版本；PDF中姓名/学期/版本与所选学生一致。
9. 390px和桌面均可完整查看六板块并找到导出/打印；键盘可进入学生详情与返回，焦点有明确位置。

配套静态原型只含虚构班级和学生，报告正文由现有renderer生成示例数据，用于验证排版与操作；不能当作正式权限和数据落地验收。

实施可行性复核已完成；审阅指出的“固定页数与溢出如何处理”已按第4节明确为阻止错误打印、保留全文与版式修复，不静默丢数据。
