# 人脸登录扩展设计

状态：用户已确认并继续实施；代码、正式表迁移及自动回归已完成，真人与攻击样本验收待完成。分支feature-six-education-v4-face；现有React、Express、MySQL、JWT架构不替换。

## 已确认的用户要求

保留密码登录；使用Google MediaPipe检测人脸和提取关键点；与注册模板比对后登录；处理摄像头权限、光照和无人脸异常；保护人脸数据。首次绑定由本人密码登录后再次验证密码完成，可自行解绑。

## 用户可见流程

登录页沿用现有云美配色和双栏，增加“账号密码 / 人脸登录”切换。人脸模式先填写账号，只在点击“开启摄像头”后请求权限；展示取景框和逐步提示，按服务器随机指令完成轻微左右转头/眨眼，再验证并进入原角色首页。关闭弹窗、切回密码、超时或离页立即停止摄像头。

三角色均从账号区域进入“人脸登录设置”对话框，不增加管理员业务模块或教师业务菜单。未绑定时显示用途、存储方式及自愿开启说明；勾选同意并验证当前密码，采集正面和轻微侧面帧，检查为同一人后绑定。已绑定显示时间，可密码验证后重新录入或解绑；不展示照片、向量或相似度。解绑删除活动模板并使未完成挑战失效；数据库历史备份仍遵循原备份生命周期，不宣称已删除历史备份中的数据。

明确提示：权限拒绝、无设备/占用、摄像头不安全来源、模型加载失败、光线不足、图像模糊、脸太小/偏离、无人脸、多人脸、动作未完成、挑战过期、网络中断。可重试并始终提供密码登录。未开通、账号不存在、禁用、身份不匹配统一登录失败，不泄露账号的人脸开通状态。模型或密钥不可用时关闭人脸入口，密码入口照常可用。

## 检测与身份比对的技术职责（实现方选择）

MediaPipe Face Landmarker是Face Mesh的新任务API，通过@mediapipe/tasks-vision在浏览器处理摄像头和关键点/表情；它不提供身份特征。不得用关键点几何距离当作账号身份凭据。

身份模型选本机OpenCV SFace；Node调度一个本机Python工作进程，在内存处理请求，使用YuNet检测/五点对齐、SFace提取并比较特征，并以Python MediaPipe在提交帧序列上复核动作。模型、WASM、许可证文件固定版本、校验哈希并由本站提供，不运行时引用浮动CDN。依赖包含Python、MediaPipe、NumPy、OpenCV；依赖兼容矩阵和具体版本在实施时实测锁定，不引入云识别服务，不向Google或其他第三方传脸。

Express是唯一认证裁决者，不接受浏览器提交的“已匹配”、匹配分数、特征向量或“动作通过”来发token。提交的是限量低分辨率帧，后端重新检测、提取及比对，要求全序列只有一个稳定的人脸。验证通过后继续调用现有signToken；status、school_id、role、token_version在最终事务内重新读取，不由客户端指定。沿用现有8小时JWT，不改变权限校验和密码登录接口。

选择输入账号后1:1验证，不建设全校人脸搜索，不识别未绑定人员。模板取多帧一致特征；阈值由服务器配置并绑定模型版本，客户端不可降低阈值。官方示例阈值只用于研究参照，不能作为本校儿童场景的精度承诺；默认采用保守值，实施报告列出实际使用值和待人工校准范围。

## 挑战与边界

服务器签发60秒一次性随机动作挑战，绑定学校、用户、用途（登录/绑定）、模板版本、随机nonce。后端根据帧序列重新核对动作；客户端关键点仅用于即时引导。数据库行锁及nonce消耗保证并发登录同一挑战只有一次成功，成功与失败的验证尝试均消耗挑战。绑定挑战只在现有登录态+正确当前密码+同意后签发。

采用每账号一个活跃挑战，新的挑战替换旧挑战；页面主动开始采集时申请，失败重试重新申请。IP及账号分别限速，有限工作队列/输入大小/帧数/像素数、推理超时和进程重启，避免未认证请求耗尽CPU。单个Node进程初期复用一个有界Pythonworker，协议是stdin/stdout内部JSON，不公开额外HTTP端口；支持配置进程数，不能无限spawn。账号nonce存数据库，多个Express实例仍按同一数据库裁决。

本方案是普通RGB摄像头的轻量动作挑战，不宣称是认证级PAD或能抵抗高级深伪、虚拟摄像头注入。实现必须测试静态照片、重复帧、过期序列、直接伪造前端结果；不能通过的路径不得放行。不把浏览器声明的liveness当作安全证据；生产默认关闭人脸登录，由部署方在真人和攻击样本验证后显式启用。密码功能不依赖此开关。

## 数据与迁移

继续使用正式student_growth原8表，不加临时库或临时表。仅为users增加可空face_template_enc（MEDIUMTEXT）、face_enrolled_at（DATETIME(3)）、face_credential_version（INT默认0）、face_challenge_json（JSON可空）。challenge仅存nonce哈希、用途、动作、期限、模板/会话版本等非图像数据，不存密码。新字段默认未绑定，不为现有演示账号伪造模板或批量录入人脸。

模板使用AES-256-GCM加密，独立环境密钥，随机IV、认证标签、keyId、模型版本、用户/学校AAD绑定；不可复用JWT_SECRET，不将密钥写入数据库、代码或前端。只在后端内存解密，任何普通/me、账号导入预览/查询/Excel导出都不得输出密文、向量、nonce或原图。密钥丢失或模型不兼容时要求密码重新绑定，不降级校验。密钥轮换支持旧keyId解密后重加密，未配置旧keyId则回到密码路径。

浏览器至服务端必须HTTPS；开发仅允许loopback的HTTP，不把任意X-Forwarded-Proto当作可信。Nginx明确TLS及受信代理设置。原图与采集帧不落盘、不进入日志、错误体或数据库；处理后释放引用。模板仍是敏感生物数据，不使用普通哈希代替可近似比较特征的加密。日志只保留事件、用户ID、结果和时间，不输出向量/分数/人脸/密码。

迁移check默认只读；apply校验正式库、先完整备份、幂等加列；不会删除原数据。结构核验支持旧库密码登录运行，face能力缺字段时不可用；显式apply后可启用。更新schema检查说明及空库演示兼容测试，确保新增可空列不会改变导入、还原与八表hash校验逻辑。新师生导入不会带人脸模板。

## API与模块

- 公共GET /api/v1/auth/face/capabilities：仅返回系统级可用性及公开协议配置。
- 公共POST /api/v1/auth/face/challenge、POST /api/v1/auth/face/login：账号+挑战+采集序列；复用认证响应和JWT。
- 登录后GET /api/v1/me/face：仅本人绑定状态、时间和是否可用。
- 登录后POST /api/v1/me/face/challenge：密码及同意，签发绑定/重绑采集挑战。
- 登录后PUT /api/v1/me/face：消费绑定挑战并加密保存模板；DELETE同路径：当前密码验证后删除模板并推进模板版本。

前端独立FaceCapture组件负责MediaPipe和设备生命周期；登录及设置组件共享。后端独立faceAuth服务、密码重新验证、模板加解密、worker适配器和限流器；路由遵循原错误格式。限流必须覆盖两个现有API别名前缀，绕过旧密码登录限流不能绕过人脸接口限流。角色和登录成功后的页面初始化共用同一方法，避免密码/刷脸两套状态。

## 验收与实际限制

单元/集成测试：加密随机性、AAD篡改、错误密钥、不可导出；密码错误不绑定、越权拒绝、禁用/跨校拒绝；nonce过期/重放/并发一次性消费、解绑/重绑后旧挑战失效；只篡改前端匹配结果不能登录；限流/大文件/超时/模型缺失安全失败；密码登录与原角色权限回归。正式表数据用事务回滚，迁移单独备份，不建临时数据库。

摄像头UI测试覆盖所有异常、重试、切模式停止轨道和不自动请求权限。模型测试分别报告真实推理与测试替身，不能用伪造embedding测试声称真人识别通过。只使用许可明确/本人同意的测试素材，不从现有学生资料推断人脸，也不默认打开用户物理摄像头。真人绑定、同人不同光照、异人拒绝及照片/视频攻击需本人配合；未完成的真人安全验收明确列为未通过，不宣布生产安全。

原空库23步演示及八表还原、管理员3模块、教师菜单顺序、学生发布报告读取均保留并进行适当回归；不把人脸自动绑定到虚构测试账号。
