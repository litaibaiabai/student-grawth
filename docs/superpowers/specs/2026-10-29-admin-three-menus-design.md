# 管理员三项数据菜单：学籍与账号、体测原始值、月度卡额度

日期：2026-10-29。状态：本轮新增设计，待页面评审；正式系统未修改。

用户要求三项各自作为独立菜单，不再收在“数据与额度”一个任务面板。管理员主导航据此为：**发布中心 / 学籍与账号 / 体测原始值 / 月度卡额度 / 学期配置**。发布中心、全校发布权限和低频学期配置保留。

关联：[三角色总设计](2026-10-28-three-role-ux-and-cleanup-design.md)、[卡台账](2026-10-28-teacher-card-ledger-design.md)、[实施计划](../plans/2026-10-29-role-ux-and-report-management.md)。

## 1. 共用布局与交互

三个菜单各有稳定页面地址、独立标题/筛选/业务表/导入或下发记录，不用弹窗装整项业务。桌面延续深绿/米白工作区，左导航固定，主区依次为：学期与标题 → 摘要 → 查询区 → 主表或导入工作区 → 最近记录。手机各区纵向呈现，数据表局部横滚，主按钮至少44px。

主按钮只推动当前明确动作，如“预览导入”“确认导入”“预览下发”“确认批量下发”；保留取消/重新选择，不增加无意义的二次确认。真正写入前必须先预览，预览本身不创建账号、不改体测、不改教师额度。

数据加载不显示假0；失败保留文件解析结果/编辑值；空状态解释下一步。页面离开前保护未提交数据。每个批次显示操作者、时间、范围、总行数、变更数、状态和批次号，允许按批次追溯，但不把密码和私有原文显示到历史记录。

## 2. 学籍与账号

### 2.1 版面

顶部“学籍与账号”，学期选择与“下载模板 / 批量导入”。摘要为当前学期学生数、教师账号数、班级数、待处理导入错误（没有未完成批次时不制造待办）。

主区用“学生学籍 / 教师账号”两个页签，下方固定导入记录区，可按批次查询详情；账号列表按角色分开，免让教师误以为其账号所属一个固定班。学生查询按年级/班级/姓名/学号/账号状态；教师按姓名/账号/状态查。表格支持25/50/100分页，不能只取前100人。

| 学生列表 | 教师列表 |
| --- | --- |
| 学号/登录账号、姓名、当前学期年级班级、账号状态、最近导入、变更记录 | 教师账号、姓名、账号状态、任教班级/学科摘要、最近导入 |

现有/导入账号不得显示明文密码或hash；任教分配仍在“学期配置”，账号导入不自动获得班主任或全科权限。此菜单不默认新增管理员账号、角色互换、密码重置、删除账户或批量停用。

### 2.2 模板

正式版用现有xlsx库生成两个XLSX模板，含表头说明、文本格式学号/账号和空白数据行。可接受同结构UTF-8 CSV；自动识别表头后显示映射，不模糊猜测不认识的列。

| 模板 | 必需列 | 可选/条件列 |
| --- | --- | --- |
| 学生学籍 | 学号/账号、姓名、年级、班级 | 初始密码：仅新账号必填，沿用至少10字符约束 |
| 教师账号 | 教师账号、姓名 | 初始密码：仅新账号必填；不要求年级/班级，不在这里维护任教 |

角色由模板类型确定，不由Excel自由填写任意role。账号按字符串处理，前导零不能丢；空行忽略，同批重复账号/缺关键字段/不合法班级逐行报错。已有账号角色不一致时拒绝该行，不能把教师悄悄变为学生或为教师创建学生学籍。

### 2.3 导入流程

1. 在学生/教师页选择模板类型，下载模板填表，上传本地文件。
2. 本地解析并显示识别列、数据行数；超过现有1000行上限要求拆批，不能截断。
3. 点击“预览导入”，服务端校验账号、角色、学校及当前修订，返回所有可定位错误及新旧差异。预览表为：行号、账号、姓名、班级、处理方式（新增/更新/不变/错误）、变更前→后、错误位置。密码仅显示“已提供/新账号需提供”，不回显明文/hash。
4. 有错误时禁止确认；允许下载错误清单、修改文件重新预览，或在预览格修正后重新校验。正确输入不清空。
5. 无错误时显示新增N、更新N、跳过N及影响班级。更新姓名/班级须明确差异；已采集数据/已确认报告受影响时单列提示。点击一次“确认导入”，整批原子提交，返回真实结果。
6. 结果显示批次与数量，刷新对应列表；重复请求返回原结果。预览后账号/学籍已变化则409，保留本次输入并重新预览，不覆盖别人更新。

已有账号密码保持不变，即使文件带初始密码也不以导入重置；新账号只在服务端bcrypt后保存。教师导入grade/classNo允许null，不创建student_term_evaluation。学生更新当前学期快照后须推进修订并使旧确认失效；历史已发布快照不改，原卡发行班级/历史领取记录不改写。转班后当前任教权限重新计算，不借名单导入转移原始卡凭证。

## 3. 体测原始值

### 3.1 版面

顶部“体测原始值”，学期、“下载模板 / 导入体测数据”；摘要为适用学生、五项齐全学生、待补学生、最近导入时间。筛选年级/班级/姓名或学号/完整度。主表固定学生身份列，五原值各一列，右侧更新时间和来源批次；下方最近导入记录。

| 列 | 类型/呈现 |
| --- | --- |
| 身高 | 数值，cm |
| 体重 | 数值，kg |
| 左视力 | 原始文本值，保留学校约定写法，不转星级 |
| 右视力 | 原始文本值，同上 |
| 1分钟跳绳 | 非负整数，次 |

体测水平、体测过程表现、体育学业等级不在此导入，继续原来源。这里明确授权管理员查看/比较本校五项健康原值，这是健康录入职责；发布中心、卡台账和报告查询仍不向管理员返回其他健康、六育正文或学生故事。

### 3.2 模板与流程

模板列为学号、姓名、年级、班级及五原值，学号为匹配主键，姓名/班级供核对，不能仅按重名匹配。保留既有值域校验，不额外引入医学判断/自动推断等级。

1. 选学期/班级、下载模板；上传数据，识别列与匹配人数。
2. 点击“预览差异”，服务端返回每格旧值→新值、匹配身份、无变化/新增值/覆盖/错误计数。
3. 预览中变化格淡黄、错误格红边且有文字原因，未变格弱化。可筛“只看变化/只看错误”。空白默认“不覆盖”，不是0或null；整行无变化可跳过，并列入跳过数量。清空旧值必须单独勾选要清空的具体格，预览明确显示“清空”，调用已有clearFields语义，不能把普通空白当清空。
4. 学号不存在、身份核对不一致、非法数值、重复学生均逐行显示；存在阻断错误时不提交任何一行。
5. 无错误时显示将更新学生N、实际变化格N、明确清空格N，点击“确认导入”。记录每个学生expectedRevision；冲突整批拒绝，保留输入重取差异。
6. 成功后刷新五原值与缺项统计，导入记录可查看谁在何时改了哪些格；不伪造体测等级、不改其他学业分。

## 4. 月度卡额度

### 4.1 版面

顶部“月度卡额度”，学期/月选择、教师姓名/学科/下发状态过滤；摘要：启用教师数、已下发人数、月总额度、已制卡总量。初始展示该范围所有启用教师，包括尚无QUOTA记录者，不能只显示已任教或已领额度的人。

主表为可多选、可编辑的教师额度表：

| 列 | 说明 |
| --- | --- |
| 选择 | 勾选教师，支持“全选当前页 / 清空”，跨页选择数量明确，最多200名/批 |
| 教师/账号 | 同名用账号区分；不要求输入数据库ID |
| 任教摘要 | 学科与班级，无任教显示提示并可去配置，不自动授予权限 |
| 当前月额度 | Q；无记录显示“尚未下发”与数值0，区别于已下发0 |
| 已分配 / 已制卡 | P与G，用于解释下调下限 |
| 下发后月总额度 | 本次可编辑的绝对总额，不是“再加多少张” |
| 本次调整 | 自动显示新总额−旧总额，如+20、−10或不变 |
| 校验/下发状态 | 合法、低于分配下限、未选、已提交等 |

表上提供“将所选教师统一设为N张”和按模板导入教师额度（教师账号、下发后月总额度）；表中仍能逐人改。统一设置仅作用已选教师，未选教师不被清零。切换月份先保护未提交值，不能把上一月额度自动重复下发。

### 4.2 真正批量下发流程

1. 选月份，在教师表多选；输入统一总额后“应用到已选教师”，或逐行编辑/导入模板。
2. 即时显示选择人数、旧总额、新总额、净调整；值必须是0–10000整数。总额不得低于该教师`max(P,G)`，作废/过期不释放G。新总额等于旧总额列为无变化，不制造重复下发。
3. 点击“预览下发”，服务端逐教师返回旧→新、已有配额修订与校验错误。任一错误时确认禁用，列出全部错误教师，用户直接改该行重新预览。
4. 点击“确认批量下发”，**整个已校验批次一个事务**；所有教师一起成功，任一教师额度/计划已改变则整批409并保持未提交，不出现部分成功。
5. 成功结果显示新增获配/调整/无变化人数、总张数和批次号；每个教师当前QUOTA更新，追加各自额度变化AUDIT与一条批次审计，教师端随后可看到获配。
6. 批次详情显示教师清单、前后总额、操作者、时间及结果，支持按月/教师追查；幂等重试不重复加额度，不用多个单教师HTTP请求伪装原子批量。

保留当前每教师每月一个QUOTA、生成后计划锁定的规则。管理员可追加额度但不能因此让旧已生成计划自动再制卡；页面解释“额度增加，原计划仍锁定”。无任教教师可提前获配但提示先配置任教后才能分班制卡。管理员不直接设教师卡的学生、班级和细分方向，不代教师发卡/冲正。

## 5. 数据与最小接口

不新增业务表。账号/学籍分别落users、student_term_evaluation；两个导入继续IMPORT BATCH/ITEM；额度继续CARD/QUOTA，批次预览与批量结果放**现有AUDIT（source_type=NULL）**，不能用CHECK未允许的CARD/BATCH新类型。

| 能力 | 最小变更 |
| --- | --- |
| 账号列表/模板 | 新`GET /api/v1/admin/report-core/accounts?termId&role&grade&classNo&q&status&cursor&limit`；模板由前端既有xlsx生成，固定列映射 |
| 学籍/体测预览 | 复用`POST /report-core/imports/preview`与commit；聚合全部校验错误，成功diff含安全的旧/新字段、处理类型与计数；错误返回422/details且无可提交batchId |
| 体测列表 | 新`GET /api/v1/admin/report-core/health?termId&grade&classNo&q&completeness&cursor&limit`，仅五原值/身份/修订/批次 |
| 导入历史 | 新`GET /api/v1/admin/report-core/imports?termId&kind&cursor&limit`与批次详情，屏蔽密码/哈希，仅授权ROSTER/HEALTH差异 |
| 月度教师额度列表 | 新`GET /api/v1/admin/report-core/teacher-quotas?termId&monthKey&q&status&cursor&limit`，启用教师LEFT JOIN当月QUOTA与计划/生成汇总 |
| 批量额度预览 | 新`POST /api/v1/report-core/card-quota-batches/preview`：termId、monthKey、entries[{teacherId,total}]、requestKey；≤200人，去重验证，AUDIT/PREVIEW存原修订及新值，返回batchId/revision/diffs/errors |
| 批量额度确认 | 新`POST /api/v1/report-core/card-quota-batches/:id/commit`：expectedRevision、requestKey；验证所属管理员/学校及预览未过时，同事务更新所有QUOTA及AUDIT |

实现额度批量时提取`saveQuotaInTransaction(connection,...)`供单笔/批量共用；外层只调用一次withMutation，禁止循环调用会各自提交的saveQuota。按稳定teacherId顺序锁定，重新验证教师启用状态、Q/P/G及expectedRevision；新配额不存在也需在当前学期锁和唯一键下防并发插入。

ROSTER预览修复教师必填班级与已有账号角色不一致的现有缺口；提交复验账号角色/当前值/唯一键，防止预览后新建同名账号被错误更新。新密码仅内存校验后服务端hash，不能返回preview、写明文BATCH/AUDIT/错误清单/日志；旧账号绝不通过此入口重置密码。

发布准备/激活期间沿既有term锁拒绝冲突写入；成功更改学生学籍/健康时沿原投影与修订机制使相关确认失效，不能绕过闭环。读取接口均仅manager本校，不能通过teacherId/studentId跨校。

## 6. 验收

1. 管理员侧栏三个独立入口，没有“数据与额度”聚合菜单；刷新/返回定位正确，发布中心与学期配置保留。
2. 学生/教师模板分别正确，教师不需假填班级；同名不同账号可区分，前导零不丢；已有密码不变，角色不互换。
3. 导入逐行定位错误、全部错误一次返回；预览不写业务数据，有错误不提交，无错误整批幂等提交。
4. 五原值逐格旧→新可核对，空白不覆盖、明确清空才null，合法0值不被当空；不出现体测终测分/等级导入。
5. 预览后修订变化整批409且输入保留；导入/额度结果是真实持久化反馈，非仅toast。
6. 多选教师真实一次事务下发，任一越额/冲突则全部不变；未选教师不变；重试不重复加Q，0额度与未下发区分。
7. 教师额度下限受max(P,G)约束，已生成计划不会因追加Q自动解锁；下发历史能追溯操作者及前后值。
8. 账号、体测、额度接口对学生/教师和跨校请求拒绝；密码/hash不进入任何响应、导出、历史及日志。
9. 390px可查询、预览并定位错误，桌面表格易读；标题/单位/禁用原因/保存状态可被键盘和读屏识别。

配套预览只展示内置虚构样例与本页内存结果，不解析或上传用户文件，不创建真实账号或下发真实额度；完整模板与事务校验在实施计划落地。

独立实施可行性审阅结论为“nothing important left”，已覆盖教师账号无班级、角色/密码保护、健康空白不覆盖、六表类型约束、批量原子性及幂等。浏览器原型已核对三个独立入口、阻断错误、示例差异与批量确认结果；这不是正式后端的集成验收。
