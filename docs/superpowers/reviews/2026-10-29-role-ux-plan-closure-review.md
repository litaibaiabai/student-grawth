## 第1轮：需求骨架与边界核对

### 1.1 本轮应完成什么

核心链路为：学期学籍与教师职责 → 六类数据采集 → 来源校验与认定/评分 → 学生学期宽表投影 → 完整性与布局核验 → 班主任确认 → 全校准备/一次激活 → 学生阅读冻结报告 → 导出打印。

六类来源均有入口：卡/无卡直评、外部导入、奖状、自评、教师评价、月度故事。六育板块属于报告输出分类，不是六套独立录入数据库。

核心数据仍为六表：users、academic_year、teacher_teaching_assignment、student_term_evaluation、evaluation_source_record、term_report。97个固定评价字段、两个特长集合和109个呈现位置沿现有字典；不能因早期“74项”统计而删除有效字段，也不能拿109当每名学生的必填分母。

### 1.2 不应被误计为本轮完成

原计划已明确排除或另列门槛的内容：真实钉钉统一登录、AI寄语、原微信故事系统入口合并、新建学期/切换全校当前学期UI、商城/排行榜/公共终端、Word/Excel报告导出、服务器PDF引擎。保留账号登录、教师手写寄语、已有学期配置、HTML打印。

这些不是本轮新发现的代码遗漏；交付必须继续说明边界。真实LLM调用可用性、学校正式校样审批和生产切换也不能由本地可控夹具或原型代替。

### 1.3 闭环不变式

1. 相同逻辑命令重试一次效果，同键异内容拒绝；上传也适用。
2. 未领卡不加分，冲正只扣一次；任何统计可追溯到原始来源。
3. 来源改变只重算相应投影，并推进宽表修订、失效确认；发布快照不变。
4. 月故事只有一个当前生效提交批次，草稿不覆盖有效成绩；旧版本迟到结果不回写。
5. 发布的名单、缺项计算、班级摘要和管理员总数使用同一学期范围。
6. 管理员仅执行其输入和元数据职责；任课、班主任、学生权限分别由后端决定。
7. “未完成/无奖/未结算/已结算0分/不适用”是不同情况，不能都当空或0。
